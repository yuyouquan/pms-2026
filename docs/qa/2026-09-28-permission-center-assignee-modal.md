# 权限中心：人员配置 tab 与选择弹窗

## 本轮范围

- 角色视图按“人员配置 → 功能权限 → 数据权限”展示，默认进入人员配置。人员视图仍为只读有效权限。
- 授权人员点击“配置”打开待选/已选双栏弹窗，可按姓名或部门搜索、多选、移除、清空。
- 授权部门点击“配置”打开多选部门树，搜索不丢失其他已选项。当前 Mock 只有四个平级部门，放在可展开的“全部部门”下；没有虚构部门层级。授权不自动关联上下级部门。
- 弹窗取消、关闭、Escape 均丢弃草稿；确定一次性更新当前字段，保留另一个字段的最新值。存储失败留在弹窗，保留草稿供再次确定。主界面仅展示静态标签。
- 系统超级管理员仍至少保留一位人员，不能通过部门授权。弹窗草稿接入原有导航保护。
- Mock 用户目录和种子新增 SnoopyYu 超管。权限缓存 envelope 4 升至 5 时只补充这一成员，不重置项目权限、自定义角色或菜单策略；升级后的主动撤销不会在刷新后重新添加。缺失或无效的内置超管不会恢复授权。

### 浏览器实测（localhost:3017，生产构建预览）

1. 默认第一项为人员配置；授权人员/部门仅出现在该 tab。功能权限仍显示合并父菜单矩阵，数据权限仍有四个可配置菜单树；人员视图保留只读有效权限。
2. XPM 角色中按“示例测试组”搜索人员，只显示三位匹配用户。勾选后取消，主界面仍为空；重新打开不保留取消的草稿。
3. 多选人员、移除一个并确定，主界面只出现保留的人员标签，无编辑控件和关闭图标。
4. 部门选择测试组后搜索质量组并选中，已选列表保留两项；确定后主界面静态显示两部门。刷新页面再进入 XPM，两类配置均保留。
5. 部门搜索无匹配时显示空状态，已选项仍在；跨搜索新增后点关闭或 Escape 均丢弃新增草稿。节点标识改为 ASCII 后，每个部门勾选框有正确且独立的可访问名称。
6. 390×843 CSS 窄屏下双栏变上下布局，弹窗边界约 x=8..382、y=107..736，无文档横向溢出；人员搜索、多选、取消和部门 Escape 操作均可完成。验证后恢复默认视口。
7. SnoopyYu 在超级管理员人员名单和人员视图中显示，拥有全部数据/全部列。通过用户切换器实际切至 SnoopyYu，全部项目可见，可进入 DEMO017-DEMOCHIP001_DEMOBOARD016 并打开“编辑项目信息”弹窗（未提交项目变更）。
8. 超管名单清空后点确定，提示“必须保留至少一位超级管理员”，主界面名单不变；部门配置按钮禁用。
9. XPM 的临时测试人员和部门已清空恢复原状态；用户预览页已刷新。浏览器 error/warn 日志为空。

### 本轮发现并修复

- 中文部门 key 被 AntD 转成重复 DOM ID，多个 checkbox 名称指向首个部门：改为稳定 ASCII key，显示和持久化仍使用原部门名称。
- 原 Mock 清洁度检查只接受“演示用户NN”，并要求所有登录用户有 Mock 通知身份：根据本次明确要求，仅增加 SnoopyYu 的精确例外和 `example.com` 模拟身份。`verify-mock-data-hygiene.mjs` 修复后 11 项检查全部通过，任意真实姓名仍被拒绝。
