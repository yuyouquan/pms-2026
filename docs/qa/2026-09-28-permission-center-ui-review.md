## Important

### 1. P1 — 首次条件策略未完成时，人员/功能变更会直接授予全部数据

位置：`src/components/permission-center/PolicyEditor.tsx:29-32,56,61-62`；关联 `src/components/permission-center/DataPolicyEditor.tsx:26,34-40`、`src/lib/permissionCenter.ts:7`、`src/stores/permission.ts:578-588`。

复现路径：

1. 新建普通角色，保留尚未配置过的“项目视图”菜单。
2. 选择“符合筛选条件的数据”，留下空条件；页面提示“条件未完整，尚未生效”。
3. 选择一个人员，然后勾选“查看”（这两个操作的先后顺序不影响结果）。
4. 当前条件仍不完整，但 store 中产生 `users=[所选人员]`、`actions=['view']`、`data.mode='all'` 的有效策略。对于这个新角色，授权计算已允许该人员查看全部行。

原因：条件草稿只保存在 `DataPolicyEditor` 本地 state，验证失败后不调用 `onUpdate`。其余控件不知道草稿存在，使用 `createEmptyMenuPolicy` 的 `data.mode='all'` 逐项写入。`savedDataKey` 未变也会保留界面中的条件模式，导致界面仍显示条件未完成，而其他字段已经使全量授权生效。

这违反规格 4.5 的“首次新增策略仍无授权”和 4.6 的有效变更原子保存要求；用户明确开始配置限制条件时，不能通过另一项控件生成未限制的首次授权。已有有效策略的未完成条件编辑仍应继续沿用原策略。

建议：将未完成条件状态提升到完整策略提交边界，在首次授权尚无有效条件时缓冲或阻止会形成有效授权的人员/功能变更；条件完整后作为同一授权单元提交。不要仅改变提示或禁用条件编辑器。验证“先条件后人员/功能”的顺序，以及已有有效策略编辑未完成时保留原策略的行为。

### 2. P2 — 数值字段的“属于 / 不属于”控件永远无法保存

位置：`src/components/permission-center/DataPolicyEditor.tsx:53,60-67`；关联 `src/lib/permissionCenter.ts:9,25-27`、`src/constants/permissionCenter.ts:13`。

复现路径：

1. 为普通角色打开“项目视图”的条件编辑器。
2. 字段选择“进度”，运算符选择“属于”或“不属于”。
3. 在多值输入中输入 `10`、`20` 并按回车形成两个值。
4. 控件生成字符串数组，但校验的数值分支拒绝所有数组，所以完整输入仍显示“请输入有效数字”，策略永不生效。

原因：运算符目录对数值字段公开 `in/notIn`，UI 因此使用多选标签控件；领域校验却在数值字段分支无条件拒绝 `Array.isArray(value)`。这是可见控件与提交契约不一致。

建议：统一运算符目录、值控件和类型校验；保留这些运算符时逐项验证和比较数值数组。日期多值控件也应按同一契约校验每个元素。协调 agent 已将此项交给领域负责人处理，修复结果需在后续整体验证回读，不将其视为已修复。
