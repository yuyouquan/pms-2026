# PMS 转维融合验收

## 范围与环境

- 基于 `origin/dev` 的 `68a44cb9bd7df4a70923b4fc0e6058377178fca0`，独立分支 `codex/feature-transfer-maintenance-integration`。
- 源流程参考本地 `transfer-maintenance-flow`，保留 PMS 项目空间导航和样式。
- 本项目仍为前端 mock；AI 检查为显式模拟。终审通过后进入源流程的“信息变更”阶段；源项目未提供该阶段自动完成处理，本次不扩展后端。

## 实现

- 整机与 tOS 独立配置模板/团队。tOS 只含 CheckList。
- 导入/导出保留用户序号；序号与标准/评审要素连续同组合并。真实模板版本和对比，既有申请保存团队及模板快照。
- 申请 Modal、资料草稿、模拟 AI、按角色提交、委派、单条/批量审核备注、Block/遗留任务、关闭/失败重开。
- 维护 SPM 终审可新增遗留任务、修改状态；通过后材料及终审管理冻结。已有遗留任务仍由其责任人在详情标记已解决，与源项目保持一致。
- 项目、人员、阶段、权限切换重新校验；工作台支持实际录入/审核人、被委派人和角色提交责任人。

## 审查修复

- 保留已通过材料，部分驳回可补充后再次提交。
- 跨角色录入由配置责任角色提交；配置完整名称不会被旧后缀规则截断。
- 关闭范围限申请人且尚未进入审核；无材料角色不阻止早期关闭。
- 所有可选人员可通过 PMS 用户切换进入流程；mock 用户目录唯一。申请/委派只允许当前项目有转维查看权限的人员，并在提交时复核最新权限与父项目作用域，避免无法进入审核的人员阻断流程。
- 终审汇总显示配置责任人及真实意见。
- 全部材料已通过后仍可在终审前追加角色遗留任务。
- 角色名称与其他角色 Code 不允许歧义；版本对比保留重复分组行，数字/文本序号导出导入不产生伪差异。
- 失败重开按完整业务键逐条继承，不复用首条资料。

## 追加源交互审计

用户追加要求后，重新对照源项目的五个页面、共享 DelegateModal、PipelineProgress 和 ApplicationContext。补充以下差异：

- 单条委派回填已有人员；批量委派不回填，不能批量清空；录入禁止清空，审核可清空单条。委派替换保留原责任人，候选支持姓名、角色、部门检索。
- “委派给我的”独立默认展开，跨角色聚合两类材料；纯被委派人能处理材料，整角色提交由配置团队责任人负责。
- 已通过材料可在终审前管理审核委派，但不能借此重新编辑审核结果。
- 节点下动态角色圆点和驳回提示；文本列搜索、状态筛选、AI详情、驳回意见、Block默认折叠、角色通过时选择是否创建遗留任务。
- 详情/终审锚点、项目信息和双团队、申请指南、失败原因及重开入口、成员清空、500字计数、任务创建时间、时间升序历史、UNC目录链接、关闭上下文。
- 已有遗留任务的责任人可在详情二次确认后标记已解决，包括终审通过或申请终止以后；不赋予其他终态编辑权限。
- 模拟AI按源90%通过/10%失败，失败后可修改重试；刷新时恢复持久化中的待完成检查，避免丢失计时器卡住。

## 转维按钮样式检查

- 检查转维页面、团队/模板配置及筛选组件的52处显式按钮和Modal自动生成的操作按钮。根因是共享危险按钮规则强制设置边框，影响本应无边框的link/text类型；禁用规则也给文字操作增加了背景和边框。
