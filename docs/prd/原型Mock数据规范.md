# 原型 Mock 数据规范

本原型使用虚构数据集 `2026-09-08-v1`。人员、项目、品牌、组织、交付物和评审示例不对应真实业务；日期及版本号仅用于演示流程和校验边界。

## 数据命名

| 对象 | 示例及约束 |
| --- | --- |
| 可切换登录用户 | `演示用户01` 至 `演示用户09`；权限由原有角色配置决定 |
| 展示成员、外协成员 | `演示成员01`、`演示外协01`；不凭姓名自动授予系统权限 |
| 品牌、产品系列、组织 | `示例品牌A`、`示例系列A`、`示例项目组` |
| 整机、芯片、主板、芯片型号 | `DEMO017`、`DEMOCHIP001`、`DEMOBOARD016`、`DEMOSOC003` |
| 技术及能力建设项目 | `示例架构演进V3`、`DEMO-TECH-V2`、`DEMO-OPS` |
| 编译选项 | `demo_build_01` 等虚构选项 |
| 邮箱与业务链接 | 使用 `example.com` 及其子域；不填真实租户、内部域名、个人邮箱或共享盘地址 |
| 转维材料和评审规则 | 使用通用虚构材料、演示指标和说明；不复制内部标准、放行阈值、文档编号或真实评审记录 |

系统功能词汇（如 tOS、STR、角色名称、项目类型、版本状态）保持业务定义。虚构数据仍须覆盖正常、异常、草稿、已发布、锁定、停发、转维各阶段及不同成员权限。

## 关联约束

项目 ID 及其在市场计划、tOS/MR、子项目、路标、待办、权限和转维中的引用必须一致。人员目录与转维外部 ID 的映射必须同时更新；不同外部 ID 不因同名自动匹配。页面、筛选选项、历史样例快照、配置模板和测试样例须使用同一命名体系。

## 刷新与持久化

所有浏览器存储通过 `src/lib/mockDatasetStorage.ts` 访问。在首次读写和 Zustand 恢复数据前检查数据集版本，仅删除明确属于 PMS 的旧数据、草稿和视图配置。其他应用的存储不受影响。当前版本的演示修改继续保存；存储不可用时不读取未清理的旧数据。

包含内容快照的分享链接必须携带数据集版本；旧数据集的快照显示已过期。按项目 ID 读取当前已发布计划的链接继续读取当前虚构数据。

## 验证

- `npm run verify:mock-data`：检查虚构命名、地址、数据关联、权限目录和一次性缓存刷新。
- `npx tsc --noEmit`、`npm run build`：验证类型及生产构建。
- 浏览器检查项目列表、路标、联合项目空间、转维、权限切换、旧缓存刷新和二次加载后编辑保留。

以后替换整套演示数据时提升数据集版本；普通业务字段调整不应触发整套数据重置。
