## 一、产品概述

### 1.1 产品定位

PMS（Project Management System）是一套面向手机研发团队的项目管理平台，支持整机产品项目、产品项目（tOS版本）、技术项目和能力建设项目四种项目类型的全生命周期管理。

### 1.2 目标用户

| 角色 | 说明 |
| --- | --- |
| SPM（高级项目经理） | 负责整体项目计划制定与跟踪 |
| TPM（技术项目经理） | 负责技术方案推进与里程碑管理 |
| 产品经理 | 负责需求定义与市场计划 |
| 开发代表 / 软件SE | 负责开发任务执行与进度更新 |
| 测试工程师 | 负责测试计划与质量跟踪 |
| 管理层 | 负责项目组合视图与决策 |

### 1.3 V1.0 范围

> **V1.0 包含：** 工作台（项目列表+工作跟踪）、项目空间（基本信息+一级计划）、项目路标视图、一级计划配置、权限中心、一级计划分享

> x **V1.0 不包含：** 二级计划管理、计划总览、转维模块、二级计划配置、转维材料配置、人力资源管道

#### 3.1.4 待办中心 1️⃣

**功能描述：** 工作台右侧常驻的可折叠面板，集中展示当前登录用户在所有可见项目中、且属于「修订中」版本的计划相关待办。已发布版本不产生待办。

**数据来源与去重：**

- 仅扫描各项目「修订中」版本的任务（V4 修订版等），已发布版本任务不进入待办列表。
- 按 `项目 + 计划级别 + 计划类型 + 版本` 聚合：同一组的多条任务合并为一条代表项，显示「共 N 项待处理」。
- 仅展示 `responsible === 当前登录用户` 的待办；系统级「管理组」成员不会因为旁路 RBAC 而看到他人的待办，待办过滤始终基于责任人字段。

**信息层次（自上而下）：**

- 主标题：项目名称
- 副标题：计划级别（一级计划 / 二级计划）+ 计划类型（如 `1+N MR版本火车计划`）+ 版本号 + 市场标签（仅整机产品项目显示）
- 合并计数：当聚合后包含 ≥2 条任务时显示「共 N 项待处理」（仅 1 条时不显示该行）

**点击行为（精确跳转）：**

1. 跳转到该项目的 `项目空间 → 计划`
1. 自动切换到对应的版本（修订中版本对应的 versionId）
1. 切换到对应的计划级别（一级 / 二级）
1. 二级计划同时切到对应的 planTabKey
1. 整机产品项目按 todo.market 切到对应市场 Tab
1. 在表格中将责任人为当前用户的行高亮 2 秒并 scrollIntoView 至视野中心

#### 3.1.5 新增项目 1️⃣

**功能描述：** 工作台「项目列表」工具栏右侧的「+ 新增项目」按钮，用于将外部系统中的项目纳入 PMS 并指定 PMS 专属字段（项目类型、项目责任人）。点击按钮弹出 Modal，提交后新项目直接进入「基础信息」页。

**入口与可见性：**

- 入口位于工作台「项目列表」工具栏最右侧（卡片/列表视图切换器之后），与 1px 灰色分隔条一同显示。
- 仅当当前登录用户属于系统级**「管理组」**时按钮可见，其他用户看不到入口。

**表单字段：**

| 字段 | 控件 | 说明 |
| --- | --- | --- |
| 项目名 | 下拉单选 + 模糊搜索 | 候选项从外部系统获取（每条仅含项目名 + 业务 ID `bid`）。已存在于 PMS 的同名项目会自动从候选中排除，防止重复导入。 |
| 项目类型 | 下拉单选 | 四选一：整机产品项目 / 产品项目 / 技术项目 / 能力建设项目。外部系统不区分项目类型，故必须由当前用户在 PMS 内显式指定。 |
| 项目责任人 | 下拉多选 | 从系统全量人员中手动选择，至少 1 人。**不默认回填**外部项目配置的 SPM，需由管理员显式确认。 |

三个字段均必填；任一未填则点击「创建」时 Antd 表单会在对应字段下展示校验提示，提交不继续。

**提交后行为（一次性事务）：**

1. 通过外部 `bid` 拉取该项目补充信息（产品线 / 品牌 / Android 版本 / 芯片平台 / 计划起止时间等）。
1. 在 PMS 中创建新项目记录：状态默认「筹备中」、进度 0、健康度「正常」、责任人取首位选中人员、SPM 取外部系统数据。
1. 将项目责任人写入该项目的「项目成员可见性映射」——责任人立即能在工作台看到该项目卡片，无需刷新。
1. 在权限中心初始化该项目的角色权限快照：「**系统管理员**」角色成员设为本次选中的项目责任人；其他固定角色（产品经理 / 项目经理 / 开发代表 ...）继承系统默认配置。
1. 自动跳转至新项目的「项目空间 → 基础信息」页，弹出成功提示：「项目创建成功」。

**与权限中心的联动：**

- 创建项目时设置的「项目责任人」是该项目权限中心**项目级**「系统管理员」的初始成员，**仅作用于该项目**，不影响其他项目的角色配置（per-project 隔离）。
- 创建完成后，可在该项目的「权限配置 → 角色人员配置」中继续调整任何角色的人员名单，详见 3.6.2。
- 全局「管理组」成员对所有项目自动拥有完整权限，不依赖项目级「系统管理员」配置。

### 3.3 一级计划管理

**功能描述：** 在项目空间的"计划"模块中，管理项目一级计划。支持三种视图模式、版本管理、分享功能。

#### 3.3.1 版本管理 2️⃣

**版本状态：**

- **已发布**：只读版本，但实际开始/实际完成日期可点击编辑
- **修订版**：完全可编辑的草稿版本，自动进入编辑模式**版本操作：**

| 操作 | 触发条件 | 行为 |
| --- | --- | --- |
| 创建修订 | 无修订版存在时显示 | 基于最新已发布版本克隆任务数据，创建新版本号（V+1），自动切换到修订版 |
| 发布 | 修订版选中时显示 | 将修订版状态改为"已发布"，需先通过所有约束校验 |
| 版本对比 | 任意版本选中时均显示（含修订中） | 选择两个版本进行差异对比（新增/删除/修改/未变更） |
| 分享 | 已发布版本存在时显示 | 复制公开分享链接到剪贴板 |

> 🔒 **权限说明：** "创建修订""发布"操作受 `plan:一级计划-编辑` 权限控制，无权限时按钮 disabled 并 Tooltip 提示"无一级计划编辑权限"。系统级"管理组"成员旁路此校验。

#### 3.3.2 飞书通知机制 3️⃣

**功能描述：** 一级计划的任务变更和到期状态自动通过飞书通知对应的责任人，减少人工跟踪成本。包含两个触发场景。**场景 A — 发布修订版时的变更通知：**

- **触发时机**：用户点击"发布"按钮将修订版切换为"已发布"状态
- **检测逻辑**：对比本次发布的任务与上一已发布版本快照，识别新增任务（id 不存在于 baseline）和修改任务
- **修改判定字段**：仅以下关键字段的变化触发通知
	- 任务名称（taskName）
	- 计划开始（planStartDate）
	- 计划完成（planEndDate）
	- 责任人（responsible）
	- 前置任务（predecessor）
- **不触发通知的字段**：状态、进度、实际开始/完成/工期 —— 这些属于执行态，不属于计划变更
- **聚合规则**：同一责任人的多条变更合并为一条飞书消息，避免打扰
- **UI 反馈**：右上角弹出蓝色 `notification.info` 汇总提示，详细消息内容在浏览器控制台输出
- **消息示例**：

> bell 您好 张三，一级计划 V3 已发布，您负责的任务变更如下：【新增 1 条】• 2.3 STR4（2026-02-16 ~ 2026-03-01）【修改 1 条】• 1.1 概念启动- 任务名称: 概念启动 → 概念启动(已修改)- 计划完成: 2026-01-07 → 2026-01-10

- **扫描对象**：最新已发布版本的**叶子任务**（有 parentId 的里程碑/活动节点，阶段节点不参与）
- **筛选条件**：
	- 实际完成时间（actualEndDate）为空 —— 仅通知未完成的任务
	- 计划完成时间（planEndDate）已设置且可解析
- **通知规则**：
	- 距离计划完成 ≤ 2 天（今天/明天/后天）→ "即将到期"
	- 已过计划完成时间 → "已逾期"（按天数递增）
- **聚合规则**：同一责任人的多条合并为一条
- **UI 反馈**：右上角弹出黄色 `notification.warning` 汇总提示

#### 3.3.3 编辑模式详细操作 2️⃣

##### 进入/退出编辑模式

- **自动进入**：选择修订版时自动进入编辑模式，表格行背景变为浅黄色
- **已发布版本**：不进入全局编辑模式，但实际日期字段可单独点击编辑
- **退出**：发布后自动退出

##### 可编辑字段及操作方式

| 字段 | 编辑控件 | 说明 |
| --- | --- | --- |
| 任务名称 | Input 文本框 | 直接输入修改 |
| 责任人 | Input 文本框 | 直接输入人名 |
| 前置任务 | Input 文本框 | 输入前置任务编号（如 1.1） |
| 计划开始 | DatePicker 日期选择 | 弹出日历选择日期 |
| 计划完成 | DatePicker 日期选择 | 弹出日历选择日期 |
| 预估工期 | Input 数字输入 | 输入天数 |
| 实际开始 | DatePicker（仅已发布版本可编辑） | 点击单元格展开日期选择器 |
| 实际完成 | DatePicker（仅已发布版本可编辑） | 点击单元格展开日期选择器 |

> 🎁 **重要**：修订版中实际开始/实际完成日期为只读，仅已发布版本可点击编辑实际日期。

> ⚠️ **操作日志**：所有修改的操作需要记录，每一条用户操作后的实时保存以及计划的创建发布等

##### 任务增删操作

| 操作 | 入口 | 规则 |
| --- | --- | --- |
| 添加子任务 | 编辑模式下，任务序号左侧的 "+" 按钮 | 一级计划最多支持 2 层（阶段→里程碑），已达最大层级时 "+" 按钮不显示 |
| 删除任务 | 编辑模式下，行右侧的删除按钮 | 需二次确认（Popconfirm），删除时连同子任务一起删除 |
| 拖拽排序 | 编辑模式下，任务序号左侧的拖拽手柄 | 支持同级任务拖拽排序，带子任务整体移动 |

##### 时间约束校验

发布前系统会执行以下三项校验，任一不通过将阻止发布并弹出警告：

**约束 1：父子任务时间约束**

- 子任务的计划开始时间不能早于父任务的计划开始时间
- 子任务的计划完成时间不能晚于父任务的计划完成时间

**约束 2：任务开始和结束时间约束**

- 任务的计划开始时间不能晚于任务的计划完成时间

**约束校验**

- 在甘特图中拖拽修改时间时，即时检查前置任务约束
- 冲突时将错误行的任务使用红色高亮出来，让用户修改，用户点击发布时，如果有错误的任务，会提示“任务校验不通过，无法发布”并自动滚动到第一条不符合要求的任务。

> 📋 **校验时机总结：**
>
> - **发布时**：执行约束1（父子时间），全部通过才能发布，如果有错误的任务，会提示“任务校验不通过，无法发布”并自动滚动到第一条不符合要求的任务
> - **表格编辑时**：实时校验，将错误行的任务使用红色高亮出来

#### 3.3.10 任务时间合法性校验 2️⃣

**功能描述：** 在「修订中」版本下实时校验任务计划时间的合法性，违规字段单元格红色高亮（淡粉底 + 左侧 3px 红条 + Antd DatePicker 原生 status="error" 红边 + 红色日历图标），hover 显示红色 Tooltip 列出该字段的具体违规原因。

**校验规则：**

| 规则 | 具体约束 |
| --- | --- |
| 同一行内 | planStartDate ≤ planEndDate |
| 父子关系 | 子.planStartDate ≥ 父.planStartDate 且 子.planEndDate ≤ 父.planEndDate |

**触发与表现细节：**

- 仅在 `currentVersionData.status === '修订中'` 时启用校验扫描，已发布版本不做该校验。
- 任一边日期为空时跳过该规则（避免编辑过程中临时空值误报）。
- 多级层级（例如 1.1.1）通过 parentId 链传递性自动覆盖：子在父内 + 父在祖父内 → 子在祖父内，无需独立校验跨级。
- 同行 start > end 时 start 和 end 两个格子都标红（不一致需用户决定改哪个）。
- 父子区间违规时，仅标记越界的那一边（例如子.start < 父.start 只标 start，end 正常时不标 end）。
- 单元格 hover Tooltip 列出该字段所有违规原因，逐条以「· 」开头。例如：
	- 计划开始（2026-01-25）不能晚于计划完成（2026-01-15）
	- 计划开始（2026-01-01）不能早于父任务「概念」的计划开始（2026-01-25）

**发布拦截：**

- 点击「发布」按钮时，先扫描完整任务列表 `getInvalidTaskFields(tasks)`：
	- 若不存在违规字段 → 进入正常发布流程（diff 通知 / 状态切换 / 快照保存）。
	- 若存在违规字段 → `message.error("任务校验不通过，无法发布")`，setTimeout 后自动平滑滚动到第一条违规任务行（按数据数组顺序），且**不**改变版本状态。
- 滚动逻辑通过查询 `tr[data-row-key={firstInvalid.id}]` 调用 scrollIntoView。

**适用范围：** 该校验同时作用于 一级计划（项目空间） / 二级计划（项目空间） / 配置中心一级计划模板。三处共享同一份 `getInvalidTaskFields` 实现。

#### 3.3.11 默认版本与行级编辑权限 2️⃣

**功能描述：** 进入项目空间「计划」时，系统按当前用户的「计划编辑权限」与「是否为某条任务的责任人」自动选择默认显示的版本，并控制版本下拉里是否暴露修订中版本、以及行级编辑能力。

**默认版本与版本下拉矩阵：**

| 用户身份 | 是否有修订版 | 默认显示 | 版本下拉 |
| --- | --- | --- | --- |
| 有计划编辑权（一级或二级） | 有 | 修订版 | 全部版本可见，提供「发布」入口 |
| 有计划编辑权 | 无 | 最新已发布 | 全部版本可见，提供「创建修订」入口 |
| 无编辑权 + 是某条任务责任人 | 有 | 修订版 | 全部版本可见，无「创建修订」/「发布」按钮 |
| 无编辑权 + 是某条任务责任人 | 无 | 最新已发布 | 全部版本可见 |
| 无编辑权 + 非任何任务责任人 | 有 / 无 | 最新已发布 | **修订中版本被过滤掉**，无法切到修订版 |

![](pic/V8ZvwVI6xhSQPebI2aCc7Odenid.jpg)

**自动切换逻辑：**

- 触发时机：`activeModule === 'projectSpace' && projectSpaceModule === 'plan'` 且 `projectId × market × planLevel × currentLoginUser` 组合发生变化时。
- 用 ref 锁定到 `(项目 + 市场 + 级别 + 用户)` 的复合 key，避免用户手动切换版本后被覆盖；用户切换登录身份时复合 key 变化会重新评估。
- 责任人判定 `isResponsibleForAnyTask`：扫描当前 effectiveTasks（L1）+ level2PlanTasks（L2 全集）中是否存在 `responsible === currentLoginUser`。

**行级编辑能力分级（仅在编辑模式 + 修订中版本时生效）：**

| 能力档位 | 判定 | 可执行操作 |
| --- | --- | --- |
| canFullyEdit | 编辑模式 + 用户有相应级别（plan:一级计划-编辑 或 plan:二级计划-编辑）的编辑权 | 拖拽排序、添加子项、删除任务、新增一级活动；任意单元格可编辑（含责任人 / 前置任务等结构性字段） |
| isRowEditable | 编辑模式 + 用户为该行的 responsible | 仅本行的「任务名称 / 计划开始 / 计划完成 / 预估工期」可改；责任人 / 前置任务为只读；不能新增 / 删除 / 拖拽任务 |
| 只读 | 已发布版本 或 用户不满足以上两档 | 所有字段只读（已发布版本下"实际开始 / 实际完成"在最新已发布版本上仍可点击编辑） |

**编辑提示横条文案：**

- canFullyEdit：`编辑模式 - 拖拽手柄排序，点击单元格编辑，完成后点击保存`
- 仅 isRowEditable：`编辑模式 - 你只能编辑负责人为自己的行，其他任务为只读`

**为什么责任人字段不允许责任人本人改：** 若允许责任人将自己改成他人，会立即丢失该行编辑权，造成"改一半改不回来"的死锁体验。结构性字段（responsible / predecessor）保留给 canFullyEdit 用户。

**为什么父子时间校验对责任人也生效：** 一致性优先于可操作性。如果父任务范围被超出（自己看不到的格子），对应自己负责的子任务格子会标红，需协调有编辑权的同事修复，避免局部修改产生不可见的隐患。

#### 3.5.3 版本管理

配置中心计划模板的版本管理与项目空间共享同一套底层机制（`VersionData[]` 列表 + `currentVersion` 状态 + `publishedSnapshots` 快照映射），但适用对象是**计划模板**而非**项目实例**。

**版本状态：**

| 状态 | 说明 |
| --- | --- |
| 已发布 | 只读模板。新建项目时按当前项目类型选取「最新已发布」模板克隆任务结构（仅 id / order / parentId / taskName 等结构字段，不带日期 / 工期 / 实际值） |
| 修订中 | 可编辑草稿。每个项目类型同时只能存在一份；自动保存到 publishedSnapshots，但**发布前不会被新建项目使用** |

**版本编号策略：** Vn 自增（V1 → V2 → V3 ...）。创建修订时基于该项目类型下的「最新已发布」编号 +1；若该项目类型从未发布过版本，则创建空白 V1 修订中。

**版本切换：**

- 顶部下拉选择器列出当前项目类型下所有版本（含状态后缀，如 `V3 (已发布)` / `V4 (修订中)`）
- 切换到任一已发布版本进入只读浏览模式
- 切换到修订中版本时自动进入编辑模式（与项目空间一致的 useEffect 监听 currentVersion / isCurrentDraft 触发 setIsEditMode(true)）
- 切换项目类型（左侧边栏）后版本下拉重新加载该类型的版本链；不同项目类型版本互不影响

**操作触发条件：**

| 操作 | 显示条件 | 行为 |
| --- | --- | --- |
| 创建修订 | 当前项目类型下不存在「修订中」版本（hasDraftVersion === false） | 克隆「最新已发布」生成 Vn+1 修订中（无已发布则创建空白 V1）；setCurrentVersion(newId)，UI 自动切换到该版本进入编辑模式 |
| 发布 | 当前选中版本为「修订中」（isCurrentDraft === true） | 先做任务时间合法性校验（同 3.3.10）；通过则将版本状态切换为「已发布」并写入 publishedSnapshots[versionId] = JSON.parse(JSON.stringify(tasks)) |
| 编辑 | 当前选中版本为「修订中」 | 不需要单独的"编辑"按钮，进入修订中即自动进入编辑模式（auto-edit useEffect） |
| 历史版本对比 | 任意版本均显示（含修订中） | 弹出 Modal 选择基准版本 + 对比版本（任意两个版本，含修订中），并排展示新增（绿）/ 删除（红）/ 修改（蓝）/ 未变更行；表头按 `序号 / 变更类型 / 任务名称 / 责任人 / 前置任务 / 计划开始 / 计划完成 / 预估工期 / 状态 / 进度` 列出 |

**与项目空间一级计划版本管理的差异：**

| 对比项 | 配置中心 | 项目空间 |
| --- | --- | --- |
| 版本作用域 | 项目类型级（4 个项目类型独立维护各自版本链） | 项目实例级（每个项目独立版本） |
| 市场维度 | 无（模板与市场无关） | 整机产品项目按市场（OP / TR / RU）独立维护版本和任务数据 |
| 权限准入 | 系统级权限中心控制：计划编辑用于模板修改，计划发布用于模板发布；无对应权限时相关操作禁用 | 有 plan:一级计划-编辑 → canFullyEdit；仅是责任人 → isRowEditable；其他 → 只读（详见 3.3.11） |
| 默认版本选择 | 始终显示当前项目类型下最新版本（不区分用户身份） | 按用户编辑权 + 责任人身份矩阵决定（详见 3.3.11） |
| 实际日期 / 工期 | 不支持（模板本身不含 actualStartDate / actualEndDate / actualDays） | 已发布版本可点击编辑实际日期，自动计算实际工期 |
| 分享链接 | 无 | 已发布版本可复制公开分享链接 |

#### 3.5.7 新建项目时的模板克隆机制

**核心定位：** 配置中心的一级计划模板是项目实例的「起点蓝图」。新建项目时按项目类型自动套用对应模板。

**克隆触发：** 创建新项目并指定项目类型时（V1.0 在工作台暂未开放新建入口，本机制为后端约定），系统按下面规则取模板任务结构作为该项目的初始一级计划任务列表。

**克隆来源选取：**

| 场景 | 克隆来源 |
| --- | --- |
| 该项目类型有「已发布」版本 | 取最新已发布版本（versionNo 最大且 status='已发布'）的 publishedSnapshots[versionId] 作为模板 |
| 该项目类型仅有「修订中」版本，无任何已发布 | **不使用修订中模板**；新建项目得到空白一级计划，由项目内的「创建修订」流程自行构建 |

**克隆字段范围：**

| 分类 | 字段 |
| --- | --- |
| ✅ 克隆（结构 + 默认值） | id、order、parentId、taskName、defaultRoadmap、responsible、predecessor、estimatedDays |
| ❌ 不克隆（项目实例独立维护） | planStartDate、planEndDate、actualStartDate、actualEndDate、actualDays、status、progress |
| 说明 | 模板提供"做什么 / 顺序 / 估时 / 默认负责人"，项目实例提供"具体什么时候做 / 实际进度"。模板不带项目实例特有的执行态。 |

**默认路标与项目路标视图联动：** 模板发布后，项目路标视图按当前项目类型的最新已发布一级计划模板读取二级任务，并以任务名称生成里程碑列。二级任务的 `defaultRoadmap=true` 时，该里程碑列在路标视图默认显示；`defaultRoadmap=false` 时默认隐藏但可在列设置中选择显示。一级任务只作为分组/阶段，不参与默认路标设置，也不会生成路标列。

**模板更新对已存在项目的影响：** 模板版本发布后**不回填**已存在的项目实例。每个项目实例的一级计划版本链独立演进。模板的版本对比能力主要服务于**模板维护者评估变更**，不直接驱动项目实例迁移。

**整机产品项目的特殊处理：** 整机产品项目在创建后会按 `markets` 字段（如 OP / TR / RU）独立维护各市场的一级计划版本和任务数据；模板克隆发生一次，每个市场各拿到一份初始拷贝，之后各自独立编辑。

### 3.6 权限中心 4️⃣

权限体系分为两个层级：**系统级权限中心**（Header 导航"权限中心"）和**项目级权限配置**（项目空间侧边栏"权限配置"）。两级权限都必须区分三类能力，避免把"能进入菜单""能看见数据""能执行操作"混为一个权限。

#### 3.6.1 权限模型

| 权限类型 | 控制对象 | 典型场景 | 无权限表现 |
| --- | --- | --- | --- |
| 菜单权限 | 是否展示或允许进入某个模块入口 | Header「项目路标视图」、Header「配置中心」、项目空间「权限配置」 | 菜单隐藏或禁用；直达 URL 时显示无权限页 |
| 数据权限 | 用户能看到哪些项目、市场、记录或字段 | 工作台项目列表、路标视图项目行、项目空间详情数据 | 数据不返回或不渲染；列表为空时显示无权限/空态 |
| 操作权限 | 用户能否执行某个动作 | 编辑、发布、导出、分享、创建基线、角色管理 | 按钮禁用并通过 Tooltip 说明原因；接口二次校验拒绝 |

**权限判定顺序：**

1. 先校验菜单权限：没有模块入口权限时，不展示入口。
2. 再校验数据权限：进入模块后，只展示当前用户有权访问的数据范围。
3. 最后校验操作权限：用户看到数据不代表可以编辑、发布、导出或管理角色。

**旁路规则：** 系统级"管理组"成员拥有全部系统级权限，并旁路项目级权限校验；普通用户必须同时满足项目数据权限和对应操作权限。

| 模块 | 菜单权限 | 数据权限 | 操作权限 |
| --- | --- | --- | --- |
| 项目路标 | `roadmap:view` 控制是否显示/进入「项目路标视图」 | 复用项目可见范围，只展示用户有权访问的项目行；管理组可看全部项目 | `roadmap:edit` 编辑路标数据；`roadmap:baseline` 创建基线/快照；`roadmap:share` 分享视图；`roadmap:export` 导出 Excel |
| 配置中心 | 当前版本由 `configCenter:planEdit` / `configCenter:planPublish` / `configCenter:transferEdit` 任一权限推导显示入口；后续可独立拆出 `configCenter:view` | 可查看对应项目类型的模板数据；没有任何配置中心权限时不展示配置中心入口 | `configCenter:planEdit` 修改计划模板；`configCenter:planPublish` 发布计划模板；`configCenter:transferEdit` 修改转维材料模板（当前为后续能力预留） |
| 权限中心 | 当前版本由 `permissionCenter:manageRoles` 推导显示入口；后续可独立拆出 `permissionCenter:view` | 可查看系统级角色、成员和权限配置 | `permissionCenter:manageRoles` 对系统级角色进行新增、修改、删除、成员添加和权限调整 |

**系统级预置权限：**

| 权限组 | 菜单权限 | 数据权限 | 操作权限 |
| --- | --- | --- | --- |
| 管理组 | 项目路标、配置中心、权限中心 | 全部项目、全部项目类型模板、全部系统角色配置 | 项目路标全部操作 + 配置中心全部操作 + 系统角色管理 |
| 编辑组 | 项目路标 | 按项目可见范围过滤项目行 | 项目路标编辑、基线 |
| 查看组 | 项目路标 | 按项目可见范围过滤项目行 | 无编辑类操作 |

#### 3.6.3 项目级权限配置

**入口：** 项目空间 → 侧边栏 → "权限配置"

**定位：** 管理单个项目内的角色、成员、菜单权限、数据权限和操作权限。项目级权限只作用于当前项目，不影响其他项目。

##### Tab 1：角色人员配置

| 功能 | 说明 |
| --- | --- |
| 角色列表 | 表格展示项目内所有角色及其成员 |
| 新增角色 | 弹窗输入角色名称创建自定义角色 |
| 重命名 | 行内编辑角色名称（固定角色不可重命名） |
| 删除角色 | 二次确认后删除（固定角色不可删除） |
| 人员配置 | 多选下拉框选择项目成员 |

**项目数据权限基础规则：**

| 场景 | 数据权限规则 |
| --- | --- |
| 工作台项目列表 | 管理组可见全部项目；普通用户仅可见自己在项目成员或项目角色中的项目 |
| 项目空间直达 | 用户没有该项目数据权限时，不进入项目详情，显示无权限提示 |
| 项目空间页面数据 | 进入项目后仍按模块数据权限控制可见内容，例如基本信息、转维信息、计划与配置、计划数据 |
| 整机项目市场数据 | 当前按项目授权；用户能看项目即能看该项目全部市场。若后续需要市场级隔离，需新增市场数据权限 |
| 字段级数据 | 当前不做字段级脱敏；有对应模块数据权限即可查看该模块内配置展示字段 |

##### Tab 2：权限配置

项目级权限配置采用"角色 Tab + 权限表格"布局。

- 顶部以 Tab 展示项目角色：系统管理员、项目经理、产品经理、软件SE、开发代表、设计师、测试TPM、SQA、开发工程师、测试工程师、管理层、其他、自定义角色。
- 切换角色后，下方只展示当前角色的权限表。
- 权限表左侧展示模块，右侧展示权限项。
- 勾选项显示蓝色勾选图标，未勾选项显示红色叉号。

**项目级权限拆分：**

| 模块 | 菜单权限 | 数据权限 | 操作权限 |
| --- | --- | --- | --- |
| 项目资料 | 拥有任一项目资料数据权限时展示「基础信息」入口 | `basicInfo:查看` 查看基本信息；`basicInfo:transferView` 查看转维信息；`basicInfo:planConfigView` 查看计划与配置信息 | `basicInfo:编辑` 编辑基础信息；`basicInfo:applyTransfer` 发起转维申请 |
| 计划管理 | `plan:一级计划-查看` 或 `plan:二级计划-查看` 控制是否展示计划入口 | 查看一级计划、二级计划、版本、任务和计划总览数据 | `plan:一级计划-编辑` 编辑/创建修订/发布计划；`plan:一级计划-分享` 分享计划；`plan:导入` 导入计划；`plan:导出` 导出计划 |

> 说明：当前实现中一级计划的"查看/编辑"权限同时兼容二级计划查看/编辑能力，避免旧权限键失效。若后续需要严格区分一级计划和二级计划，应将 `plan:一级计划-查看/编辑` 与 `plan:二级计划-查看/编辑` 拆成独立配置项。

#### 3.6.4 两级权限体系对比

| 对比项 | 系统级权限中心 | 项目级权限配置 |
| --- | --- | --- |
| 入口 | Header "权限中心" | 项目空间侧边栏 "权限配置" |
| 管辖范围 | 全局功能：项目路标、配置中心、系统权限中心 | 单项目功能：项目资料、计划管理、项目权限中心 |
| 菜单权限 | 控制 Header 级模块入口 | 控制项目空间内侧边栏菜单入口 |
| 数据权限 | 控制跨项目/跨模板数据可见范围 | 控制当前项目内模块数据可见范围 |
| 操作权限 | 控制全局动作，例如路标导出、模板发布、系统角色管理 | 控制项目内动作，例如基础信息编辑、计划分享导出、项目角色管理 |
| 角色类型 | 3 个固定角色 + 自定义角色 | 12 个固定角色 + 自定义角色 |

#### 3.6.5 UI 级权限闸点

以下列出 V1.0 需要在 UI 上强制校验的主要权限点。前端禁用或隐藏只用于体验优化，后续接入后端后仍需由接口做同样校验。

| 页面/入口 | 校验类型 | 权限点 | 无权限时表现 |
| --- | --- | --- | --- |
| Header「项目路标视图」 | 菜单权限 | `roadmap:view` | 菜单隐藏或禁用；直达时显示无权限 |
| 路标视图项目行 | 数据权限 | 用户可见项目范围 | 不渲染无权项目行 |
| 路标视图编辑动作 | 操作权限 | `roadmap:edit` | 编辑入口禁用 |
| 路标视图创建基线/快照 | 操作权限 | `roadmap:baseline` | 按钮禁用 + Tooltip |
| 路标视图分享 | 操作权限 | `roadmap:share` | 分享按钮禁用 + Tooltip |
| 路标视图导出 | 操作权限 | `roadmap:export` | 导出按钮禁用 + Tooltip |
| Header「配置中心」 | 菜单权限 | 任一配置中心操作权限，后续可拆 `configCenter:view` | 菜单隐藏或禁用 |
| 配置中心计划模板编辑 | 操作权限 | `configCenter:planEdit` | 编辑入口禁用 + Tooltip |
| 配置中心计划模板发布 | 操作权限 | `configCenter:planPublish` | 发布按钮禁用 + Tooltip |
| 配置中心转维模板编辑 | 操作权限 | `configCenter:transferEdit` | 转维模板编辑入口禁用 |
| Header「权限中心」 | 菜单/操作权限 | `permissionCenter:manageRoles` | 菜单隐藏或禁用 |
| 工作台项目列表 | 数据权限 | 项目成员/项目角色归属；管理组旁路 | 无权项目不展示 |
| 项目空间直达 | 数据权限 | 当前用户是否有该项目访问权 | 显示无权限提示，不展示项目详情 |
| 项目空间「基础信息」入口 | 菜单/数据权限 | 任一项目资料数据权限 | 入口隐藏或禁用 |
| 项目空间「基础信息」编辑按钮 | 操作权限 | `basicInfo:编辑` | 按钮禁用 + Tooltip "无基本信息编辑权限" |
| 项目空间「申请转维」按钮 | 操作权限 | `basicInfo:applyTransfer` | 按钮禁用 + Tooltip |
| 项目空间「计划」入口 | 菜单/数据权限 | `plan:一级计划-查看` 或 `plan:二级计划-查看` | 入口隐藏或禁用 |
| 一级计划「创建修订」「编辑」「发布」 | 操作权限 | `plan:一级计划-编辑` | 按钮禁用 + Tooltip "无一级计划编辑权限" |
| 计划分享 | 操作权限 | `plan:一级计划-分享` | 分享按钮禁用 + Tooltip |
| 计划导入 | 操作权限 | `plan:导入` | 导入按钮禁用 + Tooltip |
| 计划导出 | 操作权限 | `plan:导出` | 导出按钮禁用 + Tooltip |
| 项目空间「权限配置」入口 | 菜单/操作权限 | `projectPermission:manageRoles`，后续可拆 `projectPermission:view` | 入口隐藏或禁用 |
| 项目权限角色管理 | 操作权限 | `projectPermission:manageRoles` | 新增、重命名、删除、成员调整、权限调整入口禁用 |

> 🎁 **校验规则：** 普通用户按当前项目内所属角色聚合权限，只要任一角色对该权限项设为 true 即通过；系统级"管理组"成员直接放行。菜单权限只决定入口是否可见，不能替代数据权限；数据权限只决定可见范围，不能替代操作权限。

#### 3.6.6 用户切换器（开发辅助）

**功能描述：** 为方便开发阶段测试不同角色的权限效果，系统在主 Header（工作台/路标/配置中心等模式）和项目空间 Header 的右上角内置用户切换下拉。点击头像可快速切换当前登录用户，UI 权限闸点和项目可见范围会立即按新身份刷新。

**能力：**

- 下拉列出所有可选用户，每项标注是否属于"管理组"以及该用户可见的项目数量
- 选中后无需刷新页面，权限校验、项目列表过滤、转维申请人身份等即时生效
- 管理组用户旁路所有项目级权限

> 🎁 **注意：** 该功能为**开发 / 演示辅助工具**，正式环境上线前应下线此入口，或仅对管理员可见。
