# 一级计划业务节点与 MR 联动规则

用户授权：实现、测试，推送 dev，合并 master，发布 Vercel。

## 规则

- tOS 上市迭代、维护子任务仅最新发布版允许有权限人员维护；修订同步显示且只读，发布不覆盖共享集合。
- 跟随市场/类型只跟随普通里程碑，业务子任务保留当前市场/类型的独立集合。
- 整机上市、生命周期子任务由本市场 MR 自动生成，所有版本禁止手动维护。
- N/A 转测整机行不投影到整机 MR 或一级计划。其他现有 MR 有效性约束保留。
- 按 tOS 版本数字升序统一编号 MR1、MR2…，tOS 上市迭代映射整机上市，维护映射生命周期。
- 用户确认：自动节点计划起止日期取该市场 MR 活动日期最早/最晚值。没有活动日期保持空白，不借用其他市场日期。
- 整机 MR 计划横版和竖版的 tOS版本号 后新增 MR号，显示与一级计划一致的自动 MR 序号。
- 保持稳定来源身份、历史快照、权限检查、跨页同步幂等，不丢弃原来 MR 明细。

## Task 1: 整机自动投影领域

在 mrMachineMarketRules 与新领域 helper 中实现从现有 MR 投影到各市场业务子任务，接入全局同步 hook。使用当前 tOS 业务来源确定阶段并按版本排序；保留稳定身份，过滤 N/A，不能继承跟随市场的子任务。添加领域回归。允许修改 src/lib/mrMachineMarketRules.ts、新 helper、src/hooks/useTosMrLevel1Sync.ts 和新测试；不修改 ProjectSpaceContainer、level1PlanRules 或 fixtures。不提交、不推送，交由主 agent 集成。

## Task 2: 一级计划界面与权限

主 agent 修改权限领域、tOS 独立类型的业务 scope 和 UI mutation guard。修订不可维护业务节点；最新发布的跟随类型可维护本类型业务，其他里程碑仍只读。整机全部业务编辑入口关闭。保留旧版本历史，发布/取消修订不能覆盖共享集合。

## Task 3: Mock 与验证发布

更新代表性 mock（类型/市场独立、两个阶段、N/A、不同市场日期）。更新旧权限测试契约。领域校验、类型检查、构建，真实浏览器操作 tOS 最新发布与修订、跟随类型、整机自动投影及刷新数据保持。独立代码审查后修复，dev/master 合并发布并检查部署 commit、生产流程与运行错误。

## 协作边界

Task 1 生成共享业务集合，Task 2 读取集合，不从生成节点反向写 MR。Task 1 的 hook 必须可重复执行且未 hydration 时不写。Task 2 保持 setPublishedSnapshots 的 no-op 写入保护。Task 3 只更新确认为旧契约的断言。

## 验证结果

- 领域回归通过：一级计划权限/业务隔离、MR 自动投影、来源同步、删除重建、快照幂等、MR 完整规则与 mock、列表/甘特规则。
- npx tsc --noEmit、npm run build、git diff --check 通过。
- 浏览器回归通过：最新发布维护与修订只读、跟随类型独立、发布历史、整机自动节点发布、市场独立日期、N/A 排除、两方向 MR号、跨页同步和刷新；未捕获运行错误。
- 正常来源 mock 的 16.3.0.145 开始和 16.3.0.150 结束与一级计划边界一致；负向日期测试保留为独立输入，避免正常下游被来源错误污染。
- 最终独立审查无阻塞项。
