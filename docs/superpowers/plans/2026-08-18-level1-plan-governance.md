# 一级计划治理实施计划

> 依据 `docs/superpowers/specs/2026-08-18-level1-plan-governance-design.md`。本轮在三级计划已独立发布后实施，完成后再次走 dev → master → Vercel。

## Task 1：统一一级计划规则层

- 新增 `src/lib/level1PlanRules.ts`，定义标准四阶段模板、任务来源、项目计划投影、日期合法性、严格递增校验、阶段聚合、工期、人力占比和延期计算。
- 技术子项目单层节点使用独立模式：可编辑两个完成时间、无阶段聚合和占比。
- 新增 `scripts/verify-level1-plan-governance.mjs`，先覆盖空阶段跳过、自然日差、严格递增、延期、权限和例外场景。

## Task 2：模板配置与持久化迁移

- 升级计划 store 版本；整机、tOS、能力建设内置模板迁移为四阶段结构并保留稳定 ID/source。
- 技术 TDT、子项目模板内容保持现状，只补来源与兼容字段。
- 配置中心模板固定为“序号、任务名称、角色”；隐藏非技术项目的二级计划配置，技术项目只显示 TDT/子项目模板。
- 迁移必须保留用户项目、自定义节点和历史快照并保持幂等。

## Task 3：版本、模板同步与实际完成时间联动

- 项目初始化记录模板版本和稳定任务 ID。
- 第一次修订同步最新正式模板；后续修订只复制上一正式版。
- 实际完成时间只在当前修订与其来源正式版之间双向同步；计划完成时间不跨版本同步。
- 增加纯函数验证首次/后续修订、模板新增删除、自定义节点保留和异常稳定 ID 阻断。

## Task 4：项目空间表格、权限和结构操作

- 一级计划竖版固定九列，移除责任人、前置任务、状态、进度。
- 标准计划一级活动始终只读；二级活动只编辑计划完成/实际结束。已发布版只允许实际结束。
- 权限统一为项目 SPM、技术项目负责人或全局管理组；事件处理与按钮显示共用同一判断。
- 普通 SPM 仅能在整机“上市收编阶段”新增 custom 子活动并删除 custom；系统管理员可新增删除全部结构。
- 日期错误保留输入、红色标记、明确提示并阻止修订发布。

## Task 5：横版、基础信息、导出和版本对比

- 进入计划默认横版；横版阶段名称下显示时间范围，右侧显示工期权重占比。
- 横版与基础信息共用投影和编辑逻辑；修订版可改两个完成时间，发布版只改实际结束。
- 列设置、导出和版本对比统一使用九列投影，不再暴露旧字段。

## Task 6：技术计划与 Mock

- TDT 项目计划复用标准父子活动规则和技术项目负责人权限。
- 子项目计划按单层里程碑例外处理，保持现有模板内容。
- 刷新整机、tOS、能力建设 Mock 日期为四阶段严格递增结构；技术 Mock 仅转换字段/来源。

## Task 7：验证与第二次发布

- 运行全部相关契约脚本、TypeScript 和生产构建。
- 浏览器覆盖管理员、项目 SPM、技术项目负责人和普通成员；验证配置入口、九列表格、横版编辑、红色校验、首次修订同步、实际时间联动和技术计划例外。
- 推送 dev，干净工作区合并 master，等待 Vercel READY，并在线回归关键路径。
