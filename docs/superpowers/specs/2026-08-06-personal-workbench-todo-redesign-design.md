# 个人工作台待办中心精简设计

## 1. 目标

将工作台首页从“分类待办 + 指标卡片 + 独立页签栏”精简为一个统一的个人工作台：标题与模块切换位于同一行，待办中心聚焦当前仍需处理的任务，并以生成时间和任务分类进行筛选。

## 2. 页面结构

### 2.1 顶部标题区

- 左侧标题固定为“个人工作台”。
- 删除原“个人工作台”眉题和“分类待办”标题的双层结构。
- 右侧显示“待办中心 / 工作跟踪”胶囊切换，不显示图标。
- 切换仍使用现有 `workbenchTab` 状态和 `navigateWithEditGuard`，不改变返回项目空间时的来源恢复逻辑。

### 2.2 待办中心移除内容

- 删除“全部 / 计划待办 / 转维待办”的顶部分段切换。
- 删除待办总数、今日到期、已逾期、本周完成四个指标卡片。
- 保留筛选区、结果状态、表格、加载态、错误态和空状态。

## 3. 表格字段

| 顺序 | 字段 | 数据来源 | 展示规则 |
| --- | --- | --- | --- |
| 1 | 任务名称 | `todo.title` | 单行省略，完整内容可通过 Tooltip 查看 |
| 2 | 所属项目 | `todo.projectName` | 无项目时显示“未关联项目” |
| 3 | 任务 | `todo.source`、`sourceLabel`、`context` | 显示计划待办或转维待办标签，并补充具体计划名称、版本、市场或当前节点 |
| 4 | 处理人 | `todo.assignee` | 显示当前处理人 |
| 5 | 生成时间 | `todo.generatedAt` | 仅显示 `YYYY-MM-DD`，不显示到期、逾期或其他状态徽标 |
| 6 | 操作 | 当前待办路由 | 固定在右侧，文案为“前往处理” |

删除原独立“状态”列和“截止日期”列。

## 4. 待办范围

- 只展示仍需处理的任务，即 `status !== 'completed'`。
- `pending` 和 `in_progress` 都属于待处理范围。
- 已完成任务不参与结果、分页或筛选数量。
- 权限过滤、当前登录用户过滤和计划/转维路由合法性继续使用现有聚合逻辑。

## 5. 生成时间规则

- `WorkbenchTodo`、`PlanTodoCandidate` 和 `TransferTodoCandidate` 增加 `generatedAt`。
- 转维待办优先读取转维申请 `createdAt`。
- 计划待办优先读取任务或版本提供的 `generatedAt`。
- 当前 Mock 未提供计划生成时间时，使用本次聚合的 `today` 日期作为兼容值；后续接入后端时直接由服务端字段覆盖。
- 聚合层统一规范化为 `YYYY-MM-DD`，无合法值时显示“未记录”。
- 列表默认按生成时间倒序，再按任务名称和 ID 稳定排序。

## 6. 筛选

筛选区从左到右：

1. 搜索：模糊匹配任务名称、项目名称、具体计划/节点上下文。
2. 项目：单选，可清空。
3. 任务分类：多选，选项为“计划待办”“转维待办”；未选择表示全部。
4. 生成时间：日期范围选择器，同时选择开始和结束日期；允许清空。
5. 清空筛选。

移除状态筛选。筛选条件变化后分页回到第一页。

## 7. 分页

- 默认每页 10 条。
- 可选每页 10、20、50 条。
- 显示总条数。
- 数据不足一页时仍保留简洁分页信息，不显示无意义的页码跳转。
- 当前页因筛选或数据变化超出最大页码时自动回到最后一个有效页，优先回到第一页。

## 8. 状态与反馈

- 加载、错误重试和空状态继续保留。
- 空状态统一为“暂无符合条件的待办”，若任务分类只选计划或转维，则显示对应分类空状态。
- 结果状态展示筛选后的未完成待办总数，不把分页后的当前页数量误当作总数。
- “前往处理”继续调用现有 `onOpenTodo`，项目缺失时沿用警告提示。

## 9. 样式与无障碍

- 顶部胶囊使用当前项目列表视图切换的轻量样式语言，选中态为白底/主色或主色底，避免大按钮。
- 标题区高度固定，待办中心和工作跟踪切换时不跳动。
- 胶囊支持键盘操作并具有 `aria-label="个人工作台模块"`。
- 表格操作按钮具有包含任务名称的辅助文本。
- 日期范围和任务分类筛选具有可读标签。

## 10. 不在本次范围

- 不新增待办完成、转派或批量处理功能。
- 不改变计划和转维业务流程。
- 不引入后端持久化或新的通知机制。
- 不展示已完成历史待办。

## 11. 验收标准

1. 页面顶部仅显示“个人工作台”和右侧胶囊切换。
2. 原分类待办标题、来源分段和四个指标卡片已移除。
3. 表格列严格为任务名称、所属项目、任务、处理人、生成时间、操作。
4. 列表不包含 `completed` 任务。
5. 任务分类多选、项目、搜索和生成时间范围共同生效。
6. 状态筛选不存在，生成时间后无状态徽标。
7. 操作文案为“前往处理”，并可进入原目标页面。
8. 分页默认 10 条，支持 10/20/50，显示总数。
9. 筛选变化后回到第一页。
10. `npm run verify:todo-center`、`npx tsc --noEmit` 和 `npm run build` 通过。
11. 浏览器手动验证待办中心/工作跟踪切换、全部筛选组合、分页、空态、加载/错误态和前往处理。
