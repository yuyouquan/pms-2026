# 一级计划业务节点、MR 版本计划与项目字段调整设计

**日期：** 2026-08-30  
**适用分支：** `codex/mr-version-plan`  
**状态：** 已完成业务确认与书面规格审核

## 1. 目标与范围

本次在现有一级计划和“三级计划-MR版本计划”基础上完成六类调整：

1. 整机与 tOS 一级计划业务节点新增由两步弹窗改为单步弹窗，并提供严格名称校验和自动预填；
2. tOS 项目空间的 MR 版本计划增加已添加版本号模糊搜索；
3. 所有 MR 日期错误提示补充实际边界日期；
4. 联合项目空间删除独立“错误提示”列，错误落到对应日期单元格；
5. 增加独立项目经理 Mock 用户，用于项目空间权限验证；
6. 按确认清单调整整机、技术项目的新建字段顺序、必填规则、项目空间顺序和默认显示状态。

本次不调整 tOS 版本项目的新建或项目空间字段顺序，不改变已经确认的 MR 聚合、停止发版、主市场同步和 1+N 计算规则。

## 2. 总体方案

采用“共享规则 + 字段 Schema 驱动”方案：

- 名称自动生成、名称校验、日期边界错误格式化进入纯规则函数；
- 一级计划弹窗、tOS MR 页面、联合项目空间只消费规则结果；
- 字段的业务定义保持单一来源，但新建页与项目空间使用独立的有序字段键清单；
- 项目空间默认显示状态继续由字段定义控制，用户字段设置继续工作；
- 不做通用元数据引擎重构，不扩展到本次未指定的项目类型。

## 3. 一级计划业务节点新增

### 3.1 入口范围

- 整机产品项目：仅“上市阶段、生命周期阶段”允许添加业务节点；
- tOS 版本项目：仅“上市迭代阶段、维护阶段”允许添加业务节点；
- 入口权限、修订状态限制和父阶段结构规则继续沿用现有一级计划。

### 3.2 单步弹窗

点击添加业务节点后直接打开名称输入弹窗，不再出现“是否添加 MR 里程碑？”或“是否添加 tOS 版本？”确认步骤，也不再出现“下一步”按钮。

弹窗结构：

1. 标题：整机为“输入 MR 里程碑名称”，tOS 为“输入 tOS 版本名称”；
2. 顶部规则说明；
3. 自动预填的名称输入框；
4. “取消”“确认添加”按钮。

弹窗只录入名称。计划开始、计划完成、实际开始和实际完成日期仍在一级计划表格或甘特图中维护。

### 3.3 MR 名称规则

- 格式：`MR` + 不含前导零的正整数；
- 允许：`MR1`、`MR2`、`MR10`；
- 拒绝：`MR0`、`MR01`、`MR001`、其他前后缀和重复名称；
- 弹窗规则文案：`格式：MR+正整数，不允许前导0；示例：MR1、MR2。`；
- 自动预填：取当前项目所有现有 MR 业务节点中的最大数字加 1；
- 当前没有 MR 节点时预填 `MR1`；
- 中间编号被删除时不补缺号。例如已有 `MR1、MR3`，新增预填 `MR4`。

### 3.4 tOS 业务版本规则

- 继续使用项目名称解析出的 `<主版本>.<次版本>.0.XXX` 前缀规则；
- `XXX` 必须为三位数字，最后一位必须为 `0` 或 `5`；
- 弹窗规则文案展示当前项目的实际前缀和合法示例；
- 自动预填：取当前项目现有 tOS 业务版本的最大三位尾号加 5；
- 当前没有业务版本时预填 `<项目版本>.0.100`；
- 中间版本被删除时不补缺号。例如已有 `.100、.110`，新增预填 `.115`；
- 人工修改仍执行完整前缀、三位尾号、尾号末位和重复名称校验。

### 3.5 提交保护

- 默认名称只在打开弹窗时计算，取消不修改计划；
- 确认添加时再次执行格式、重复名称、父阶段和计划日期顺序校验；
- 输入非法时保持弹窗打开，输入框标红并显示明确原因；
- 添加成功后沿用现有序号重排、保存和历史记录逻辑。

## 4. tOS 项目空间 MR 版本号搜索

- 在“新增tOS版本号”按钮左侧增加搜索框；
- 支持完整版本号和任意片段模糊匹配，例如输入 `145` 匹配 `16.3.0.145`；
- 搜索只过滤当前已经添加到三级计划中的 tOS 版本实例，不改变新增弹窗候选项；
- 竖版和横版共用相同搜索条件和过滤结果；
- 搜索条件为当前页面临时状态，不写入 MR 业务数据或持久化存储；
- 无结果时显示空状态，清空搜索后恢复完整列表；
- 搜索不改变版本号原有升序排列。

## 5. MR 日期错误与联合空间展示

### 5.1 错误文案补充实际边界日期

所有含“不早于”“不晚于”“至少一周”“不能超过”的 MR 日期错误都必须显示用于比较的实际边界日期。

示例：

- `修改点收集开始时间不能早于一级计划中的计划开始时间（2026-09-10）`；
- `OTA开放验证&部署不能晚于一级计划中的计划完成时间（2026-10-20）`；
- 上一个 1+N 类型至少一周规则显示计算后的最早允许日期；
- 下一个 tOS 版本限制显示对应活动的最晚允许日期；
- 同时存在上下限时在同一提示框逐条显示并去重。

规则层返回结构化错误，至少包含：行键、活动键、活动名称、消息、边界日期和边界类型。展示层不得自行拼装不同文案。

### 5.2 联合项目空间

- 删除最右侧“错误提示”列及其固定列宽；
- 每个错误只标记在对应日期单元格；
- 可编辑日期输入框显示红色边框，并在单元格右侧显示红色错误图标；
- 悬浮或键盘聚焦错误图标时显示该单元格全部错误；
- tOS 只读行若源数据违反其一级计划边界，同样在对应只读日期单元格显示红色状态和错误图标；
- 错误单元格、固定列和水平滚动区域不能重叠。

项目空间横竖视图继续使用相同的单元格错误模式，并读取同一结构化错误结果。

## 6. 项目经理权限 Mock

- 用户列表新增独立用户“钱九”；
- “钱九”不属于全局“管理组”、系统管理员或其他项目角色；
- 在整机项目 `X6877-D8400_H991` 中，“钱九”仅属于项目级“项目经理”；
- 将“钱九”加入该项目可见成员范围，使其可从项目列表进入项目空间；
- “钱九”的能力完全来源于现有项目经理角色权限，不增加用户级硬编码；
- 权限验收角色：
  - 张三：全局超级管理员；
  - 钱九：单项目项目经理；
  - 李四：普通成员/无项目经理权限。

## 7. 字段 Schema 与顺序

### 7.1 结构原则

- 共享字段定义保存字段键、标签、输入类型、只读性、必填性和默认显示状态；
- 新建页与项目空间分别维护有序字段键清单，不再依赖同一个数组顺序；
- 删除字段不进入项目空间字段清单，也不出现在字段设置中；
- 默认不显示字段仍存在于字段设置中，可由用户显示；
- 保存的旧字段设置在读取时清理无效或已删除字段，其他选择继续保留；
- 为兼容其他业务消费者，只从项目信息 Schema/UI 删除字段，不破坏性删除底层项目类型属性。

## 8. 数据流与兼容性

- 一级计划节点写入仍走现有计划 Store 和版本快照；
- MR 日期错误由纯规则函数计算，不在组件内部生成第二套规则；
- tOS 搜索只作用于派生后的展示行；
- 联合空间删除错误列不改变 MR 计划、停止发版或聚合数据结构；
- 字段顺序调整不改写已有项目值；
- 新增“其他”等当前缺少的展示字段时使用明确字段键，并纳入创建草稿、项目保存和字段设置清理；
- 从 UI 清单移除的字段保留底层兼容读取能力，避免影响项目列表、路线图等其他模块。

## 9. 验收与回归

### 9.1 规则验证

- MR 首个、连续、缺号、前导零、重复名称；
- tOS 首个 `.100`、连续加 5、缺号取最大值、前缀和尾号校验；
- 每一类 MR 日期错误均包含正确边界日期；
- 搜索片段过滤、清空恢复、横竖视图一致；
- 四套字段顺序、必填状态和默认显示状态逐项精确匹配；
- 旧字段设置中的删除键被清理。

### 9.2 页面验证
