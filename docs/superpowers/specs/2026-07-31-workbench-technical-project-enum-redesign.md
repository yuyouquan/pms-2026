# 工作台拆分、技术项目与枚举配置设计

日期：2026-07-31  
状态：已完成口头设计确认，待用户审核书面规格  
实现方式：快速开发模式，领域模块化增量实现

## 1. 背景

当前工作台同时承载项目列表、工作跟踪和折叠式待办中心；项目列表尚未覆盖技术项目；技术项目创建、项目空间、计划模板、权限与IPM子项目关系也未形成完整闭环。tOS版本目前由路标模块独立维护，缺少统一的枚举配置入口。

本次改造拆分工作台与项目列表，重做待办中心，补齐枚举值配置、整机tOS版本联动、技术项目创建与项目空间，并将技术项目的TDT计划、IPM子项目计划、权限和项目列表统一到明确的数据模型中。

## 2. 目标

1. 将“项目列表”从工作台拆为独立主导航。
2. 工作台只保留待办中心与工作跟踪，默认打开待办中心。
3. 新版待办中心统一聚合当前用户的计划待办和转维待办。
4. 配置中心增加固定类型的枚举值配置。
5. tOS路标和技术子项目使用两位tOS枚举；整机版本字段使用三位tOS枚举。
6. 补齐整机新品／老品的首销版本和当前版本联动。
7. 完成技术TDT项目创建、编辑、核心信息、团队、交付物、IPM子项目与计划管理。
8. 技术项目采用TDT项目计划和子项目计划两类模板。
9. 补齐tOS项目与技术项目的权限角色规则。
10. 项目列表支持整机、tOS和技术项目的专属字段、筛选、里程碑分组与跳转。

## 3. 非目标

1. 不为能力建设项目新增列表表格规则，仍展示空状态。
2. 不允许在PMS手工创建技术子项目。
3. 不重构整套项目、计划和权限store为全新的实体框架。
4. 不建设真实IPM接口、文件服务或后端数据库；继续使用可替换的前端Mock适配层。
5. 不保留当前技术项目旧一级／二级计划Mock版本。
6. 不改变整机、tOS既有计划编辑、发布、比较、导入导出等业务交互。

## 4. 总体架构

采用领域模块化增量实现：

- `workbench`：待办中心、工作跟踪。
- `projectList`：项目创建、分类、筛选、汇总表格。
- `enumConfig`：固定枚举类型和字符串值维护。
- `technicalProject`：TDT项目字段、IPM子项目、子项目配置与停用状态。
- `technicalPlan`：TDT计划和各子项目计划的独立版本实例。
- `todoAggregation`：从计划与转维状态派生当前用户待办。
- 继续复用现有项目基础信息schema、项目汇总表格、计划版本能力、权限检查和导航编辑保护。

## 7. 枚举值配置

### 7.1 页面结构

配置中心增加“枚举值配置”。

- 左侧：枚举类型。
- 右侧：当前类型的枚举值表格。
- 右侧支持新增、编辑、删除。

### 7.2 固定类型

本期固定两种类型，不允许新增、重命名或删除类型：

1. `tOS版本（2位）`
2. `tOS版本（3位）`

初始数据：

- 两位：`16.0`、`17.2`
- 三位：`16.0.1`、`16.0.2`、`17.2.0`

### 7.3 校验与保存

- 两位格式：`数字.数字`。
- 三位格式：`数字.数字.数字`。
- 保存前去除前后空格。
- 同一类型内禁止重复。
- 枚举中心保存纯数字版本，不保存`tOS`前缀。
- 业务页面统一显示为`tOS`加版本字符串。

枚举值是业务输入选项，不是引用实体：

- 业务表单保存当时选择的字符串快照。
- 枚举值允许直接删除。
- 删除或修改枚举不会更新、清空或阻止历史业务值显示。
- 编辑业务记录时允许保留已删除的旧值；重新选择时只展示当前有效枚举。

### 7.4 使用范围

两位版本：

- tOS路标视图的tOS版本维护。
- 技术子项目配置的首导tOS。

三位版本：

- 整机产品项目首销tOS版本。
- 整机产品项目当前tOS版本。

tOS版本项目的`tOS版本`直接读取项目名称，不读取枚举；创建项目不会自动新增枚举，也不要求同名枚举存在。

## 8. 项目创建与责任人

### 8.1 通用责任人规则

- 整机产品项目：项目责任人自动等于SPM。
- tOS版本项目：项目责任人自动等于版本项目经理。
- 技术TDT项目：项目责任人自动等于技术项目负责人。
- 能力建设项目：继续手工填写项目责任人。
- PMS不提供技术子项目创建入口。

自动责任人不再作为独立可填写字段。

### 8.2 整机新品与老品

同一产品族使用PMS项目名匹配：

- 去除项目前后空格后精确匹配。
- 只匹配产品类型为“新品”的整机项目。
- 项目编码、Android版本和创建年份不参与匹配。

新品：

- 用户填写首销tOS版本。
- 创建时当前tOS版本初始化为首销版本。

老品：

- 必须匹配唯一新品。
- 首销tOS版本继承新品。
- 用户填写当前tOS版本。
- 找不到新品或匹配到多个新品时禁止提交。

新品当前版本计算：

- 收集全部同名老品项目的当前tOS版本。
- 按数字分段进行三位版本比较。
- 新品当前版本取最大老品版本。
- 没有老品时等于新品首销版本。
- 修改任意老品后重新计算，不使用“最后保存覆盖”。
- 删除枚举不影响历史版本字符串继续参与计算。

口头示例中的`tOS14.0`、`tOS15.0`是简称；实际三位值为`tOS14.0.0`、`tOS15.0.0`。

## 9. 技术TDT项目创建与编辑

### 9.1 IPM带出字段

选择IPM项目后自动带出：

- 项目名称
- 项目分类
- 项目二级分类
- 技术赛道

项目分类和二级分类使用现有IPM项目类型映射。PMS创建入口只创建TDT项目；子项目由IPM同步。

### 9.2 技术领域与子领域

`TMG及技术领域`必填、单选。`子领域`必填、单选，并随技术领域变化。

映射：

| TMG及技术领域 | 子领域 |
| --- | --- |
| 基础架构TMG | 无 |
| 性能TMG | 无 |
| DFX TMG | 无 |
| UX TMG | 无 |
| 系统应用 | AIOS、应用、图形、内核、多媒体 |
| 底软通信 | 器件、蜂窝、短距、功耗 |
| 集成维护 | 三方体验、GMS |
| 其他 | 安全、AIOT |

选择前四种技术领域时，子领域自动填写“无”、禁用修改，并视为满足必填。

### 9.3 其他项目字段

- 前置项目：仅IPM项目类型为“技术项目前置工作”时显示并必填。
- 前置项目选项：PMS中除当前项目外的全部项目，支持模糊搜索。
- 项目年份：年份选择器。
- 项目价值：非必填多行文本。

### 9.4 团队字段

创建与编辑包含：

- 技术项目负责人：必填。
- 技术项目经理：非必填。
- 测试代表：非必填。
- 质量代表：非必填。
- 产品代表：非必填。
- 标准化代表：非必填。

项目责任人始终取技术项目负责人。

### 9.5 交付物字段

- 项目KPI文件
- 概设
- charter报告
- PDCP报告
- TDCP报告
- EDCP报告

规则：

- 全部非必填。
- 每个字段最多保存一个内容。
- 支持链接或文件上传，两者互斥。
- 可替换或清空。
- 当前Mock实现保存URL，或文件名与附件元数据。

## 10. 技术项目空间

### 10.1 核心板块

展示：

- 项目名称
- 项目分类：显示二级分类值
- 技术赛道
- TMG及技术领域
- 子领域
- 项目阶段
- 前置项目
- 项目年份
- 项目价值：独立一行

### 10.2 项目阶段

项目阶段从TDT项目最新已发布计划的一级任务日期自动计算：

- 当前日期位于某一级任务计划开始／完成区间：显示该一级任务名称。
- 首个阶段开始前：`未开始`。
- 全部阶段结束后：`已完成`。
- 日期缺失、阶段间空档或无法唯一判断：`-`。

所有活动子项目继承所属TDT项目阶段。

### 10.3 基础信息与计划Tab

保留现有项目空间主导航。

基础信息页：

- 只显示活动子项目Tab。
- 不显示TDT项目Tab。
- 子项目Tab旁展示配置按钮。
- 可通过“显示已停用”查看已停用子项目。

计划页：

- TDT项目计划固定第一项。
- 活动子项目计划按IPM顺序依次展示。
- 子项目Tab旁展示配置按钮。
- 可查看已停用子项目的历史计划。

### 10.4 IPM子项目模型

采用“父空间管理＋子项目派生列表行”：

- IPM子项目具有稳定子项目ID。
- 子项目隶属于一个TDT项目。
- 子项目在父TDT项目空间内管理自己的基础信息和计划版本。
- 子项目在项目列表形成独立行。
- 子项目没有独立项目空间和独立权限配置。

IPM不再返回已存在子项目时：

- 标记为已停用。
- 保留基础信息、计划版本和历史记录。
- 默认从活动Tab和项目列表隐藏。
- 通过“显示已停用”查看。
- IPM重新返回相同稳定ID时恢复为活动状态。

同步失败时：

- 保留上一次有效数据。
- 不新增、覆盖或停用子项目。
- 重复子项目ID导致本次同步失败并提示冲突。

### 10.5 子项目信息配置

不可删除子项目，仅配置：

- 核心价值：追赶、人无我有、人有我有。必填。
- 开发模式：自研、谷歌合作、SoC合作、高校合作。必填。
- 首导tOS：来自当前两位版本枚举。非必填。
- 首导整机产品：来自全部整机产品项目。非必填。

必填项未完成时：

- 标记为“待配置”。
- 禁止为该子项目创建计划修订。

### 10.6 团队与交付物模块

团队信息模块使用与整机一致的展示形式，显示：

- 技术项目负责人
- 技术项目经理
- 测试代表
- 质量代表
- 产品代表
- 标准化代表
- 权限配置中维护的其他角色

交付物模块显示六类交付物并支持打开链接或查看附件元数据。

## 12. 权限角色

### 12.1 技术项目

固定团队角色：

- 技术项目负责人
- 技术项目经理
- 测试代表
- 质量代表
- 产品代表
- 标准化代表

规则：

- 六个固定角色的成员由项目创建／编辑表单单向同步。
- 权限配置中固定角色成员只读，但可配置权限。
- 其他角色可在权限配置中新增、配置成员和权限。
- 一套TDT项目权限覆盖TDT计划和全部子项目。

### 12.2 tOS版本项目

固定角色按参考图和现有团队schema：

- 版本项目经理
- 规划代表
- SE
- 测试代表
- SQA
- CMO
- UX
- 稳定性代表
- 性能代表
- 功耗代表
- 系统应用开发代表
- 底软通信开发代表
- 集成维护开发代表
- 软件架设与技术规划部开发代表
- 创新产品开发代表
- TEX AI开发代表
- 影像开发代表
- 预装管理开发代表
- 研发战略生态合作部代表

规则：

- 团队信息和权限配置两处都可修改角色成员。
- 最后保存的一处覆盖另一处并同步显示。
- 版本项目经理变化时同步更新项目责任人。

## 13. 状态保存与迁移

- 新模块使用独立、带版本号的本地持久化键。
- 枚举值、技术子项目配置、技术计划版本和用户列表偏好分别存储。
- 历史已删除枚举值保留在业务记录中。
- 技术项目旧计划持久化数据升级时直接重置为新结构。
- 整机、tOS及能力建设项目其他业务数据不重置。
- 项目列表首次进入和筛选状态重置后默认整机产品项目。
- 工作台默认待办中心。

## 14. 异常与保护

- 所有可能丢失草稿的导航继续使用现有编辑保护。
- 创建、编辑、配置、修订、发布按现有RBAC权限控制。
- 老品匹配不到唯一新品时禁止提交并说明原因。
- 版本字符串不合法时禁止保存。
- 子项目必填配置不完整时禁止创建修订。
- IPM同步失败不修改现有子项目状态。
- 文件链接不符合基本URL格式时禁止保存。
- 枚举删除不清空业务字段。
- 已停用子项目只读保留历史，不能新建修订。

## 15. 快速开发与测试

实现批次：

1. 导航拆分、工作台与新版待办中心。
2. 独立项目列表与整机、tOS、技术列表规则。
3. 枚举值配置和tOS路标接入。
4. 整机创建／编辑版本联动和责任人映射。
5. 技术项目创建、编辑、团队和交付物。
6. 技术项目空间、IPM子项目配置和软停用。
7. TDT／子项目模板、计划版本和项目阶段。
8. tOS与技术权限角色同步。
9. 全链路回归。

每个批次必须覆盖：

- 正常、空数据、取消、保存、重新进入和无权限。
- 必填、条件必填、重复、非法版本和已删除枚举历史值。
- 新品、多个老品及最大版本计算。
- IPM子项目新增、修改、停用、恢复、失败和重复ID。
- TDT与多个子项目独立修订、发布和列表刷新。
- 项目列表快捷筛选、高级筛选、列设置、横向滚动和行跳转。
- 待办分类、当前用户过滤和计划／转维跳转。
- 普通与全屏状态下的筛选、列设置和计划操作。

最终门禁：

- 所有专项契约脚本。
- `npx tsc --noEmit`
- `npm run build`
- `git diff --check`
- 浏览器逐项验收本规格全部用户路径。

发现失败必须在当前批次修复并重新运行相关门禁，不留到最终交付。
