# 项目列表全屏展示设计

## 目标

为项目列表的“列表视图”和“日历视图”增加页面内全屏展示能力，让用户在不受主导航、分类和快捷筛选区域占用的情况下查看宽表或日历。卡片视图保持现状。

## 交互

- 当当前视图为列表或日历时，在内容区域右上方显示带文字的“全屏”按钮；卡片视图不显示。
- 点击“全屏”后打开覆盖整个浏览器视口的页面级覆盖层，不调用浏览器原生 Fullscreen API。
- 覆盖层顶部显示当前视图名称和“退出全屏”按钮，主体复用当前列表或日历内容。
- 用户可点击“退出全屏”或按 `Esc` 退出。
- 进入、退出全屏不修改项目分类、二级分类、项目状态、快捷筛选、高级筛选或“关于我的”状态。
- 全屏期间禁止页面底层滚动；退出后恢复原有滚动能力。

## 组件边界

- `ProjectListContainer` 持有 `isFullscreen` 状态，并决定普通内容与全屏覆盖层的挂载位置。
- 抽取当前列表/日历内容为单一渲染函数，普通模式和全屏模式共享同一数据、筛选条件和打开项目回调，避免两套逻辑漂移。
- 全屏工具条只承担标题和退出操作，不复制项目分类及快捷筛选工具条。
- 样式集中放在 `globals.css`，使用固定定位、白色背景和清晰阴影，层级高于主 Header 与普通浮层。

## 可访问性与体验

- 按钮使用 `FullscreenOutlined` / `FullscreenExitOutlined`，同时保留可见文字与明确 `aria-label`。
- 覆盖层使用可识别的全屏区域语义，退出按钮保持键盘可聚焦。
- `Esc` 监听仅在全屏开启时注册并在退出或卸载时清理。
- 进入与退出采用短时透明度过渡，并尊重现有系统视觉风格。

## 验证

- 新增源码契约：列表、日历显示全屏入口；卡片不显示；存在退出按钮与 `Esc` 处理；内容复用而非复制数据逻辑。
- 运行项目列表现有契约，确保筛选、固定列和日历逻辑不回归。
- 运行 `npx tsc --noEmit` 与 `npm run build`。
- 浏览器验证列表和日历进入/退出全屏、`Esc`、筛选状态保留及控制台错误。

## 非目标

- 不为卡片视图增加全屏。
- 不使用浏览器原生 Fullscreen API。
- 不修改项目列表的数据、筛选规则、列配置或项目打开行为。
