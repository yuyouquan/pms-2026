# 三级计划-MR版本计划设计

**状态：** 已确认

**日期：** 2026-08-29

**适用项目：** tOS版本项目、整机产品项目

## 1. 背景与目标

现有“三级计划”围绕通用两级活动、责任人、状态、风险、市场/类型跟随和活动历史建设，已经不适合新的 MR 版本计划业务。本期完全删除旧三级计划及其配置、项目数据、本地持久化数据和历史记录，不做数据迁移。

新建独立的“三级计划-MR版本计划”领域，贯通四个业务入口：

1. 配置中心的 tOS版本项目 MR 计划模板；
2. tOS 版本项目空间的 MR 版本计划；
3. 主页 Header 新增的联合项目空间；
4. 整机产品项目空间的主市场同步与非主市场计划。

系统使用统一的数据模型和规则引擎，避免在四个页面间复制同一份事实数据：

```text
配置中心已发布模板
        │ 新增 tOS 版本号时复制快照
        ▼
tOS 项目 MR 版本计划
        │ 联合空间只读引用 tOS 行
        ▼
联合项目空间：整机 1+N 与主市场日期
        │ 整机主市场只读实时引用
        ▼
整机项目 MR 版本计划：非主市场日期覆盖
```

## 2. 已确认的关键口径

| 主题 | 口径 |
|---|---|
| 旧三级计划 | 功能、Mock、本地持久化数据和历史记录全部删除，不迁移 |
| 模板结构 | 最多两级活动；可新增、删除和同级排序；活动名称可修改 |
| 模板名称 | 整个模板内活动名称必须唯一 |
| 规则识别 | 直接按当前活动名称识别特殊节点，不保留隐藏业务标识 |
| 模板同步 | 已创建的 tOS 版本保留初始化快照；模板新版本只影响之后新增的 tOS 版本 |
| 一级计划来源 | 只读取最新已发布一级计划，不读取修订中版本 |
| 版本区间 | 取 tOS MR 版本全部非空二级活动日期的最早值至最晚值 |
| STR5 门槛 | 系统当天日期晚于整机项目最新已发布一级计划中 STR5 的计划完成时间 |
| 自动插入 | `STR5 + 1天` 落入哪个版本区间，就从该 tOS 版本起向后插入整机项目 |
| 动态重算 | 来源日期变化后重新计算；不再符合条件的整机行和日期删除 |
| 错误日期 | 允许保存，单元格标红并显示错误图标和悬浮说明 |
| 停止发版 | 符合截止条件的未来行和已填日期永久删除；仅保留记录，不支持恢复 |
| N/A | 立即清空全部活动日期并显示“/”；改回数字后重新填写 |
| 默认视图 | tOS 和整机项目空间首次进入默认竖版，并记住用户上次选择 |
| 组包方式 | 保留列，统一显示“/”，本期不可编辑 |

## 3. 导航和页面入口

### 3.1 主页 Header

在“项目列表”右侧新增“联合项目空间”：

```text
工作台｜项目列表｜联合项目空间｜tOS路标｜人力资源管道｜配置中心
```

- 所有登录用户均可进入并查看；
- Header 切换继续经过现有编辑离开保护；
- 本期联合项目空间仅提供一个 Tab：“tOS&整机MR版本计划”；
- Tab 切换样式和页面布局复用 tOS 路标的表单视图/版本演进视图样式。

### 3.2 配置中心

只有“tOS版本项目”的计划配置显示：

- 一级计划；
- 三级计划-MR版本计划。

整机产品、能力建设和技术项目不显示该模板入口。

### 3.3 tOS 版本项目空间

项目空间 → 计划显示：

- 一级计划；
- 三级计划-MR版本计划。

MR 计划提供“新增tOS版本号”、竖版/横版切换，不显示市场切换。

### 3.4 整机产品项目空间

项目空间 → 计划的第一层切换改为：

- 一级计划；
- 三级计划-MR版本计划。

第一层计划 Tab 与原市场 Tab 交换位置：

- 一级计划选中时，第二层显示市场 Tab；
- MR 版本计划选中时，不显示市场 Tab，页面同时展示全部市场；
- “市场编辑”按钮是两个计划 Tab 共用操作，固定在第一层 Tab 最右侧。

## 4. 领域数据模型

### 4.1 模板版本

`MrTemplateVersion` 保存：

- 版本 ID、版本号、状态（修订中/已发布）；
- 创建人、创建时间、发布时间；
- 两级活动快照；
- 修订历史。

`MrTemplateActivity` 保存：

- 稳定 ID；
- 父活动 ID；
- 层级（一级/二级）；
- 同级排序值；
- 活动名称。

tOS 版本号和日期不是模板输入字段，模板表格中始终显示“-”。活动名称的业务规则完全依赖当前显示文本；改名后，旧名称的特殊规则不再生效。

### 4.2 tOS 项目版本实例

以 `tOS项目ID + tOS版本号` 唯一标识一个实例，保存：

- tOS 版本号；
- 来源模板版本 ID；
- 创建时复制的活动快照；
- 二级活动日期；
- 创建人、创建时间、最后修改信息。

一级活动日期不聚合，竖版始终显示“/”。横版只为二级活动生成日期列。

### 4.3 联合空间整机记录

以 `整机项目ID + tOS版本号` 唯一标识，保存：

- 1+N 转测类型；
- 各二级活动日期；
- 最后修改人和时间。

以下内容不重复保存，展示时动态计算：

- tOS 只读参考行；
- tOS 版本区间；
- 整机项目是否有资格进入某个版本；
- 项目名称、市场名、产品线、SOC平台、SPM、是否MADA；
- 组包方式“/”；
- 日期错误列表。

### 4.4 停止发版记录

保存：

- 记录 ID；
- 整机项目 ID 和项目名称；
- 停止发版日期；
- 操作人；
- 操作时间。

停止记录同时作为动态聚合的排除条件，防止被删除的未来版本行在下一次计算时重新出现。

### 4.5 非主市场日期

以 `整机项目ID + tOS版本号 + 市场` 唯一标识，只保存非主市场二级活动日期。

- 主市场日期不复制，实时读取联合空间整机记录；
- 非主市场读取自己的覆盖值；
- 市场新增后自动出现同版本空白行；
- 市场删除后不再展示对应覆盖数据。

表头固定为：

1. tOS版本号；
2. 活动序号；
3. 活动名称；
4. 日期。

显示规则：

- tOS版本号：“-”；
- 日期：“-”；
- 活动序号根据当前层级和同级顺序实时生成；
- 只有活动名称可以编辑。

### 5.3 版本和修订

交互、版本选择、修订、保存、发布、取消修订和历史记录沿用一级计划模板样式：

- 已发布版本只读；
- 修订中可新增一级活动、在一级活动下新增二级活动；
- 支持一级活动同级排序、二级活动在同一父活动内排序；
- 支持删除任意一级或二级活动；删除一级活动同时删除其子活动；
- 发布前校验整个模板活动名称唯一；
- 模板为空、存在重复名称或层级超过两级时禁止发布。

## 6. tOS 项目空间 MR 版本计划

### 6.1 新增 tOS 版本号

候选值来源：当前 tOS 项目最新已发布一级计划中“上市迭代阶段”和“维护阶段”的二级 tOS 版本节点。

规则：

- 已添加的 tOS 版本号不可再次选择；
- 候选节点缺少计划开始时间或计划完成时间时仍显示，但禁用选择，并提示“请先完善一级计划中的计划开始时间和计划完成时间”；
- 没有已发布 MR 模板时禁用新增，并提示先在配置中心发布模板；
- 新增成功后复制配置中心最新已发布模板快照；
- 系统按版本号各数字段升序排列，例如 `16.3.0.110 < 16.3.0.115 < 16.3.0.140`；
- 已创建实例不随模板后续发布自动同步。

### 6.2 日期编辑

- 一级活动日期显示“/”，不可编辑；
- 所有二级活动日期可以在竖版和横版直接更新；
- “修改点收集开始时间”不得早于该 tOS 版本在一级计划中的计划开始时间；
- “OTA开放验证&部署”不得晚于该 tOS 版本在一级计划中的计划完成时间；
- 名称被修改后不再命中上述特殊规则；
- 不合规日期允许保存，但立即标红并显示原因。

### 6.3 权限

- 当前 tOS 版本项目经理可以新增版本号和修改二级活动日期；
- 系统超级管理员拥有相同权限；
- 其他用户只读。

### 6.4 视图

竖版字段：

- tOS版本号；
- 活动序号；
- 活动名称；
- 日期。

横版：

- 左侧固定 tOS版本号；
- 一级活动作为分组表头；
- 二级活动作为日期列；
- 每个 tOS 版本号一行。

首次进入默认竖版；之后按用户记忆上次视图。

## 7. 联合项目空间

### 7.1 页面结构

唯一 Tab：“tOS&整机MR版本计划”。

顶部左侧筛选器：

- tOS版本号；
- 项目名称；
- 1+N版本类型。

顶部右侧操作：

- 停止发版；
- 停止发版记录。

表格固定信息列：

1. tOS版本号；
2. 项目名称；
3. 市场名；
4. 产品线；
5. SPM；
6. 是否MADA；
7. SOC平台；
8. 组包方式；
9. 1+N转测类型。

之后按照模板一级活动生成分组表头，二级活动生成日期列。系统自动按照 tOS 版本号数字升序排列；同一版本下先显示 tOS 只读参考行，再显示整机项目行。

### 7.2 tOS 只读参考行

- 实时读取对应 tOS 版本项目的 MR 计划；
- 不能在联合空间编辑；
- 项目名称显示对应 tOS 项目；
- 1+N转测类型固定显示 `1`；
- 市场名、产品线、SPM、是否MADA、SOC平台、组包方式统一显示“/”；
- 日期读取 tOS 项目对应二级活动。

### 7.3 整机项目关联规则

1. 产品类型为“新品”时读取首销 tOS 版本；产品类型为“老品”时读取当前 tOS 版本；历史“升级/切换/换代”先按现有迁移规则归一为“老品”。
2. 取版本号前两段数字匹配 tOS 版本项目，例如 `16.3.0.145` 匹配 `tOS16.3`。
3. 读取整机项目最新已发布一级计划中的 STR5 计划完成时间。
4. 只有系统当天日期晚于 STR5 计划完成时间时继续计算。
5. 每个 tOS MR 版本区间等于该版本全部非空二级活动日期的最早值至最晚值；没有任何日期时不形成区间。
6. `STR5 + 1天` 落入哪个版本区间，就从该版本及其之后的所有 tOS 版本插入整机项目。
7. 来源日期、STR5 或项目基础信息变化后动态重算；不再满足条件的行及其日期删除。
8. 仍满足条件但日期违反新边界的行保留，错误单元格标红。

整机信息自动读取：

- 项目名称；
- 主市场名称；
- 产品线；
- SOC平台；
- SPM；
- 是否MADA：任意一个市场为 MADA 则显示“是”，全部为否则显示“否”；
- 组包方式：“/”。

新插入整机行的 1+N 转测类型默认 `1`，日期为空。

### 7.4 1+N 转测类型

枚举固定为：

```text
N/A、1、2、3、4、5、6、7、8
```

切换为 `N/A`：

- 永久清空当前项目当前版本的全部日期；
- 日期列显示“/”；
- 再切换回数字类型时不恢复旧日期。

### 7.5 停止发版

停止发版 Modal 字段：

- 停止发版项目名称：只显示当前表中存在且尚未停止的整机项目；
- 停止发版日期。

停止发版依赖名称精确为“修改点收集开始时间”的二级活动。系统按每个 tOS 版本自己的模板快照查找该节点；某个版本不存在该名称时，该版本不能判断为“晚于停止日期”，不会被删除。当前全部候选版本都不存在该名称时，停止发版按钮禁用，并提示“当前MR版本计划缺少修改点收集开始时间，无法判断停止范围”。

提交后：

- 以 tOS 参考行的“修改点收集开始时间”作为版本判断日期；
- 该日期晚于停止日期的版本，不再带出此整机项目；
- 已存在的对应整机行及其日期永久删除；
- 日期为空时不满足“晚于”条件，暂不删除；后续补齐为晚于停止日期时，由动态重算删除；
- 停止记录持续阻止未来版本重新插入；
- 不提供恢复功能。

“停止发版记录”Modal 显示：操作人、操作时间、操作项目、停止发版日期。

权限：

- 系统超级管理员可以停止任何整机项目；
- 整机项目 SPM 只能停止自己负责的项目；
- 其他用户不能停止发版。

### 7.6 项目跳转

整机项目名称显示为可点击链接。点击后：

- 打开对应项目空间；
- 左侧定位“计划”；
- 第一层定位“三级计划-MR版本计划”；
- 保留当前 tOS 版本作为初始定位条件，方便编辑非主市场。

导航继续经过现有编辑离开保护。

## 8. 联合空间日期规则

### 8.1 通用交互

- 日期直接在单元格中编辑；
- 不合规日期仍保存；
- 单元格使用红色边框/背景；
- 行右侧显示错误图标；
- 悬浮图标显示当前行全部具体错误；
- 横版、竖版和项目回填共用同一校验结果。

空日期不主动报错，允许用户分步填写；只有已填写值与边界冲突时标红。

### 8.2 修改点时间

同一 tOS 版本下，整机项目的：

- 修改点收集开始时间；
- 修改点锁定时间；

必须与 tOS 参考行对应时间一致。

### 8.3 MP 入库截止时间

整机项目的 MP入库截止时间不得晚于 tOS 参考行时间，可以相同。

提示词：

> 整机产品项目的MP入库截止时间不得晚于tOS项目时间

### 8.4 版本转测时间

同一 tOS 版本号下：

- 同一 1+N 数字类型的所有整机项目版本转测时间必须一致；编辑一个项目不会自动修改其他项目，不一致时分别标红；
- 类型 `1` 的版本转测时间必须等于 tOS 版本转测时间；
- 类型大于 `1` 时，与小于当前类型的最大已存在类型比较，至少晚 7 个自然日；
- 类型大于 `1` 时，不得晚于下一个 tOS 版本的测试开始时间；
- 最后一个 tOS 版本没有下一版本上限。

提示词：

- 类型 1：`版本转测时间应等于tOS版本转测时间`；
- 类型大于 1：`版本转测时间需晚于上一个1+N转测类型至少1周`；
- 同类型不一致：`同一1+N转测类型的版本转测时间需保持一致`。

### 8.5 测试、评审和发布节点

适用名称：

- 测试开始时间；
- 测试完成时间；
- 评审时间；
- 软件归档时间；
- OTA开放验证&部署。

类型 `1`：

- 每个字段不得早于同一 tOS 版本对应的 tOS 项目时间，可以相同；
- 不得晚于下一个 tOS 版本的测试开始时间；
- 最后一个 tOS 版本不执行下一版本上限校验。

类型大于 `1`：

- 与小于当前类型的最大已存在类型的对应字段比较，至少晚 7 个自然日；
- 不得晚于下一个 tOS 版本的对应字段；
- 最后一个 tOS 版本不执行下一版本上限校验。

提示词按具体字段替换：

- 类型 1：`{字段名称}不早于tOS项目时间，可与tOS项目保持一致，且不能超过下一个tOS版本的测试开始时间`；
- 类型大于 1：`{字段名称}需晚于上一个1+N转测类型至少1周，且不能超过下一个tOS版本的{字段名称}`。

## 9. 整机项目空间 MR 版本计划

### 9.1 数据生成

当联合空间中某个整机项目、某个 tOS 版本的任一活动日期首次出现非空值时，对应整机项目 MR 计划自动出现该版本。

- 只有 1+N 类型、没有任何日期时不生成项目空间版本；
- `N/A` 不视为日期；
- 联合空间动态删除整机行后，项目空间对应版本和非主市场日期一并删除。

### 9.2 主市场

- 主市场每个活动日期实时读取联合空间；
- 在整机项目空间中只读；
- 联合空间更新后无需复制或刷新版本即可显示最新值。

### 9.3 非主市场

- 由该整机项目 SPM 或系统超级管理员填写；
- 每个活动日期不得晚于主市场对应日期；
- 主市场对应日期为空时，非主市场该日期禁止填写，并提示“主市场对应时间未填写，当前市场不可填写”；
- 已有非主市场日期在主市场改早后变为不合规时，保留值并标红。

### 9.4 竖版

固定列：

- tOS版本号；
- 活动序号；
- 活动名称。

之后每个市场一列；一级活动各市场显示“/”，二级活动显示日期。主市场列只读，非主市场按权限编辑。

### 9.5 横版

固定列：

- tOS版本号；
- 市场项目。

之后按照一级活动分组、二级活动展开日期列。每个 tOS 版本按市场逐行显示，主市场行只读。

首次进入默认竖版，之后记住当前用户上次选择。

## 12. 错误、空状态和降级

- 没有已发布模板：禁用新增 tOS 版本号，提示先发布模板；
- 一级计划版本节点缺少起止日期：候选项显示但禁用；
- tOS MR 版本没有任何二级日期：不形成版本区间，不聚合整机项目；
- 模板活动名称重复：保存时提示具体重复名称，发布被阻止；
- 动态来源变化：不合资格数据删除，仍合资格但错误的数据保留并标红；
- 未命中特殊活动名称：作为普通日期节点展示，不执行名称专属规则；
- 模板改名或删除“修改点收集开始时间”后：已有停止记录继续对仍保留该名称的版本快照生效；全部候选版本都缺少该名称时，新的停止发版操作禁用；
- 本期继续使用前端 Mock 和 Zustand/localStorage，不新增数据库、接口或 Feishu 通知。
