# 系统全局列设置拖拽排序设计

## 1. 背景与目标

当前系统存在多套“列设置 / 自定义列”实现。它们可以控制字段显示，但交互、保存时机和列顺序处理不一致，部分入口完全不支持排序。

本次改造的目标是：

1. 所有当前可访问的列设置入口统一支持拖拽排序。
2. 拖拽后的顺序真实控制表格或卡片字段的展示顺序。
3. 固定左侧列维持稳定的左侧边界，其他列不能越过该边界。
4. 不可取消但未固定左侧的列仍可参与排序。
5. 所有入口统一采用草稿编辑语义：确定保存、取消放弃、重置恢复默认。

本次不改变字段定义、字段权限、列宽、表格数据或业务筛选规则。

## 2. 覆盖范围

改造覆盖当前代码中所有面向用户的列设置入口：

- 项目路标表单视图和版本演进视图
- 项目计划竖版表格和甘特图字段
- 配置中心计划模板
- 需求开发计划
- 版本火车计划
- 项目计划汇总看板
- 分享计划页

历史但仍可被当前页面挂载的列设置实现也需要接入共享能力，避免同一系统中继续保留不可排序的入口。

横版计划中原本不支持自定义列的视图不新增列设置入口。

## 3. 统一交互

采用“单列表排序”：

- 每个字段占一行。
- 行内依次展示拖拽手柄、显示复选框、字段名称和状态说明。
- 显示列与隐藏列共用一个顺序数组。
- 勾选仅控制是否显示，不改变字段所在位置。
- 拖动改变字段在顺序数组中的位置。
- 隐藏字段重新勾选后，按照它在顺序数组中的既有位置出现。

弹窗或抽屉打开时复制当前配置为草稿：

- 拖动和勾选只更新草稿。
- 点击“确定 / 应用”后写回对应页面状态。
- 点击“取消”或关闭面板时放弃草稿。
- 点击“重置”后将草稿恢复为当前视图的默认列集合与默认顺序；仍需点击“确定 / 应用”才保存。

## 4. 固定列与拖拽边界

列定义区分三个属性：

- `hideable`：是否允许取消显示。
- `fixed: 'left'`：是否固定在表格左侧。
- `locked`：兼容现有路标列定义，表示不可取消；它不等同于固定左侧。

拖拽规则：

1. 固定左侧列不可拖动。
2. 固定左侧列按照列定义中的默认顺序组成列表前缀。
3. 非固定列不能拖到固定左侧列之前。
4. 不可取消但未固定左侧的列可以拖动。
5. 至少保留一个业务字段等现有显示约束继续生效。

当页面没有固定左侧列时，所有可排序字段可以在列表范围内自由拖动。

## 5. 共享组件

新增共享组件 `SortableColumnSettings`，负责：

- 渲染统一的单列表列设置界面。
- 管理草稿顺序和草稿显示状态。
- 使用现有 `@dnd-kit` 依赖提供鼠标、触控和键盘拖拽。
- 执行固定左侧边界校验。
- 执行最少显示字段校验。
- 提供重置、取消和应用事件。

建议的核心接口：

```ts
interface SortableColumnDefinition {
  key: string
  title: React.ReactNode
  defaultVisible: boolean
  hideable?: boolean
  fixed?: 'left'
  disabledReason?: string
}

interface SortableColumnSettingsValue {
  order: string[]
  visible: string[]
}
```

业务页面负责：

- 将自己的字段定义适配为共享列定义。
- 提供当前视图的 `order` 与 `visible`。
- 在应用时写回原有 Zustand 状态或页面本地状态。
- 按已保存顺序生成表格列或卡片字段。

共享组件不直接读取任何业务 store。

## 6. 数据与渲染规则

所有页面的列状态统一解释为：

- `order`：包含可配置字段的完整顺序，包括隐藏字段。
- `visible`：当前显示字段的 key 集合。

表格列生成必须遵循：

1. 先按 `order` 对字段定义排序。
2. 再按 `visible` 过滤。
3. 最后附加不属于列设置范围的系统操作列。

操作列、选择框列和展开控制列不进入用户拖拽列表，继续由页面固定在原有位置。

对目前只有 `visibleColumns: string[]` 的页面，迁移后允许将完整顺序写入同一个数组；隐藏状态需要单独保存时，使用对应页面现有状态结构扩展，不跨页面共享。

## 7. 历史配置迁移

读取历史配置时统一规范化：

1. 删除重复 key。
2. 删除已不存在的字段。
3. 按默认字段顺序补回新增字段。
4. 将固定左侧字段恢复到最前面，并保持其默认相对顺序。
5. 保留非固定字段的历史相对顺序。
6. 保留历史显示状态；若历史配置无独立顺序，则以原数组顺序为初始顺序。

规范化后为空时回退到当前视图默认配置。

## 8. 可访问性与反馈

- 每个可拖动字段提供明确拖拽手柄。
- 手柄使用 `aria-label="拖动{字段名}调整顺序"`。
- 固定左侧字段不提供可操作拖拽属性，并显示“固定左侧”说明。
- 不可取消字段的复选框禁用，并显示不可取消原因。
- 键盘用户可通过 dnd-kit 的 Keyboard Sensor 调整顺序。
- 非法越界拖拽不改变草稿顺序。
- 应用成功沿用各页面现有成功提示。

## 9. 验收标准

### 功能

- 每个覆盖范围内的列设置入口均显示统一拖拽列表。
- 拖动后点击确定，目标视图的列顺序同步变化。
- 隐藏列重新显示后回到已安排的位置。
- 取消不保存任何勾选或排序改动。
- 重置恢复该视图默认显示字段和默认顺序。
- 不可取消但未固定左侧的列可以拖动。
- 固定左侧列不能拖动，其他列不能拖到其前面。
- 原有最少显示字段、锁定字段和独立视图配置规则不回退。

### 兼容

- 历史列配置能正常加载并被规范化。
- 新增字段可自动补入列设置。
- 表格操作列、选择列和展开列位置不受影响。
- 原本具有持久化能力的页面刷新后继续保留顺序。

### 验证

- 为共享规范化函数、固定边界和拖拽结果增加自动化覆盖。
- 为每个列设置入口增加源码或组件级接入断言。
- 路标专项校验通过。
- `npx tsc --noEmit` 通过。
- `npm run build` 或 Node 入口的 Next.js 生产构建通过。

## 10. 非目标

- 不新增列宽拖拽。
- 不新增跨页面同步列设置。
- 不改变服务端数据结构或权限模型。
- 不将操作列纳入用户排序。
- 不为原本没有列设置能力的横版计划新增列设置。
