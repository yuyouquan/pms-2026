# 配置中心三级计划模板与新维度初始化设计

## 1. 背景与目标

配置中心目前仅为整机产品项目、tOS 版本项目展示一级计划模板；项目空间三级计划仍以范围内活动数据或演示数据为来源。与此同时，配置中心计划模板顶部卡片在可用高度不足时会被纵向压缩，导致计划类型 Tab 被底部边界裁切。

本次交付目标：

1. 整机产品项目、tOS 版本项目在配置中心增加“三级计划”模板配置。
2. 三级计划模板复用一级计划的版本、修订、发布、取消修订、版本对比和结构维护交互。
3. 模板表头与项目空间三级计划一致，活动结构最多两级。
4. 模板只允许修改活动名称和关键节点，其他字段只读并显示“-”。
5. 关键节点选项来自同项目类型最新已发布一级计划模板的二级活动。
6. 整机产品项目新增市场、tOS 版本项目新增版本类型时，从当时最新已发布的对应三级计划模板初始化一次。
7. 修复配置中心计划模板 Tab 裁切和内容重叠问题。
8. 项目空间三级计划在修订和查看状态下均支持表格视图与甘特图视图切换。
9. 完成 dev、主干和 Vercel 发布，并将详细需求、字段、交互和功能截图写入指定飞书 PRD。

## 2. 范围

### 2.1 本期范围

- 配置中心项目分类：整机产品项目、tOS 版本项目。
- 配置中心三级计划模板的表格、版本生命周期、结构维护和关键节点选择。
- 整机产品项目新增市场时的三级计划初始化。
- tOS 版本项目新增版本类型时的三级计划初始化。
- 项目空间三级计划表格/甘特图双视图。
- 配置中心计划模板卡片与 Tab 的布局修复。
- 自动验证、浏览器验证、发布和 PRD 更新。

### 2.2 不变范围

- 能力建设项目仍只显示一级计划模板。
- 技术项目仍显示 TDT 项目计划和子项目计划，不增加三级计划模板。
- 项目空间三级计划的权限、跟随、脱离、拖动、筛选、导出和历史逻辑保持不变；甘特图仅作可视化查看，日期维护仍通过有权限的表格单元格完成。
- 已有市场、已有版本类型和已有三级计划活动不回填、不覆盖。
- 跟随市场或跟随类型仍以主市场或主类型作为展示来源；为新维度创建的独立初始化数据不会改变跟随展示逻辑，脱离时仍按既有规则物化主范围数据和覆盖记录。

## 3. 方案选择

采用“复用一级计划版本框架 + 三级计划专用模板模型”的方案。

- 复用配置中心现有版本选择、创建修订、自动保存、发布、取消修订和版本对比入口，避免出现两套交互。
- 使用独立的三级计划模板活动类型，只保存结构字段和关键节点引用，避免把责任人、日期、状态、风险等项目执行数据误存为模板配置。
- 三级计划项目实例仍写入现有 `level3Plan` Store，通过纯函数把模板活动物化为项目活动。

不采用以下方案：

- 独立实现一套三级计划版本系统：会复制一级计划生命周期并增加行为偏差风险。
- 固定模板、无版本生命周期：不符合“交互和一级计划保持一致”。

## 4. 信息架构与入口

配置中心“计划模板配置”中，各项目类型的计划 Tab 为：

| 项目类型 | 计划 Tab |
| --- | --- |
| 整机产品项目 | 一级计划、三级计划 |
| tOS 版本项目 | 一级计划、三级计划 |
| 能力建设项目 | 一级计划 |
| 技术项目 | TDT 项目计划、子项目计划 |

切换项目类型时：

- 整机产品、tOS、能力建设默认进入一级计划。
- 技术项目默认进入 TDT 项目计划。
- 若当前处于修订编辑态，继续使用现有离开编辑保护逻辑。

## 5. 三级计划模板数据模型

新增三级计划模板活动结构：

| 字段 | 说明 |
| --- | --- |
| `id` | 稳定活动 ID，不使用显示序号作为业务主键 |
| `parentId` | 父活动 ID；一级活动为空，二级活动指向一级活动 |
| `order` | 同级顺序 |
| `activityName` | 活动名称，可编辑 |
| `milestoneId` | 所选一级计划二级活动的稳定 ID，可编辑 |
| `milestoneName` | 所选关键节点名称，随选择同步保存 |
| `source` | `template` 或 `custom`，用于版本同步和删除规则 |

模板按项目类型隔离：

- `整机产品项目::level3`
- `tOS版本项目::level3`

版本和对比沿用配置中心现有版本 Scope；已发布快照使用三级计划专用快照键，避免与一级计划快照冲突。

持久化迁移只补充三级计划模板默认状态，不改写既有一级计划模板、项目三级计划和用户自定义数据。

## 6. 表格字段与编辑规则

表头顺序必须与项目空间三级计划保持一致：

| 顺序 | 字段 | 模板展示 | 修订中可编辑 |
| --- | --- | --- | --- |
| 1 | 序号 | 系统按结构生成 | 否 |
| 2 | 活动名称 | 模板值 | 是 |
| 3 | 责任人 | `-` | 否 |
| 4 | 责任部门 | `-` | 否 |
| 5 | 计划开始时间 | `-` | 否 |
| 6 | 计划结束时间 | `-` | 否 |
| 7 | 预估工期 | `-` | 否 |
| 8 | 关键节点 | 模板值或 `-` | 是 |
| 9 | 实际开始时间 | `-` | 否 |
| 10 | 实际完成时间 | `-` | 否 |
| 11 | 实际工期 | `-` | 否 |
| 12 | 状态 | `-` | 否 |
| 13 | 任务风险 | `-` | 否 |
| 14 | 备注 | `-` | 否 |
| 15 | 创建者 | `-` | 否 |

已发布版本全部只读。修订中仅“活动名称”和“关键节点”显示输入控件；其他列无论数据状态都显示“-”，不展示可编辑控件。

## 7. 关键节点来源

关键节点下拉按当前项目类型读取配置中心一级计划模板：

1. 找到该项目类型最新已发布的一级计划模板版本。
2. 读取该版本快照。
3. 只保留存在 `parentId` 的二级活动。
4. 以稳定任务 ID 作为选项值，以任务名称作为显示值。
5. 去除空名称和重复 ID，保持模板结构顺序。

没有已发布一级计划模板或没有二级活动时，下拉为空并提示“请先发布包含二级活动的一级计划模板”，不允许保存无效关键节点引用。

一级计划模板后续改名或删除节点时，已发布三级计划模板快照保留原名称；创建新的三级计划修订时才重新校验当前可选节点。

## 8. 结构维护与版本交互

三级计划模板与一级计划保持以下交互一致：

- 版本选择。
- 创建正式或非正式修订。
- 修订中自动保存。
- 发布和取消修订。
- 历史版本对比。
- 搜索、全部展开、全部收起。
- 新增一级活动、新增二级活动、删除活动。
- 只允许同级拖动；一级活动拖动携带其二级活动。
- 拖动或增删后重新生成 `1`、`1.1`、`1.2`、`2` 等显示序号。

层级限制：

- 一级活动允许新增二级活动。
- 二级活动不显示新增子活动入口。
- 任一操作都不能生成第三级活动。

发布前校验：

- 活动名称不能为空或全为空格。
- `parentId` 必须指向存在的一级活动。
- 同级顺序必须可规范化。
- 关键节点必须存在于当前有效的一级计划二级活动选项中；空关键节点允许保存为 `-`。

## 9. 项目空间初始化

### 9.1 模板选择

初始化时读取当前项目类型最新已发布三级计划模板快照。初始化只发生在维度新增保存成功的那一刻；模板后续发布新版本不会自动更新已初始化项目数据。

### 9.2 整机产品项目

保存市场配置时比较保存前后的市场集合，对每个新增市场生成范围键：

`project::<projectId>::market::<market>::level3`

每个新增市场调用一次幂等初始化。无论新市场是否设置“跟随主市场”，都记录该市场自己的初始化数据；跟随状态下页面仍读取主市场，脱离时继续按现有跟随物化规则处理。

### 9.3 tOS 版本项目

保存版本类型配置时比较保存前后的类型集合，对每个新增类型生成范围键：

`project::<projectId>::tosType::<type>::level3`

每个新增类型调用一次幂等初始化。跟随主类型时展示来源仍是主类型。

### 9.4 物化规则

模板活动转换为项目空间 `Level3Activity`：

- 保留活动稳定 ID、层级、顺序、活动名称和关键节点引用。
- 责任人、责任部门、计划日期、实际日期和备注为空。
- 状态默认“待启动”。
- 任务风险默认“无”。
- 创建者、更新人为“系统管理员”，时间使用初始化时刻。
- 关键节点计划完成时间从项目空间当前最新已发布一级计划对应节点中解析；无法解析时为空，后续编辑二级活动时按现有校验处理。

幂等条件使用范围键是否已存在，而不是活动数量：即使模板为空并初始化出空数组，重复保存也不得再次填充或覆盖。

### 9.5 异常处理

- 没有已发布三级计划模板时，不阻止市场或类型配置保存；显示明确警告，范围保持未初始化，且后续保存或进入页面时不自动回填，避免在创建时点之后静默套用其他模板版本。
- 模板结构或快照无效时，不写入项目活动并显示初始化失败原因。
- 某一新增维度初始化失败不回滚已成功保存的基础信息，但必须逐项提示失败维度，便于用户处理。
- 已有范围存在活动、空数组或历史记录时均视为已处理，不覆盖。

## 10. 配置中心 Tab 布局修复

问题原因：计划模板内容容器为固定视口高度的纵向 Flex 布局，顶部标题/Tab 卡片和工具栏允许 `flex-shrink`，可用高度不足时卡片被压缩；卡片同时设置 `overflow: hidden`，因此 Tab 导航被底部裁切。

修复方案：

- 为标题/Tab 卡片、版本工具栏、可选工具栏增加明确类名并设置 `flex: 0 0 auto`。
- Tab 导航区域设置稳定最小高度，确保标签文字和激活线完整显示。
- 表格卡片设置 `flex: 1 1 auto; min-height: 0`，只让表格内容区滚动。
- 不使用扩大整个页面高度的方式掩盖问题。
- 验证展开/收起左侧项目分类、不同视口高度、整机/tOS/技术项目 Tab 数量变化时均不裁切、不重叠。

## 11. 项目空间三级计划双视图

- 在三级计划工具栏右侧增加与一级计划一致的视图切换入口，仅提供“表格”和“甘特图”；横版视图不可用。
- 默认进入表格视图，用户可在查看已发布计划或维护可修订计划时随时切换甘特图。
- 甘特图按一级/二级活动层级展示；一级活动使用二级活动聚合后的计划开始、计划完成、实际开始和实际完成时间，二级活动使用自身时间。
- 甘特图左侧固定展示活动名称、计划开始、计划完成、实际开始和实际完成；时间轴以计划开始和计划完成绘制。
- 无完整计划时间的活动仍保留在左侧树中，不伪造日期或工期。
- 甘特图是只读视图，不通过拖动甘特条修改日期；切回表格后继续按现有权限直接维护实际日期、状态和任务风险。
- 表格的筛选结果、展开/收起状态同步影响甘特图展示，避免两个视图的活动范围不一致。

## 14. 验收标准

- 整机产品和 tOS 版本配置中心均能进入三级计划模板，其他项目类型入口保持正确。

- 关键节点下拉准确来自对应项目类型最新已发布一级计划模板的二级活动。
- 模板活动不超过两级，结构维护和版本交互与一级计划一致。

- 专项验证、现有相关验证、类型检查和生产构建全部通过。
- dev、主干和 Vercel 发布均有当前证据。
- 飞书 PRD 已包含详细字段、交互、截图并完成回读检查。
