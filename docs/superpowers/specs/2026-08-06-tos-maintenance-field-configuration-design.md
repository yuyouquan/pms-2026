# tOS 版本维护恢复与字段配置统一设计

## 背景

当前 `tOS 路标` 的“tOS 版本维护”按钮直接跳转到配置中心枚举页，丢失了原有的路标内版本列表、新建、编辑、周期和技术点维护能力。与此同时，项目列表的全屏入口没有与字段配置形成稳定的工具组；系统内仍混用“列设置”与“字段配置”两套用户文案。

本次改动恢复路标内维护闭环，并将版本号输入改为配置驱动，同时只统一用户可见文案，不调整内部 `columnSettings` 数据结构、持久化键或列排序算法。

## 目标

1. “tOS 版本维护”继续在 tOS 路标内打开维护 Modal，不再直接跳转配置中心。
2. 新建和编辑路标版本时，`tOS 版本` 使用配置中心 `tOS版本（2位）` 的当前有效枚举值。
3. 项目列表工具按钮顺序固定为“筛选 → 字段配置 → 全屏”，全屏位于字段配置右侧。
4. 所有当前用户可访问的“列设置”文案统一改为“字段配置”。
5. 不改变既有权限、字段显隐、拖拽排序、保存、全屏和筛选数据逻辑。

## 方案选择

### 方案 A：恢复业务 Modal，复用枚举数据源，并统一用户可见文案（采用）

- 恢复 `TosVersionMaintenanceModal` 及其原有新建、编辑、删除、周期、技术点、未保存确认和引用校验能力。
- 版本号字段改为 `Select`，选项来自 `useTosEnumOptions('tos-2-part', historicalValues)`。
- 所有可见入口改称“字段配置”，内部变量继续使用 `columnSettings`。

优点是业务闭环完整、改动边界清晰、兼容既有存储；风险集中在历史版本与当前枚举值的兼容。

### 方案 B：在路标中嵌入枚举配置组件

可直接新增/编辑枚举，但会把“系统枚举治理”和“路标业务属性维护”混在同一窗口，无法恢复周期与技术点维护，不采用。

### 方案 C：继续跳配置中心并增加返回入口

实现简单，但不符合“保留之前功能”，且造成上下文切换，不采用。

## 1. tOS 版本维护

### 1.1 入口

- `RoadmapToolbar` 保留“tOS 版本维护”按钮。
- 点击后只切换 `tosMaintenanceOpen = true`，不调用 `setConfigTab('enum')` 或 `setActiveModule('config')`。
- 权限保持现有规则：有 `roadmap:view` 可查看；只有 `roadmap:edit` 可新建、编辑和删除。
- 枚举加载失败时，路标页面原有恢复入口仍可跳转配置中心；正常维护入口不跳转。

### 1.2 Modal 结构

Modal 恢复以下区域：

1. 已维护版本列表：按语义版本倒序展示。
2. 版本摘要：版本名称、周期、技术点数量、项目引用数量。
3. 新增版本：打开内联编辑卡片。
4. 编辑版本：复用同一编辑卡片并回填数据。
5. 删除版本：保留确认、项目引用拦截和结果反馈。
6. 未保存保护：切换编辑对象、取消编辑或关闭 Modal 时，对脏表单进行二次确认。

### 1.3 字段

| 字段 | 控件 | 必填 | 数据与规则 |
| --- | --- | --- | --- |
| tOS 版本 | 单选 Select | 是 | 选项来自枚举类型 `tos-2-part`；显示为 `tOS16.0`，保存值为规范化字符串 `16.0` |
| 周期 | DatePicker.RangePicker | 否 | 开始日期不得晚于结束日期；沿用原版本周期保存字段 |
| 技术点 | 多行文本 | 否 | 沿用原维护逻辑；每个版本保存独立技术点内容 |

### 1.4 枚举联动与兼容

- 当前有效选项来自 `useTosEnumOptions('tos-2-part')`，不复制枚举数据到组件常量。
- 新建版本只能选择当前有效枚举值。
- 编辑历史版本时，把该版本当前值作为 `historicalValues` 传入；若配置中心已删除该值，Select 显示“tOSxx.x（已停用）”且禁用，保留历史显示。
- 历史停用值不能被重新选择；用户如需更改，只能改为当前有效值。
- 已经存在于路标版本列表中的枚举值，在新建时禁用或从可选项中过滤，并给出“该版本已维护”的清晰状态，避免重复。
- 枚举尚未加载时显示加载态；加载失败显示错误与“重试加载”，不把正常点击强制跳转配置中心。

### 1.5 新建与编辑保存

- 新建调用现有 `createTosVersion`，编辑调用现有 `renameTosVersion`，继续保存周期和技术点。
- Select 值在提交前通过既有规范化函数转换为路标版本名称/ID。
- 重复、无效、版本不存在等错误显示在字段附近或消息提示中。
- 提交期间锁定按钮，防止重复保存；成功后刷新列表并退出编辑态。

### 1.6 删除

- 沿用既有项目引用计数。
- 被正常项目引用的版本继续禁止删除，并提示引用项目数量。
- 未被阻止的删除需二次确认；删除只影响路标版本维护数据，不自动删除配置中心枚举值。

## 2. 项目列表工具栏顺序

- 在列表视图快捷筛选行右侧，工具按钮顺序固定为：`筛选`、`字段配置`、`全屏`。
- `全屏` 必须紧邻 `字段配置` 右侧，按钮尺寸、间距、图标风格和文字基线保持一致。
- 卡片视图仍不显示全屏；日历视图继续显示筛选与全屏，但不显示字段配置，因为日历没有表格字段。
- 普通模式与全屏模式复用同一工具顺序和状态，不复制筛选或字段配置数据。
- 按钮保持明确文字和 `aria-label`，键盘 Tab 顺序与视觉顺序一致。

## 3. “列设置”统一改名为“字段配置”

### 3.1 改名范围

覆盖所有当前用户可见入口，包括：

- 按钮文字；
- Tooltip；
- Popover/Modal/Drawer 标题；
- `aria-label`；
- 搜索框占位和无障碍名称；
- 保存成功提示；
- 空状态和用户说明文案；
- 当前仍会运行的源码契约与浏览器验收文案。

重点调用方包括共享 `SortableColumnSettings`、项目列表、tOS 路标、项目空间计划、技术项目计划、项目汇总/历史可达路标视图等。

### 3.2 不改范围

- `columnSettings`、`columnOrder`、`visibleColumns` 等内部变量和类型；
- localStorage/persist key；
- 组件文件名和公共 API 名称；
- 字段显隐、拖拽排序、最低显示数量、重置、取消、确认逻辑；
- 仅用于描述代码概念且不会呈现给用户的历史设计文档。

### 3.3 共享组件

`SortableColumnSettings` 作为统一文案源，默认展示：

- 标题：字段配置；
- Tooltip/触发器：字段配置；
- 搜索 placeholder：搜索字段；
- 搜索 aria-label：搜索字段配置；
- 空结果：未找到匹配字段。

直接实现按钮而未使用共享触发器的页面同步修改用户文案，避免局部残留。

## 4. 数据流

```text
配置中心枚举 store（tos-2-part）
        ↓ hydrate / current values
useTosEnumOptions
        ↓ current + historical disabled option
tOS 版本维护 Modal
        ↓ normalize / validate
roadmap store createTosVersion / renameTosVersion
        ↓
路标列表、演进视图、筛选、计划项目引用
```

字段配置改名只发生在展示层：

```text
用户文案：字段配置
        ↓
SortableColumnSettings / 页面触发器
        ↓
内部仍使用 columnSettings、columnOrder、visibleColumns
```

## 5. 异常与边界

1. 枚举为空：Modal 可打开并查看历史版本，但新增按钮禁用或保存时提示“请先在配置中心维护 tOS版本（2位）”。
2. 枚举加载失败：显示错误与重试；不静默显示空 Select。
3. 历史值已删除：编辑时只读显示停用项，不能把停用值用于新建。
4. 切换版本或关闭 Modal：有未保存修改时二次确认。
5. 重复版本：客户端和 store 双重校验，提示“该版本已维护”。
6. 全屏：字段配置和筛选浮层继续挂载到正确容器，不被覆盖层遮挡。
7. 权限不足：查看者可打开维护 Modal，但编辑入口禁用或隐藏，不能通过事件绕过权限。

## 6. 验收标准

### tOS 版本维护

- 点击“tOS 版本维护”在当前路标页面打开 Modal，页面模块不切换到配置中心。
- Modal 可查看原版本列表并完成新建、编辑、删除、周期和技术点维护。
- 新建/编辑的版本字段为单选框，选项与配置中心 `tOS版本（2位）` 完全一致。
- 配置中心删除的历史值仍能在原记录中显示为停用项，但不能新选。
- 枚举加载、失败、空值、重复值和引用删除均有明确反馈。

### 项目列表

- 列表视图按钮顺序为“筛选、字段配置、全屏”。
- 全屏按钮位于字段配置右侧，普通/全屏状态均无错位。
- 卡片不显示全屏；日历不显示字段配置。

### 全局文案

- 当前可访问页面不再出现用户可见“列设置”。
- 所有对应按钮、标题、Tooltip、无障碍名称和成功提示统一为“字段配置”。
- 字段配置原有拖拽、显隐、搜索、重置、取消、确认与持久化行为无回归。

## 7. 验证计划

1. 新增源码契约测试：维护按钮打开 Modal、不调用配置跳转；版本 Select 使用 `tos-2-part`。
2. 更新项目列表工具栏断言：字段配置后紧跟全屏。
3. 更新全局字段配置断言：用户可见源码中不存在旧文案，内部变量不要求重命名。
4. 运行现有枚举、路标、项目列表、浮层和技术计划专项脚本。
5. 运行 `npx tsc --noEmit` 与 `npm run build`。
6. 浏览器验证 tOS 版本新建/编辑、历史停用值、按钮顺序、普通/全屏浮层和键盘焦点顺序。
