# 整机计划信息与 SPUG 市场字段调整设计

## 1. 目标

本次调整只作用于整机产品项目，统一计划信息展示字段与市场编辑字段，并恢复“编译选项、编译市场”。两个编译字段的正式枚举来自 SPUG，当前原型使用 mock 数据模拟接口返回。

## 2. 已确认字段口径

计划字段统一按以下 Schema 顺序定义：

| 顺序 | 字段 | 默认显示 | 可隐藏 | 市场编辑必填 |
|---|---|---|---|---|
| 1 | 编译选项 | 否 | 是 | 是 |
| 2 | 编译市场 | 否 | 是 | 是 |
| 3 | Google Launch Date | 是 | 否 | 否 |
| 4 | 是否 MADA 管控 | 是 | 否 | 否 |
| 5 | 是否锁卡 | 是 | 否 | 否 |
| 6 | 是否取消暂停 | 是 | 否 | 否 |
| 7 | 取消暂停时间 | 是 | 否 | 条件必填 |

取消暂停时间不是整体必填；当“是否取消暂停=是”时必须填写，为“否”或清空时同步清除日期。

## 3. 计划信息展示与字段配置

- 整机计划信息默认只展示 Google Launch Date、是否 MADA 管控、是否锁卡、是否取消暂停、取消暂停时间。
- 不再展示计划开始时间、计划结束时间、开发周期和是否运营商定制。
- “配置字段”抽屉继续保留。编译选项、编译市场默认不选中，用户可以配置显示；其余五项固定选中且不可取消。
- 用户开启编译字段后，卡片仍按 Schema 顺序排列，并继续遵循最多两行的现有布局规则。
- 显示偏好继续按用户、项目和 `plan` 分组保存，不因市场页签切换而变化。

## 4. 市场编辑

市场编辑保留市场列头、新增 / 删除市场、“主市场”和“跟随主市场”两项结构控制。业务编辑行严格限定为：

1. 编译选项
2. 编译市场
3. Google Launch Date
4. 是否 MADA 管控
5. 是否锁卡
6. 是否取消暂停
7. 取消暂停时间

是否运营商定制、分支信息、Jenkins 构建、版本地址不再出现在市场编辑界面。为避免破坏历史数据，这些旧字段不在本次迁移中物理删除；保存市场配置时原值继续透传，但界面不可查看或修改。

编译选项、编译市场按市场独立保存。不同市场可填写不同值，编辑一个市场不得覆盖其他市场。

## 5. SPUG 数据边界

界面只依赖统一的 SPUG 选项数据源，不直接持有正式枚举。数据源输出两个下拉列表：

- 编译选项 mock：`ko2_sl303`、`ko2`、`a681l_sm386`、`lj8k_h781`、`lj8_h781`、`lj7_h782`、`x1103b`
- 编译市场 mock：`op`、`tr`

当前实现使用异步 mock provider 返回以上值；正式接入时将 provider 替换为 SPUG API 适配器，市场编辑组件和业务 Schema 不变。加载期间显示 loading，加载失败时禁用两个下拉框并提供重新获取提示，不允许自由输入未受控值。

## 6. 数据兼容与初始化

- `MarketConfigRow` 增加市场级 `buildOption`、`buildMarket`。
- 历史项目若只有项目级 `buildOption`、`buildMarket`，首次构建已有市场行时将这两个值作为兼容回填；一旦市场行已有显式值（包括显式清空），不得再次被项目级值覆盖。
- 新增市场的两个编译字段默认空白，保存前执行必填校验。
- 跟随主市场只同步计划，不复制或联动编译选项、编译市场及其他市场属性。
- 当前 mock 继续随项目 store 保存；正式环境按既有约定迁移到数据库，键为 `projectId + market`。

## 7. 验证范围

- 规则测试：七字段顺序、默认显示、可隐藏属性及必填口径。
- 数据测试：SPUG mock 返回值、历史项目级值回填、市场值隔离、显式空值不被覆盖。
- 交互测试：计划默认五项、抽屉仅可切换两个编译字段、市场编辑只有七项业务行、取消暂停条件校验。
- 回归测试：主市场 / 跟随主市场逻辑保持不变；整机与 tOS 配置信息仍不展示；非整机项目不受影响。
- 工程门禁：相关验证脚本、`npx tsc --noEmit`、`npm run build` 和聚焦浏览器 smoke。

## 8. 非目标

- 本次不接入真实 SPUG 网络接口或认证。
- 本次不清理历史运营商定制、分支、Jenkins、版本地址数据。
- 本次不修改 tOS 版本项目计划字段。
- 本次不发布到 dev、master 或 Vercel，除非用户另行要求。
