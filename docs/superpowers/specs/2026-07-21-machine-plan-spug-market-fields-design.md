# 整机计划信息、SPUG 市场字段与 tOS 类型编辑统一设计

## 1. 目标

本次调整包含两个相互独立但共用交互骨架的范围：

1. 整机产品项目统一计划信息展示字段与市场编辑字段，并恢复“编译选项、编译市场”。两个编译字段的正式枚举来自 SPUG，当前原型使用 mock 数据模拟接口返回。
2. tOS 版本项目的类型编辑改为与整机市场编辑一致的矩阵交互；只统一编辑器结构，不改变一级计划跟随、二级计划独立和修订权限等类型业务规则。

本文同时修订 `2026-07-21-tos-type-follow-plan-layout-and-machine-category-split-design.md` 的主类型删除规则：主类型不再允许直接删除，必须先切换主类型后再删除原类型。

## 2. 已确认字段口径

计划字段统一按以下 Schema 顺序定义：

| 顺序 | 字段 | 默认显示 | 可隐藏 | 市场编辑必填 |
|---|---|---|---|---|
| 1 | 编译选项 | 否 | 是 | 是 |
| 2 | 编译市场 | 否 | 是 | 是 |
| 3 | Google Launch Date | 是 | 否 | 否 |
| 4 | 是否 MADA 管控 | 是 | 否 | 否 |
| 5 | 是否锁卡 | 是 | 否 | 否 |
| 6 | 是否取消暂停 | 是 | 否 | 否 |
| 7 | 取消暂停时间 | 是 | 否 | 条件必填 |

取消暂停时间不是整体必填；当“是否取消暂停=是”时必须填写，为“否”或清空时同步清除日期。

## 3. 计划信息展示与字段配置

- 整机计划信息默认只展示 Google Launch Date、是否 MADA 管控、是否锁卡、是否取消暂停、取消暂停时间。
- 不再展示计划开始时间、计划结束时间、开发周期和是否运营商定制。
- “配置字段”抽屉继续保留。编译选项、编译市场默认不选中，用户可以配置显示；其余五项固定选中且不可取消。
- 用户开启编译字段后，卡片仍按 Schema 顺序排列，并继续遵循最多两行的现有布局规则。
- 显示偏好继续按用户、项目和 `plan` 分组保存，不因市场页签切换而变化。

## 4. 市场编辑

市场编辑保留市场列头、新增 / 删除市场、“主市场”和“跟随主市场”两项结构控制。业务编辑行严格限定为：

1. 编译选项
2. 编译市场
3. Google Launch Date
4. 是否 MADA 管控
5. 是否锁卡
6. 是否取消暂停
7. 取消暂停时间

是否运营商定制、分支信息、Jenkins 构建、版本地址不再出现在市场编辑界面。为避免破坏历史数据，这些旧字段不在本次迁移中物理删除；保存市场配置时原值继续透传，但界面不可查看或修改。

编译选项、编译市场按市场独立保存。不同市场可填写不同值，编辑一个市场不得覆盖其他市场。

## 5. SPUG 数据边界

界面只依赖统一的 SPUG 选项数据源，不直接持有正式枚举。数据源输出两个下拉列表：

- 编译选项 mock：`ko2_sl303`、`ko2`、`a681l_sm386`、`lj8k_h781`、`lj8_h781`、`lj7_h782`、`x1103b`
- 编译市场 mock：`op`、`tr`

当前实现使用异步 mock provider 返回以上值；正式接入时将 provider 替换为 SPUG API 适配器，市场编辑组件和业务 Schema 不变。加载期间显示 loading，加载失败时禁用两个下拉框并提供重新获取提示，不允许自由输入未受控值。

## 6. 数据兼容与初始化

- `MarketConfigRow` 增加市场级 `buildOption`、`buildMarket`。
- 历史项目若只有项目级 `buildOption`、`buildMarket`，首次构建已有市场行时将这两个值作为兼容回填；一旦市场行已有显式值（包括显式清空），不得再次被项目级值覆盖。
- 新增市场的两个编译字段默认空白，保存前执行必填校验。
- 跟随主市场只同步计划，不复制或联动编译选项、编译市场及其他市场属性。
- 当前 mock 继续随项目 store 保存；正式环境按既有约定迁移到数据库，键为 `projectId + market`。

## 7. tOS 类型编辑矩阵

基础信息和计划模块的“类型编辑”继续打开同一个 Modal，并改为与市场编辑一致的横向矩阵：

- 每个类型占一列，左侧固定字段列。
- 字段行只有“主类型”和“跟随主类型”两行。
- 顶部工具栏从未配置的 `Full`、`Slim`、`PAD`、`GO` 中选择并增加类型。
- 每个类型列头显示类型名称、主类型 Tag 和删除按钮。
- 主类型列的删除按钮禁用；必须先把其他类型设为主类型，才可删除原类型。
- 至少保留一个类型，并且整个项目恰好有一个主类型。
- 主类型不能勾选“跟随主类型”；非主类型可以独立设置是否跟随。
- 切换主类型时清空全部已有跟随关系，避免跟随关系静默改绑。
- 保存时统一校验并归一化；取消只关闭弹窗，不写入项目类型配置。

以下既有规则保持不变：

- 跟随类型的一级计划有效来源仍为当前主类型，且不能发起一级计划修订。
- 非跟随类型和主类型继续使用自己的一级计划。
- 二级计划及版本火车继续按类型独立，不跟随主类型。
- 类型顺序继续写入项目 `versionTypes`，主类型继续写入 `versionType`，mock 阶段的跟随关系继续存入项目级类型配置仓储；正式环境存入数据库。
- 类型编辑继续受 `basicInfo:编辑` 权限控制。

## 8. 共用交互骨架

采用方案 A，抽取无业务状态的维度矩阵编辑器骨架，由市场编辑和类型编辑分别提供列数据、字段行和控件渲染：

- 共用部分：Modal/table 布局、固定字段列、维度列头、增加工具栏、删除入口、空状态、横向滚动阈值和基础样式。
- 市场专属：市场枚举、主市场修订保护、七项市场业务字段及 SPUG 加载状态。
- tOS 专属：类型枚举、主类型 / 跟随主类型两项控制，以及类型计划规则。

通用骨架不判断“主市场”或“主类型”等业务含义，删除禁用、Tag、提示和字段控件均由对应业务包装组件传入，避免两套规则互相污染。

## 9. 验证范围

- 规则测试：七字段顺序、默认显示、可隐藏属性及必填口径。
- 数据测试：SPUG mock 返回值、历史项目级值回填、市场值隔离、显式空值不被覆盖。
- 交互测试：计划默认五项、抽屉仅可切换两个编译字段、市场编辑只有七项业务行、取消暂停条件校验。
- tOS 交互测试：类型作为列、两项字段作为行；增加 / 删除类型；主类型不可直接删除；切换主类型后可删除原类型；主类型禁用跟随；取消不写入配置。
- tOS 规则回归：跟随类型一级计划来源、不可发起修订、二级计划独立、基础信息合并 Tab 均保持不变。
- 公共骨架回归：市场主市场修订保护与 tOS 主类型规则互不影响，两个入口的权限控制保持不变。
- 其他回归：整机与 tOS 配置信息仍不展示；非整机、非 tOS 项目不受影响。
- 工程门禁：相关验证脚本、`npx tsc --noEmit`、`npm run build` 和聚焦浏览器 smoke。

## 10. 非目标

- 本次不接入真实 SPUG 网络接口或认证。
- 本次不清理历史运营商定制、分支、Jenkins、版本地址数据。
- 本次不修改 tOS 版本项目计划字段、计划数据隔离方式或修订权限规则。
- 本次不把整机市场业务字段复制到 tOS 类型编辑器。
- 本次不发布到 dev、master 或 Vercel，除非用户另行要求。
