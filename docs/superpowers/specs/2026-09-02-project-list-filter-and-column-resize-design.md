# 项目列表快捷筛选、tOS 字段与列宽拖动设计

## 1. 目标与范围

本次仅调整项目列表，不改变项目卡片、项目空间、字段配置顺序拖动及表头整块换位的既有规则。

1. 缩减整机产品项目、技术项目 TDT、技术项目子项目的快捷筛选字段。
2. 将 tOS 版本项目列表固定为“tOS版本、里程碑、版本项目经理”三个字段配置单元，三个单元默认显示且均可隐藏。
3. 列表末级表头支持按住右边缘拖动调整列宽，交互对齐飞书表格。

## 2. 快捷筛选

| 列表类型 | 快捷筛选字段 | 控件与匹配方式 |
| --- | --- | --- |
| 整机产品项目 | 项目名称、首销tOS版本、芯片编码、研发模式 | 项目名称为单行文本模糊包含；其余为可搜索多选下拉，写入统一筛选条件 |
| tOS版本项目 | 项目名称 | 单行文本模糊包含，维持现状 |
| 技术项目－TDT项目 | 项目名称、技术赛道、TMG及技术领域 | 项目名称为单行文本模糊包含；其余为可搜索多选下拉 |
| 技术项目－子项目 | 子任务名称、所属TDT项目名称 | 子任务名称为单行文本模糊包含；所属TDT项目名称为可搜索多选下拉 |

快捷筛选与高级筛选继续共享同一筛选条件集合；修改任意快捷项后，已启用条件摘要同步更新。切换技术项目类型时，仅展示当前类型的快捷筛选，不保留已不适用字段对结果的限制。

## 3. tOS 版本项目字段

字段配置只提供以下三个单元，顺序如下：

| 顺序 | 配置单元 | 默认显示 | 可隐藏 | 展示内容 |
| --- | --- | --- | --- | --- |
| 1 | tOS版本 | 是 | 是 | tOS 版本号 |
| 2 | 里程碑 | 是 | 是 | 最新已发布一级计划模板的末级里程碑列，整体参与显示/隐藏及排序 |
| 3 | 版本项目经理 | 是 | 是 | 项目版本项目经理；沿用现有项目数据中的负责人字段 |

“里程碑”仍是字段配置和表头换位中的一个整体；其内部每个末级日期列可分别调整列宽。

## 4. 列宽拖动交互

### 4.1 命中与视觉反馈

- 鼠标进入末级表头右侧 8px 命中区时，光标变为 `col-resize`。
- 悬浮命中区显示 1px 蓝色边界提示；按下后显示贯穿表头和表体的 1px 蓝色插入线。
- 拖动过程实时改变目标列宽，其他列宽不变；松开后蓝线消失。
- 最小列宽 80px，最大列宽 600px，避免内容不可读或异常占满画布。
- 调整列宽的命中区提供可识别的 `aria-label`，不遮挡表头文本和排序拖动区域。

### 4.2 与表头排序共存

- 从表头正文区域按住拖动：执行既有字段/里程碑整块排序。
- 从右边缘列宽命中区按住拖动：只调整列宽，并阻止排序传感器启动。
- 列宽调整过程中表头位置不交换；松开后顺序保持不变。
- “里程碑”作为排序单元整体移动，但其末级列宽分别保存。

### 4.3 持久化

- 列宽与当前项目类型、技术项目子类型及现有字段配置使用同一项目列表偏好命名空间。
- 保存末级字段键到像素宽度的映射；刷新页面或重新进入列表后恢复。
- 新增或删除模板里程碑时，只保留仍存在字段的宽度，新增字段使用定义中的默认宽度。
- 旧版本地偏好没有列宽数据时自动采用默认宽度，不清空既有字段顺序和显隐配置。

## 5. 数据与组件边界

- `projectListMatrix` 负责快捷筛选矩阵、tOS 字段矩阵及默认宽度。
- 独立列宽规则模块负责宽度范围限制、旧数据归一化和增量更新，便于无浏览器测试。
- `ProjectSummaryTable` 负责读取/持久化列宽、把宽度应用到 Ant Design 末级列，并渲染贯穿线。
- `SortableProjectListHeader` 负责右边缘拖动手势；仅通过回调上报预览和提交，不直接读写业务状态。

## 6. 验收标准

1. 三类列表只出现本设计第 2 节定义的快捷筛选，字段标签及控件类型正确。
2. tOS 版本项目字段配置只有三个单元，全部默认显示、可逐一隐藏并可排序。
3. 任一末级表头右边缘可拖宽或拖窄，范围限制生效，表头顺序不变化。
4. 表头正文拖动排序仍正常，里程碑整块移动规则不变。
5. 列宽刷新后保留；字段显隐、顺序和筛选条件也继续保留。
6. 蓝色贯穿线为 1px，拖动结束后消失，不覆盖单元格交互。
7. 类型检查、生产构建、源代码契约测试和真实浏览器拖拽回归全部通过。
8. `dev` 远端更新后完成 Vercel 生产发布，并在线复验上述关键路径。

## 7. 补充范围：项目信息与 EOS 发版边界

### 7.1 整机 JIRA 项目布局

整机项目空间“扩展信息”中，`JIRA项目`固定为最后一个字段，并独占一整行。新建/编辑弹窗继续使用现有 JIRA 编辑器，不改变字段结构和数据。

### 7.2 新建项目状态

新建项目时状态不再读取 IPM 状态，也不默认选择枚举首项，必须由用户主动下拉选择后才能提交。选项只来自配置中心当前有效枚举：

- 整机产品项目：待立项、在研、上市、EOS、转维、已取消、已暂停。
- tOS版本项目：在研、已完成。
- 技术项目：进行中、已完成、暂停、已取消。

编辑历史项目时保留当前值兼容能力，但新选择必须属于当前枚举。

### 7.3 EOS 替代停止发版

- 联合项目空间“tOS&整机1+N项目计划”删除“停止发版”和“停止发版记录”按钮、弹窗及操作入口；历史停止记录不再参与可见性计算。
- 整机项目状态首次切换为 `EOS` 时写入 ISO 格式 `statusChangedAt`；离开 EOS 后字段可保留审计值，但不触发隐藏，再次进入 EOS 时刷新。
- 已处于 EOS 但缺少时间的历史项目，在项目状态迁移时补记首次迁移时间。
- 当某整机项目当前状态为 EOS，且 tOS 版本“修改点收集开始时间”晚于 EOS 日期时，该整机项目在该版本及后续版本中隐藏；等于 EOS 日期的版本仍展示。
- 新逻辑同时用于计划重建和列表投影，避免刷新后被旧持久化数据重新带出。

### 7.4 补充发布验收

除前述验收外，还需验证 JIRA 独占末行、三类项目状态必选及选项来源、EOS 前后版本可见性、停止发版入口完全消失。最终先更新 `dev`，再快进合入 `master`，最后发布 Vercel 生产环境。
