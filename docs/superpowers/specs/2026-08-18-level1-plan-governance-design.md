# 一级计划结构、计算与权限更新设计

## 1. 背景与目标

本次统一收敛所有项目一级计划的字段、日期、版本和编辑权限，并让技术项目的 TDT 项目计划、子项目计划复用相同交互规则。目标是让项目成员只维护二级活动的计划完成时间和实际完成时间，一级活动的时间、工期和人力占比全部自动计算，避免模板、表格、横版和历史版本出现不同口径。

截图仅作为结构和 Mock 数据参考；当截图展示值与本设计中已确认的自动计算规则冲突时，以本设计规则为准。

## 2. 范围

### 2.1 纳入范围

- 所有项目类型的一级计划。
- 技术项目的 TDT 项目计划和子项目计划。
- 配置中心的一级计划模板、TDT 项目计划模板和子项目计划模板。
- 项目空间表格、横版视图、基础信息中的计划摘要、导出、版本和发布校验。
- 系统内置 Mock、已有持久化 Mock 的兼容迁移。

### 2.2 不纳入范围

- 项目空间二级计划和三级计划的业务逻辑。
- 技术项目现有 TDT、子项目模板的节点名称和层级调整。
- 新增人力投入、人天或资源排期字段。
- 改变现有整机市场、tOS 类型的跟随关系和数据源选择逻辑。

## 3. 适用项目与模板

### 3.1 新四阶段模板

整机产品项目、tOS 版本项目、能力建设项目使用同一套一级计划结构：

1. 概念阶段
   - 概念启动
   - STR1
2. 计划阶段
   - STR2
   - STR3
3. 开发验证阶段
   - STR4
   - STR4A
   - STR5
4. 上市收编阶段
   - 收编完成

序号由树结构和同级顺序自动生成，不作为业务主键。

### 3.2 技术项目模板

- TDT 项目计划和子项目计划保留当前模板内容、节点名称和层级。
- 二者统一应用本设计中的字段显示、日期计算、版本、权限和横版编辑规则。

### 3.3 配置中心入口

- 整机产品、tOS 版本、能力建设项目只显示“一级计划”模板配置，隐藏“二级计划”配置。
- 技术项目只显示“TDT 项目计划”和“子项目计划”。
- 模板表格固定显示“序号、任务名称、角色”，不显示责任人、前置任务、日期、状态、进度或工期。
- 模板继续保留版本、修订、发布、同级拖动排序、新增和删除能力。

## 4. 数据模型与来源标记

### 4.1 模板任务

模板任务只保存结构所需字段：

- 稳定任务 ID。
- 父任务 ID。
- 同级顺序。
- 任务名称。
- 角色。
- 模板来源标记。

稳定任务 ID 用于模板同步、版本复制和实际完成时间同步；展示序号根据结构实时生成。

### 4.2 项目任务

- 一级活动保存结构信息，不保存可人工维护的执行时间；是否存在子活动不改变一级活动只读规则。
- 二级活动只把“计划完成时间、实际完成时间”作为执行输入。
- 技术子项目计划是唯一例外：其现有模板只有一级节点，这些节点按子项目里程碑单独处理，允许填写计划完成时间和实际完成时间，但不改变其他计划中一级活动始终只读的规则。
- 一级活动的计划开始、计划完成、实际开始、实际结束、预估工期、实际工期和人力占比均由统一规则层计算。
- 二级活动的“是否延期”由统一规则层计算，不允许手工选择。
- 旧记录中的责任人、前置任务、状态、进度等字段可为兼容历史数据继续存在，但不展示、不编辑、不参与新计算。

### 4.3 活动来源

每条活动增加以下来源语义：

- `template`：来自配置中心正式模板。
- `custom`：在具体项目内新增。

来源标记只影响模板合并和删除权限，不改变展示序号。

## 5. 项目空间表格

表头固定为：

1. 序号
2. 阶段/里程碑节点
3. 计划开始时间
4. 计划完成时间
5. 预估工期
6. 实际开始时间
7. 实际结束时间
8. 实际工期
9. 是否延期

显示和编辑规则：

- 一级活动整行字段只读；管理员的新增、删除是结构操作，不等同于修改一级活动字段。
- 一级活动显示自动计算的四个时间和两个工期；是否延期显示为空值。
- 二级活动的计划开始时间、预估工期、实际开始时间、实际工期显示为空值。
- 技术子项目计划的单层节点按二级里程碑的显示和编辑规则处理。
- 修订版本中，有权限用户可直接修改二级活动的计划完成时间和实际结束时间。
- 已发布版本中，有权限用户只能直接修改二级活动的实际结束时间。
- 删除责任人、前置任务、状态和进度列；列设置、导出和版本对比也不再提供这些列。
- 日期不合法时保留用户输入并把日期选择框、单元格标红，展示明确原因；修订版存在错误时禁止发布。

## 6. 自动计算规则

### 6.1 计划时间

按一级活动顺序扫描，空日期不参与聚合：

- 第一个存在二级活动计划完成时间的一级活动，计划开始时间取本阶段第一个已填写的二级活动计划完成时间。
- 一级活动计划完成时间取本阶段最后一个已填写的二级活动计划完成时间。
- 后续存在计划数据的一级活动，计划开始时间取上一个有效一级活动计划完成时间的次日。
- 没有任何二级活动计划完成时间的一级活动，计划开始、计划完成和预估工期均为空。

### 6.2 实际时间

实际时间采用与计划时间相同的有效阶段衔接规则，数据源改为二级活动实际结束时间：

- 第一个存在实际数据的一级活动，实际开始时间取本阶段第一个已填写的二级活动实际结束时间。
- 一级活动实际结束时间取本阶段最后一个已填写的二级活动实际结束时间。
- 后续存在实际数据的一级活动，实际开始时间取上一个有效一级活动实际结束时间的次日。
- 中间空阶段不占用日期；后续有效阶段继续承接上一个有效阶段。
- 没有任何二级活动实际结束时间的一级活动，实际开始、实际结束和实际工期均为空。

### 6.3 工期

- 预估工期 = 一级活动计划完成时间 - 计划开始时间。
- 实际工期 = 一级活动实际结束时间 - 实际开始时间。
- 按自然日日期差计算，不额外加 1 天。
- 工期只在一级活动显示。

### 6.4 人力占比

横版视图中的人力占比使用工期权重，不新增人力字段：

`当前一级活动预估工期 / 全部一级活动预估工期之和 × 100%`

- 最多显示一位小数，整数不显示小数位。
- 总预估工期为 0 或不存在时显示“-”。

### 6.5 是否延期

是否延期只在二级活动显示：

- 计划完成时间为空：显示“-”。
- 已填写实际结束时间：实际结束时间晚于计划完成时间为“延期”，否则为“按时”。
- 未填写实际结束时间：当前日期晚于计划完成时间为“延期”，否则为“按时”。

### 6.6 技术子项目计划例外

- 技术子项目计划保持当前单层模板，不人为增加一级父活动。
- 单层节点允许填写计划完成时间和实际结束时间，计划开始、预估工期、实际开始、实际工期显示为空。
- 单层节点计算“是否延期”，并按节点顺序执行严格递增校验。
- 因不存在一级父活动，不执行一级活动时间聚合，也不显示一级活动工期占比。

## 7. 日期顺序校验

计划完成时间与实际结束时间分别校验，二者互不交叉比较：

- 同一一级活动内，后一个已填写二级活动的日期必须至少比前一个已填写二级活动晚 1 天。
- 跨一级活动时，下一个有效一级活动的第一个已填写二级活动日期必须至少比上一个有效一级活动的最后一个已填写二级活动晚 1 天。
- 不允许同一天，不允许逆序。
- 实际时间为空的任务跳过，不因未填写而报错。
- 修订版本有错误时阻止发布并滚动到第一处错误。
- 已发布版本直接修改实际结束时间后，如果暂时形成错误，保留输入并持续红色提示，直至用户修正。

## 8. 权限

### 8.1 可维护身份

一级计划的维护权限不再取通用“一级计划编辑”授权，而是按当前项目身份严格判断：

- 整机产品、tOS 版本、能力建设项目：当前项目 SPM，即项目内“项目经理”。
- 技术项目：当前项目“技术项目负责人”，对应 `technicalLead`；“技术项目经理”不自动获得维护权限。
- 所有项目：全局“管理组”成员，即系统超级管理员。

列表入口、按钮显示、单元格编辑和事件处理函数必须使用同一权限判断，不能只隐藏按钮。

### 8.2 新增和删除

- 系统超级管理员可以新增、删除所有活动，包括模板原有活动。
- 普通项目 SPM 不能新增或删除一级计划活动。
- 整机产品项目“上市收编阶段”为 SPM 例外：可新增子活动，可删除来源为 `custom` 的子活动，不可删除来源为 `template` 的子活动。
- SPM 不能在其他阶段新增或删除活动。

### 8.3 字段编辑

- 一级活动所有字段均不可直接编辑，即使异常数据中暂时没有子活动也保持只读。
- 有权限身份只可编辑二级活动的计划完成时间和实际结束时间。
- 技术子项目计划按第 6.6 节例外处理，其单层里程碑节点允许编辑上述两个完成时间。
- 无权限成员只能查看最新可见正式版本，不可看到或操作修订版。

## 9. 横版视图与基础信息

- 点击项目空间“计划”默认进入横版视图。
- 一级活动名称下方显示 `计划开始时间 ~ 计划完成时间`；无完整范围时显示“-”。
- 一级活动名称右侧显示该阶段的人力占比。
- 有修订版本时，项目 SPM、技术项目负责人或系统超级管理员可在横版中看到修订版。
- 修订版横版中可修改二级活动计划完成时间和实际结束时间。
- 已发布版横版中只可修改二级活动实际结束时间。
- 基础信息中的计划区域和项目空间计划页复用同一横版数据投影和编辑处理，避免显示或权限不一致。
- 表格、横版和导出必须使用同一套计算结果。

## 10. 版本和模板同步

### 10.1 初始化

项目计划初始化时使用当时最新的正式模板，并记录模板版本和任务稳定 ID。

### 10.2 第一次修订

- 项目第一次创建修订版本时，再同步一次当时最新正式模板。
- 同稳定 ID 的活动更新模板结构信息，同时保留项目已填写的计划完成时间和实际结束时间。
- 模板新增活动补入项目。
- 模板已删除活动从新修订移除。
- 项目自定义活动保留。
- 同步完成后记录“首次修订已同步”，避免后续重复套用模板。

### 10.3 后续修订

- 后续修订只复制上一个正式发布版本，不再同步配置中心最新模板。
- 更早历史发布版本保持冻结。

### 10.4 实际完成时间同步

- 在修订版修改二级活动实际结束时间时，同步修改该修订来源的上一正式发布版本中相同稳定 ID 的活动。
- 更早历史发布版本不修改。
- 在来源正式版修改实际结束时间时，若当前存在由其创建的修订版，同步更新对应修订任务。
- 计划完成时间不跨版本同步。

现有整机市场和 tOS 类型跟随逻辑保持不变；本设计不扩大跟随范围的结构编辑权限。

## 11. Mock 与迁移

- 整机、tOS、能力建设的系统模板和内置项目 Mock 使用四阶段新结构。
- Mock 日期按截图的阶段范围刷新，但必须满足本设计的严格递增和自动延期规则；截图中不一致的“按时/延期”文字不写入数据。
- 技术项目 TDT、子项目 Mock 保留现有模板节点，转换为新的字段和来源语义。
- 提升计划持久化版本，迁移内置模板、内置 Mock 项目和对应默认快照。
- 用户新增项目、项目自定义活动、非默认历史版本和不相关计划数据必须保留。
- 迁移重复执行必须幂等，不能重复插入模板节点或改变稳定 ID。

## 12. 错误处理

- 权限不足时不执行写入，并提示当前允许的维护身份。
- 日期错误在原单元格给出红色状态和具体前后节点说明。
- 模板同步遇到未知或重复稳定 ID 时停止该次同步并给出提示，不部分覆盖项目计划。
- 计算函数对空日期、非法日期和零总工期返回空值或“-”，不产生 `NaN`、无效日期或负工期。

## 13. 验收与发布

### 13.1 自动验证

- 配置中心项目分类与计划页签可见性。
- 模板固定三列。
- 项目表格九列及删除字段不再出现。
- 一级活动计划/实际时间聚合和空阶段跳过。
- 工期、人力占比、延期计算。
- 同阶段和跨阶段严格递增校验。
- SPM、技术项目负责人、全局管理组和普通成员权限矩阵。
- 第一次修订同步模板、后续修订复制正式版。
- 当前修订与来源正式版的实际结束时间同步。
- 旧数据迁移幂等和用户数据保留。

### 13.2 浏览器验证

分别使用系统超级管理员、整机项目 SPM、技术项目负责人和普通成员验证：

- 配置中心整机、tOS、能力建设、技术项目模板页签。
- 项目表格和横版字段、默认视图和红色校验。
- 基础信息中的修订版本显示及直接编辑。
- 整机“上市收编阶段”自定义子活动权限。
- 发布版和修订版实际结束时间同步。
- 技术 TDT 和子项目模板内容保持不变。

### 13.3 工程与发布

- 运行相关契约验证、TypeScript 全量检查和生产构建。
- 浏览器本地回归通过后推送 `dev`。
- 将 `dev` 合并到 `master`，发布到 Vercel。
- 在线地址再次执行关键路径回归。
- 本功能与本轮已确认但尚未发布的三级计划修改一起发布。
