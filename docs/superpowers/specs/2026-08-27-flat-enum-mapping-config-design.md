# 配置中心扁平枚举与映射配置设计

## 1. 背景

当前“配置中心 → 枚举值配置”只有 `tOS版本（2位）`、`tOS版本（3位）` 两种单字段枚举，并通过“通用 / 人力资源管道”两级树导航。项目新建、编辑和路标中仍存在多处硬编码选项、项目分类映射、芯片字段和 TMG/子领域映射，配置中心尚未成为统一选项源。

本次改造删除枚举页原有分类层级，固定展示 22 个配置项；同时把配置模型从“只有字符串数组”扩展为单字段、两列映射和三列映射三种结构，并接入项目新建、项目编辑和 tOS 路标。

## 2. 目标

1. 枚举页左侧直接平铺全部 22 个固定配置项，不再显示“通用 / 人力资源管道”。
2. 右侧按配置定义动态显示单字段、两列映射或三列映射表。
3. 每张表第一列显示从 1 开始连续递增的序号。
4. 配置中心成为本期所列业务字段在前端的统一有效选项源。
5. 芯片、项目分类和 TMG/子领域按已确认的映射规则驱动项目新建和编辑。
6. 配置项修改或删除不追溯改写历史项目，历史项目继续保留字符串快照。

## 3. 非目标与当前边界

- 不新增数据库、后端接口或真实 IPM 接口；继续使用 Zustand 与浏览器本地持久化。
- 不允许用户新增、重命名、删除配置类型；只能维护固定配置类型下的数据行。
- 不建设导入、导出、拖拽排序、批量编辑或跨类型搜索值功能。
- 不根据截图猜测或补全未提供的生产枚举全集。初始 Mock 值复用当前代码中的受支持值；截图用于确认字段结构与联动关系。其余生产值由用户在配置中心维护。
- 不改变项目字段原有读写归属。例如 IPM 同步字段仍按原规则只读；本次只替换可选项和映射来源。

## 4. 已确认的关键决策

- 页面使用“A 方案”：左侧扁平列表，右侧动态维护表格。
- 项目分类使用现有正式名称 `tOS版本项目`，不改成 `tOS项目`。
- 芯片映射列为 `芯片编码`、`芯片型号`、`芯片平台`。
- 项目新建或编辑时选择芯片编码，自动带出芯片型号和芯片平台。
- 项目分类三列一起配置，但只有整机产品项目有 PMS 二级项目分类。
- 历史项目保存字符串快照。配置修改、删除后不自动更新旧项目。
- `首销tOS版本` 和 `tOS版本-路标` 录入版本号字符串；系统在配置表、下拉选项和业务展示中统一加 `tOS` 前缀，不再限制两位或三位格式。

## 6. 页面与交互设计

### 6.1 页面结构

沿用配置中心现有页签和 `ConfigWorkspaceShell` 左右工作区：

- 顶部仍选中“枚举值配置”。
- 左侧标题为 `配置项（22）`，提供按配置项名称过滤的搜索框。
- 左侧平铺 22 个配置项，显示名称和当前数据条数；不显示类别、树枝、分类计数或分类图标。
- 左侧顺序固定，区域内部滚动；当前配置项使用浅紫背景与左侧强调线。
- 右侧显示配置项名称、结构标签、应用范围、数据条数和新增按钮。
- 右侧表格根据配置定义生成业务列，最后一列为操作。
- 左右区域继续限制在浏览器可用高度内，各自独立滚动。

窄屏恢复单列结构：配置项列表位于表格上方，配置列表限制高度，避免整页被 22 项撑长。

### 6.2 表格列

#### 单字段配置

`序号 | <配置项名称> | 操作`

单字段业务列直接使用配置项名称，不使用笼统的“枚举值”列名。

#### 芯片映射

`序号 | 芯片编码 | 芯片型号 | 芯片平台 | 操作`

#### 项目分类映射

`序号 | IPM项目分类 | PMS项目分类 | PMS二级项目分类 | 操作`

#### TMG 映射

`序号 | TMG及技术领域 | 子领域 | 操作`

### 6.3 序号规则

- 序号是当前展示顺序的 `index + 1`，不是业务字段，也不作为更新和删除依据。
- 数据行使用稳定内部 ID 标识。
- 新增行追加到当前列表末尾。
- 删除行后序号立即重排为连续的 `1..n`。
- 本期不支持手工调整顺序。

### 6.4 新增、编辑、删除

- 新增和编辑使用同一个动态表单弹窗，按配置定义生成一到三个可见输入框。
- 所有输入都有可见标签，错误显示在对应字段旁。
- 提交期间确认按钮禁用并显示加载状态，防止重复提交。
- 编辑或删除完成后恢复到触发按钮或合理的后续焦点。
- 删除前使用二次确认，确认文案包含被删除的值或映射摘要。
- 空表显示 `暂无配置值`，并保留有权限用户的新增入口。

## 7. 数据模型与持久化

### 7.1 配置定义

配置注册表为每个固定类型声明：

- 稳定 `key`
- 精确中文 `label`
- `scopeLabel`
- `kind`: `single | tmg-map | chip-map | project-category-map`
- 业务列定义
- 初始 Mock 数据
- 可选的显示格式化规则，例如 tOS 前缀

UI、校验、业务取值均读取同一注册表，不在组件中复制类型数组。

### 7.2 数据行

持久化数据使用带稳定 ID 的可判别联合：

```ts
type SingleEnumRow = {
  id: string
  value: string
}

type TmgMappingRow = {
  id: string
  domain: string
  subdomain: string
}

type ChipMappingRow = {
  id: string
  chipCode: string
  chipModel: string
  chipPlatform: string
}

type ProjectCategoryMappingRow = {
  id: string
  ipmProjectCategory: string
  pmsProjectCategory: string
  pmsSecondaryCategory: string
}
```

`pmsSecondaryCategory` 始终是字符串字段，但只有 `pmsProjectCategory === '整机产品项目'` 时必填；其余三类必须保存为空字符串。

Store 持有：

- `rowsByType`
- `selectedType`
- 水合状态与水合错误
- 按 ID 的新增、更新、删除动作
- 重试和重置本地配置动作

### 7.3 本地存储迁移

升级 `pms-enum-values` 的持久化版本并提供显式迁移：

- 旧 `tos-2-part` 值迁移到 `tOS版本-路标`。
- `首销tOS版本` 使用旧 `tos-3-part` 值，并合并旧 `tos-2-part` 中未出现的值，以保留技术项目曾使用的首销版本选项。
- 合并时按首次出现顺序去重，不再按数字段自动排序。
- 其他配置使用当前代码中已有的硬编码选项或映射作为初始 Mock 数据。
- 当前代码和用户材料都没有提供完整权威值的配置类型以空列表初始化；空列表是有效初始状态，不从截图裁切内容推断生产数据。
- 无法安全解析的单行数据丢弃并回退到该类型初始值；整体存储读取失败时继续提供当前的“重试 / 重置本地配置”恢复路径。

## 8. 通用校验规则

1. 保存前去除每一列的首尾空格。
2. 除项目分类的条件性二级分类外，当前结构中的所有列均必填，纯空格视为未填写。
3. 单字段配置在同一类型内禁止完全相同的字符串；比较区分大小写。
4. 芯片和 TMG 映射禁止整行完全重复。
5. 芯片编码允许重复，只要芯片型号或芯片平台不同。
6. `IPM项目分类` 必须在项目分类映射中唯一，保证新建项目能得到确定结果。
7. 项目分类的 PMS 分类只能选择四个现有正式分类：`整机产品项目`、`tOS版本项目`、`技术项目`、`能力建设项目`。
8. 选择整机产品项目时必须填写 PMS 二级项目分类；选择其余三类时自动清空并禁用该列。
9. TMG及技术领域允许对应多个子领域。只有当前领域的唯一有效子领域为 `无` 时，业务表单才自动填写 `无` 并禁用修改。

## 9. tOS 版本显示规则

- `首销tOS版本` 和 `tOS版本-路标` 都按非空字符串保存，不再校验 `数字.数字` 或 `数字.数字.数字`。
- 用户在维护弹窗中填写版本主体，例如 `18.0` 或 `18.0.1`。
- 若用户输入了一个前导 `tOS`，保存时只去掉这一个前导，避免业务展示出现重复前缀。
- 配置表、业务下拉和业务展示统一显示为 `tOS` 加保存值，例如 `tOS18.0.1`。
- 已有业务值继续通过同一格式化函数展示。

## 10. 业务联动

### 10.1 通用读取规则

- 项目创建和编辑只把当前有效配置作为新选择项。
- 项目保存配置值的字符串快照，不保存配置行 ID 作为强引用。
- 编辑历史项目时，如果当前值已从配置中心删除，仍显示 `<旧值>（已停用）`，且允许不改该字段直接保存。
- 用户重新选择后，只能选择当前有效值。
- 配置中心修改或删除数据不批量更新、清空或阻止历史项目展示。

### 10.2 项目分类映射

项目新建选择 IPM 项目后：

1. 读取该项目的 `IPM项目分类`。
2. 在配置中心项目分类映射中按 `IPM项目分类` 精确查找。
3. 只读带出 `PMS项目分类`。
4. 当 PMS 分类为整机产品项目时，同时只读带出 `PMS二级项目分类`。
5. 当 PMS 分类为 `tOS版本项目`、`技术项目` 或 `能力建设项目` 时，不显示项目二级分类字段，提交校验也不要求二级分类。

如果 IPM 分类没有映射，项目分类保持空值，在字段旁和全局消息中提示 `该 IPM 项目分类尚未配置映射，请联系管理员维护`，并阻止提交。系统不得回退到硬编码猜测。

项目编辑时保留已保存的分类快照；由于项目名和 IPM 来源仍按原规则只读，不因配置映射后来变化而静默改写旧项目。

### 10.3 芯片映射

- 整机产品项目的新建和编辑以 `芯片编码` 为选择入口。
- 选中映射行后自动填写 `芯片型号` 和 `芯片平台`，后两项只读。
- 当同一芯片编码存在多行时，下拉选项显示完整组合，例如 `D6300 / MT6835 / MTK`，实际选择一条完整映射行。
- 用户重新选择芯片编码时，三个字段原子更新，避免型号与平台来自不同映射行。
- 旧项目中的未配置芯片组合继续显示为已停用快照。

### 10.4 TMG及技术领域与子领域

- 技术项目新建和编辑的 `TMG及技术领域` 选项取映射表中去重后的第一列，保持首次出现顺序。
- `子领域` 选项只显示当前领域对应的第二列，保持映射行顺序。
- 切换领域后，如果原子领域不再有效，则清空原值。
- 当前领域只有一个子领域且为 `无` 时，自动填写 `无` 并禁用修改；否则由用户单选。
- 配置不存在可用子领域时，显示 `暂无可用配置，请先在配置中心维护` 并阻止必填表单提交。

### 10.5 其余单字段配置

项目新建、编辑和 tOS 路标根据固定配置清单读取相应单字段值。当前字段若仍由 IPM 自动带出或按既有规则只读，则保留该读写归属；配置值用于允许用户选择的入口和编辑校验，不把只读字段改为可编辑。

硬编码数组只保留与本期 22 项无关的字段。属于本期清单的业务字段不得继续维护第二份选项数组。

## 11. 权限

- 枚举表对可进入配置中心的用户可见。
- 新增专用全局权限 `configCenter:enumEdit`，控制 22 类配置的新增、编辑和删除。
- `管理组` 默认拥有该权限；`编辑组` 和 `查看组` 默认无该权限；全局管理员仍按现有规则绕过检查。
- 无编辑权限时隐藏或禁用新增、编辑和删除操作，但仍可浏览配置值和应用范围。
- 权限中心的“配置中心”模块显示该权限，名称为 `枚举值新增、修改、删除`。

## 12. 错误与恢复

- 重复、缺失、条件字段错误均在弹窗对应输入框下显示明确原因。
- 删除目标已不存在时提示刷新后重试，不误删其他行。
- 本地存储写入失败时回滚内存中的本次变更，并保留当前表格内容。
- 水合失败继续显示当前枚举页的错误卡片、重试和重置入口。
- 必填业务字段没有可用配置时，选择控件显示空状态与维护指引，不使用静默的硬编码回退。

## 13. 可访问性与视觉质量

- 搜索框、表单输入和按钮都有可见标签或可访问名称。
- 图标按钮保留 Tooltip 和 `aria-label`；键盘可完成类型选择和 CRUD。
- 删除不只依赖红色表达危险含义，必须同时有删除文字或可访问名称与确认框。
- 表格序号使用等宽数字，列头与正文保持足够对比度。
- 焦点样式清晰，弹窗关闭后恢复焦点。
- 1440×900 桌面视口下外层不超出可用高度；窄屏无页面级横向溢出。

## 14. 验收

### 14.1 配置中心

- 左侧只有 22 个固定配置项，无“通用 / 人力资源管道”层级。
- 22 项名称、顺序、应用范围与第 5 节一致。
- 19 个单字段配置、1 个两列映射配置和 2 个三列映射配置显示正确列。
- 所有表格第一列为连续自增序号。
- 新增、编辑、删除、空状态、重复校验、删除确认、权限态正常。
- 左侧搜索只过滤配置项名称，不改变固定数据顺序。

### 14.2 项目分类

- 四种项目分类都能通过 IPM 项目分类映射带出。
- 只有整机产品项目显示并要求 PMS 二级项目分类。
- 非整机分类提交时不再被旧的“项目二级分类必填”校验阻断。
- 未映射 IPM 分类显示明确错误并阻止提交。

### 14.3 芯片与 TMG

- 芯片编码选择原子带出型号和平台。
- 同一芯片编码存在多个映射时可以通过完整组合正确区分。
- TMG 切换后子领域选项正确更新，旧子领域在失效时清空。
- 唯一子领域为 `无` 时自动填写并禁用修改。

### 14.4 历史与迁移

- 旧 tOS 两位和三位本地配置迁移后不丢失。
- 配置删除后已有项目仍显示旧值，并标记为已停用。
- 重新选择时只显示当前有效值。
- 重置本地配置可恢复 22 类初始 Mock 数据。

### 14.5 验证方式

- `npx tsc --noEmit`
- `npm run build`
- 浏览器验证 1440×900 桌面布局和窄屏单列布局。
- 浏览器逐项验证配置 CRUD、四类项目的新建与编辑、tOS 路标、历史旧值、权限用户切换和本地存储恢复。

## 15. 代码边界
