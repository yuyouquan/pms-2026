# 计划数据统一、tOS 路标芯片编码、TDT 交互与项目表单分组设计

## 1. 背景与目标

当前系统存在五类相互关联的问题：

1. tOS 版本项目空间的“三级计划-MR版本计划”与联合项目空间的“tOS&整机1+N项目计划”在页面上出现了不一致的 Mock 数据。
2. tOS 路标仍以“平台”为展示和录入字段，但业务要求使用“芯片编码”。
3. 技术项目中的 TDT 项目计划与整机产品项目一级计划的版本、编辑和视图交互不一致。
4. 项目列表仍能看到已经停用的项目状态，Mock 项目中也残留旧状态。
5. 项目新增和编辑弹窗没有稳定复用已经定义的字段分组，导致整机新增表单退化为无分组平铺。

本次目标是从数据源、交互壳层和字段 Schema 三个层面消除分叉，同时保持既有权限、校验、字段顺序和业务数据不被误删。

## 2. 已确认决策

- TDT 计划采用“完整对齐整机计划交互”的方案，但保留技术项目自身字段、TDT/子项目入口和业务数据结构。
- 顶部通用项目字段继续独立展示，业务字段按现有 Schema 分组。
- 停用状态按照业务语义迁移到当前启用状态。
- 采用共享领域数据源加页面适配器，不在不同页面复制同一份 Mock 数据。

## 3. 范围与非目标

### 3.1 本次范围

- tOS 三级计划与联合空间 MR 计划 Mock 数据统一。
- tOS 路标“平台”改为“芯片编码”，覆盖列表、详情、新增/编辑、导出和修改记录。
- TDT 项目计划版本及视图交互对齐整机一级计划。
- 项目状态 Mock 数据迁移及筛选项清理。
- 项目新增和编辑弹窗恢复字段分组。
- 本地缓存兼容迁移、规则级验证、浏览器验证及发布验证。

### 3.2 非目标

- 不把所有计划类型重构成一个大型通用组件。
- 不改变技术项目的计划任务模型、子项目配置规则或字段含义。
- 不调整已经确认的一级计划日期算法、权限矩阵和发布规则。
- 不删除数据库或后端字段；当前系统仍为前端 Mock。
- 不修改用户当前主工作区中的未提交内容。

## 4. 总体架构

### 4.1 MR 计划唯一数据源

`mrVersionPlan` Store 作为三级计划和联合计划的唯一运行时数据源：

```text
配置中心 MR 模板
        │
        ▼
mrVersionPlan.tosInstancesByProjectId
        ├── tOS 项目空间：按 projectId 直接展示 tOS 实例
        └── 联合项目空间：按 tOS 实例聚合对应整机项目
```

页面组件只负责选择、投影和显示，不再分别维护相同 tOS 版本号及日期的静态数组。

### 4.2 版本与缓存

- 更新 MR Store 的初始 Mock，使其同时覆盖正常日期、错误日期、锁定整机行和多个 tOS 版本。
- 提升持久化版本号并新增兼容迁移。
- 迁移时保留用户有效编辑；缺失的标准 Mock 记录按稳定业务键补齐。
- 稳定业务键使用 `tOS项目ID + tOS版本号`，整机聚合键继续使用 `整机项目ID + tOS版本号`。
- 同一 tOS 版本在项目空间和联合空间显示的 tOS 参考行、节点及日期必须完全一致。

## 5. 功能设计

### 5.1 tOS 项目空间与联合空间计划数据统一

#### 数据规则

- tOS 项目空间的三级计划行直接读取 `tosInstancesByProjectId[projectId]`。
- 联合空间先读取同一 tOS 实例，再根据首销/当前 tOS 版本与整机项目关系生成整机行。
- tOS 参考行只读；整机行按现有 SPM、版本项目经理和锁定规则编辑。
- 日期错误由现有校验器动态计算并标红，不额外增加“错误提示”列。
- 被锁定行继续显示锁图标；权限仍以对应 tOS 版本项目经理为准。

#### Mock 覆盖

- 至少两个 tOS 版本项目。
- 每个项目至少包含两个 tOS 版本号。
- 正常完整日期示例。
- 缺失但允许暂存的日期示例。
- 早于/晚于上下界的错误示例。
- 整机 1+N 类型为 `N/A`、普通数字类型的示例。
- 已锁定和未锁定整机行示例。

#### 一致性验收

从任意 tOS 项目空间进入三级计划，记录其版本号、任务节点和日期；进入联合空间后，对应 tOS 参考行必须逐项一致。

### 5.2 tOS 路标芯片编码

#### 字段变更

- 页面标签“平台”统一改为“芯片编码”。
- 路标领域对象使用 `chipCode` 表达业务字段。
- 旧 Mock 或旧缓存中的 `platform` 在迁移阶段映射到 `chipCode`，迁移完成后 UI 不再显示平台字段。

#### 新增/编辑交互

- “新增待规划项目”和编辑弹窗使用可搜索的芯片编码单选下拉。
- 选项读取配置中心“芯片编码/芯片型号/芯片厂商”映射枚举中的芯片编码。
- 没有可用枚举时禁用保存，并提示先在配置中心维护芯片编码。
- 芯片编码为必填；不允许用户输入任意平台文本。
- 编辑历史记录时，如旧值已停用，可显示历史值并标注“已停用”，但不能作为新建值。

#### 展示范围

- 表格视图。
- 卡片/演进视图中涉及平台的文案。
- 项目详情弹窗。
- 筛选与导出。
- 修改记录。

### 5.3 TDT 项目计划交互对齐

#### 保留内容

- `TDT项目计划` 与各子项目计划入口。
- 技术项目自己的阶段、节点和日期数据。
- TDT 与子项目的既有权限主体。

#### 对齐内容

- 默认视图顺序：横版表格、竖版表格、甘特图。
- 进入修订中版本后立即可编辑，不需要先切换版本。
- 统一自动保存状态、发布、取消修订、筛选、导出、版本对比和分享入口。
- 删除克隆功能。
- 删除一级计划中的字段配置按钮，不显示禁用占位。
- 管理员和普通项目角色都不能添加一级阶段。
- 甘特图不展示前置任务列。

#### 创建修订

- 以最新已发布的配置模板作为新修订表头和任务结构。
- 仅按“任务名”回填用户已经填写的时间，不再把大阶段作为匹配条件。
- 自定义任务（如 MR1、MR2）在其所属大阶段仍存在时自动保留。
- 如模板新增任务，历史已发布版本在该任务列显示 `-`。
- 如大阶段被删除，其下自定义任务不再保留。

#### 校验与权限

- 沿用整机一级计划相同的日期动态计算、父子范围校验、错误标红、提示和发布拦截。
- 空日期仍允许局部暂存，不因尚未填写而直接报错。
- 编辑、发布、取消修订、导出和分享继续使用项目计划权限判断。
- 仅修订中版本可编辑；已发布版本始终只读。

### 5.4 项目新增和编辑分组

#### 通用区域

顶部通用字段保持独立，不纳入折叠分组：

- 项目名。
- 项目分类。
- 项目责任人（适用时）。
- 健康状态（适用时）。

项目状态仍按已定义业务字段位置展示，并读取配置中心枚举。

#### 分组定义

| 项目类型 | 分组顺序 |
| --- | --- |
| 整机产品项目 | 基础信息、扩展信息、团队信息 |
| tOS 版本项目 | 基础信息、团队信息 |
| 技术项目 | 技术信息、团队人员、交付物 |

新增和编辑必须调用同一分组解析与渲染逻辑，字段顺序直接使用 Schema 中的有序定义。

#### 交互规则

- 默认展开第一个有字段的业务分组，其余分组折叠。
- 用户可展开多个分组。
- 分组标题展示名称和当前有效字段数量。
- 条件字段不满足展示条件时，不计入数量。
- 校验失败时自动展开错误字段所在分组，滚动到字段并显示原校验文案。
- 草稿恢复时恢复上次展开状态；无记录时使用默认展开规则。
- JIRA 项目保持扩展信息最后一项，编辑器跨整行展示。
- 不改变字段必填、只读、枚举来源、联动和提交数据结构。

### 5.5 项目状态清理

#### 启用状态集合

| 项目类型 | 启用状态 |
| --- | --- |
| 整机产品项目 | 待立项、在研、上市、EOS、转维、已取消、已暂停 |
| tOS 版本项目 / 能力建设项目 | 在研、已完成 |
| 技术项目 | 进行中、已完成、暂停、已取消 |

#### 旧状态迁移

| 项目类型 | 旧状态 | 新状态 |
| --- | --- | --- |
| 整机 | 暂停 | 已暂停 |
| 整机 | 规划中、筹备中 | 待立项 |
| tOS / 能力建设 | 未完成语义的其他旧状态 | 在研 |
| tOS / 能力建设 | 完成语义的其他旧状态 | 已完成 |
| 技术项目 | 在研、筹备中 | 进行中 |
| 技术项目 | 已迁移、EOS | 已完成 |

#### 筛选规则

- 快捷状态筛选只从当前项目类型的启用状态集合生成。
- 不再拼接数据中发现的未知状态。
- 高级筛选中的项目状态选项也使用同一集合。
- Mock 初始化和旧本地缓存迁移完成后不得存在停用状态。

## 6. 错误处理与兼容

- 枚举尚未加载：芯片编码和项目状态字段显示加载/不可用状态，不允许提交无效值。
- MR Store 迁移异常：回退到新的标准 Mock，避免空白页。
- 找不到对应 tOS 实例：联合空间显示明确空态，指向 tOS 项目三级计划，不生成伪日期。
- 权限不足：隐藏或禁用编辑动作，数据仍可只读查看。
- 已存在的表单草稿：按字段键恢复，再按当前 Schema 重新分组，不丢弃仍有效字段。

## 7. 测试与验证

### 7.1 规则级验证

- MR 初始状态包含预期项目、版本、错误与锁定样例。
- 同一 tOS 实例经项目空间选择器和联合空间选择器得到相同节点和日期。
- 旧 Roadmap `platform` 正确迁移为 `chipCode`。
- 各项目类型停用状态映射正确，筛选选项不包含停用状态。
- 新增和编辑表单对同一项目类型返回相同分组顺序。
- TDT 创建修订按任务名回填，新增任务在旧发布版本显示 `-`。

### 7.2 静态验证

- `npx tsc --noEmit`
- `npm run build`

### 7.3 浏览器验证

1. tOS 项目空间与联合空间逐行核对版本号、任务和日期。
2. tOS 路标列表、详情、新增、编辑、筛选和导出确认“芯片编码”。
3. TDT 修订中版本首次进入即可编辑；三种视图及工具栏行为一致。
4. 整机、tOS、技术项目分别打开新增和编辑弹窗，核对分组、顺序、必填和校验定位。
5. 项目列表切换项目类型，确认状态筛选及 Mock 卡片/列表无停用状态。

## 8. 发布与回滚

- 所有开发在独立 worktree 和 `codex/` 分支完成。
- 验证通过后提交并推送到 `dev`。
- `dev` 验证无误后合入主干并推送。
- 发布 Vercel 后对生产地址执行关键路径复核。
- 若线上出现回归，以本次独立提交为最小回滚单元，不操作用户主工作区中的未提交内容。

## 9. 验收标准

- 两个空间的 tOS MR 计划数据完全一致。
- tOS 路标中不再出现“平台”录入或展示，统一为芯片编码。
- TDT 计划具备整机一级计划同等版本和视图交互。
- 所有项目新增/编辑弹窗恢复正确分组，字段及规则无缺失。
- 项目列表和筛选中没有停用状态，Mock 状态均为当前启用值。
- 类型检查、正式构建、浏览器验证、远端分支和 Vercel 线上检查均通过。
