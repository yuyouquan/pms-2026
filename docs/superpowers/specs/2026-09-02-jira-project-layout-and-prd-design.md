# JIRA 项目布局与项目管理 PRD 飞书化设计

## 1. 背景与目标

整机产品项目的 JIRA 项目在不同入口存在展示和编辑能力不一致的问题：项目空间展示态排版不符合最新 UI，项目新建/编辑入口缺少“共库”和“Affect Projects”。本次同时把已有的项目管理需求从零散本地资料整理为一份可评审的飞书文档《项目管理-一级计划+三级计划+配置中心PRD》；文档必须包含字段、限制、权限、交互、异常和验收说明，并使用真实页面截图及飞书画板。

## 2. 范围

### 2.1 本次代码范围

- 整机产品项目的项目空间基础信息——扩展信息——JIRA项目展示态。
- 整机产品项目新建弹窗、项目编辑弹窗及项目空间基础信息编辑态中的 JIRA 项目编辑器。
- JIRA 行级校验、条件必填、复制、删除与数据归一化。
- 对应 Mock 数据、自动化契约和浏览器验收证据。

### 2.2 PRD 范围

- 一级计划。
- 三级计划与联合项目空间的 tOS&整机1+N项目计划。
- 配置中心。
- 项目列表、字段配置与筛选。
- 新建项目与项目空间字段。
- 本次 JIRA 项目展示/编辑规则。

### 2.3 非目标

- 不接入真实 JIRA 服务或动态拉取 JIRA 库。
- 不改变现有 JIRA 服务器、库名、类型和 Affect Projects 的 Mock 选项来源。
- 不调整非整机产品项目的字段顺序或页面功能。
- 不删除或重排扩展信息中的其他字段。

## 3. 方案选择

采用统一 JIRA 表格编辑器方案。新建、编辑和项目空间编辑复用同一套组件、校验与数据更新逻辑，避免入口间再次出现字段缺失。

未采用的方案：

- 分别修改各入口：实现直接，但字段和校验容易再次分叉。
- 建设通用动态表格引擎：扩展性较高，但明显超出本次范围。

## 4. 展示态设计

- `JIRA项目` 固定为扩展信息最后一个字段，并独占整行。
- 该行采用左右布局：左侧为标题 `JIRA项目`，右侧紧跟 JIRA 链接标签，不使用上下布局。
- 左侧标题沿用基础信息字段标题的字号、字重和颜色；右侧内容左对齐。
- 多条链接标签从左到右排列，空间不足时自然换行。
- 无数据时右侧显示 `-`。
- 标签保持可点击，使用既有 JIRA URL 生成规则并在新窗口打开。

## 5. 编辑态设计

### 5.1 列定义

| 顺序 | 字段 | 控件 | 必填 | 规则 |
|---|---|---|---|---|
| 1 | JIRA服务器 | 可搜索下拉 | 是 | 使用现有 JIRA 服务器选项。 |
| 2 | JIRA库名 | 可搜索下拉 | 是 | 使用现有 JIRA 项目/库名选项。 |
| 3 | 类型 | 下拉 | 是 | 使用现有 `sw`、`monkey` 选项。 |
| 4 | 共库 | Switch | 是 | 布尔值；控制 Affect Projects 是否可编辑、是否必填。 |
| 5 | Affect Projects | 可搜索下拉 | 条件必填 | 共库为是时启用且必填；共库为否时保留展示、禁用并清空旧值。 |
| 6 | 操作 | 图标按钮 | 否 | 支持复制、删除；按钮有 Tooltip 和无障碍名称。 |

### 5.2 行与保存规则

- JIRA 项目整体选填；没有 JIRA 行时允许创建或保存项目。
- 用户一旦新增 JIRA 行，该行的 JIRA服务器、JIRA库名、类型必须完整。
- 共库为是时，Affect Projects 必填；为空时阻止保存。
- 共库从是切换为否时，立即清空 Affect Projects，并保持该控件禁用。
- 复制操作生成新行 ID，并复制服务器、库名、类型、共库和 Affect Projects 当前值。
- 删除操作仅删除当前行；删除全部行后回到无 JIRA 配置状态。
- 校验失败时不提交半完整数据，显示具体行号和缺失字段，并把错误行滚动/聚焦到可见区域。
- 保存前统一执行 trim、空值和条件必填校验；历史数据缺少新字段时按 `共库=false、Affect Projects=''` 安全迁移。

### 5.3 响应式

- 桌面端保持六列表头与数据行对齐。
- 窄屏不压缩到不可操作；编辑表格允许横向滚动，并保留操作列可见性。

## 6. 数据与权限

- 继续使用 `JiraProjectConfig` 作为唯一数据结构：`id / server / projectKey / type / shared / affectProjects`。
- 展示、创建、编辑和保存共享同一归一化/校验函数。
- 新建权限沿用现有项目创建权限。
- 编辑权限沿用现有 `basicInfo:编辑` 权限；无权限用户仅可查看链接，不能增删改 JIRA 行。
- 字段配置仅控制 JIRA 项目整块显示或隐藏，不拆分控制内部列。

## 7. PRD 飞书文档设计

### 7.1 交付物

- 本地源文档：`docs/prd/项目管理-一级计划+三级计划+配置中心PRD.md`。
- 飞书文档：《项目管理-一级计划+三级计划+配置中心PRD》。
- 飞书画板至少覆盖：计划版本生命周期、三级计划数据/时间约束、联合计划映射与锁定权限、项目创建和 JIRA 条件校验。

### 7.2 文档结构

1. 文档信息、老板口径、背景与目标。
2. 角色和权限矩阵。
3. 项目列表、字段配置和筛选。
4. 新建项目与项目空间字段字典。
5. 一级计划字段、版本、视图、编辑与校验。
6. 三级计划及 tOS&整机1+N项目计划字段、映射、锁定和异常提示。
7. 配置中心枚举、映射关系和维护权限。
8. JIRA 项目字段及条件必填。
9. 状态流转、异常/空状态、数据兼容与审计边界。
10. 验收场景、风险和待确认项。

### 7.3 截图与画板规则

- 每个一级功能至少附一张实际系统截图，截图来自最终实现后的本地或生产页面。
- 截图必须对应正文中的功能编号并配图注，避免只贴图不说明。
- 需要表达流程、状态变化、数据来源或权限分支时使用飞书画板，不用静态文字替代。
- 画板嵌入对应章节附近，而不是统一堆在文档末尾。
- 飞书文档完成后重新读取正文和资源列表，检查章节、表格、图片、画板、标题层级和链接。

## 8. 验收标准

1. 项目空间展示态 JIRA 项目位于扩展信息最后一行，标题在左、内容在右，多条链接自然换行。
2. 新建、编辑和项目空间编辑均显示六列 JIRA 表格，字段和顺序完全一致。
3. 缺少服务器、库名或类型时阻止保存并明确提示。
4. 共库为是且 Affect Projects 为空时阻止保存。
5. 共库关闭后 Affect Projects 仍显示但禁用，旧值立即清空。
6. 复制和删除只作用于目标行，复制后的 ID 唯一。
7. 无基础信息编辑权限时不出现编辑操作。
8. 类型检查、生产构建、相关契约和真实浏览器交互全部通过。
9. `dev` 包含功能提交，`master` 包含 `dev`，Vercel 生产部署成功且线上页面复核通过。
10. 飞书 PRD 包含全部约定章节、字段说明、填写限制、权限、交互、实际截图和所需画板，复读检查无遗漏。

## 9. 已确认决策

- 采用统一编辑器方案。
- 展示态为左右布局，标题居左、内容紧随其后。
- JIRA 项目整体选填，新增行后执行行级必填校验。
- 共库关闭时 Affect Projects 保留显示但禁用，并清空旧值。
- 完成后发布至 `dev`，合并 `master` 并发布 Vercel。
