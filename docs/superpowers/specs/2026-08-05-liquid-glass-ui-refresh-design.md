# PMS 全界面结构化浅紫液态玻璃优化设计

日期：2026-08-05
状态：已确认，待实施
分支：`codex/feature-liquid-glass-ui-refresh`
基线：`origin/dev` at `eed749d`

## 1. 背景

PMS 已经形成以 Next.js、React、Ant Design、Zustand 和 Tailwind 为基础的企业项目管理前端，当前覆盖工作台、独立项目列表、项目视图、项目空间、配置、权限、转维以及计划分享等页面。现有界面已经使用紫色玻璃拟态，但不同开发阶段形成了大量分散的颜色、渐变、圆角、阴影和内联样式，页面之间的材质强度、信息密度和交互状态不一致。

本次改造对全部现有界面进行视觉统一。功能、字段、文案、信息架构、权限、状态和交互行为保持不变。目标不是重新设计产品结构，而是建立一套可持续维护的结构化浅紫液态玻璃视觉系统，并将其一致地落到所有现有页面。

## 2. Taste-Skill 设计判断

### 2.1 Design Read

这是面向企业研发项目管理人员的高信息密度产品界面，需要在长时间阅读、复杂表格操作和品牌辨识度之间取得平衡。视觉语言采用克制、明亮、精致的结构化浅紫液态玻璃，继续使用现有 Ant Design 组件体系。

### 2.2 设计参数

- `DESIGN_VARIANCE: 4`：保持稳定、可预测的企业后台结构，只在层级和局部构图上增加精致度。
- `MOTION_INTENSITY: 3`：仅使用悬停、按压、焦点和浮层过渡，不增加自动播放或装饰性动效。
- `VISUAL_DENSITY: 8`：保留现有高密度数据能力，不为了视觉效果扩大控件或减少可见信息。

### 2.3 方案选择

已比较三种方向：

1. 沉浸玻璃：玻璃覆盖率高，品牌辨识强，但会降低表格和计划页面的持续阅读效率。
2. 结构化玻璃：外壳、导航、工具区和浮层体现玻璃材质，数据表面保持清晰，最终选定。
3. 轻量清透：最克制，但不足以体现用户要求的液态玻璃品牌特征。

选定方案将玻璃视为表达层级关系的材料，不把模糊、透明和光晕铺满每一个数据单元。

## 3. 设计目标

1. 统一全部现有界面的品牌紫色、材质、排版、间距、圆角、阴影和交互状态。
2. 保留高密度表格、计划、甘特图、权限矩阵和复杂表单的清晰度。
3. 让相同语义的组件在不同模块中保持同样外观和状态反馈。
4. 删除或收敛散落在组件内的视觉常量，形成语义 Token 和共享样式类。
5. 保持现有功能、交互、路由、字段、文案、权限与状态流完全不变。
6. 为减少动效和减少透明度偏好提供安全降级。

## 4. 非目标

- 不改变导航层级、路由地址或模块入口。
- 不新增、删除或重排业务字段。
- 不修改按钮文字、表单文案、状态文案或法律提示。
- 不修改 Zustand store、业务数据结构、Mock 数据和持久化键。
- 不修改权限键、角色规则、权限绕过、编辑保护和离开确认。
- 不改变表格固定列、列设置、筛选同步、横向滚动和全屏逻辑。
- 不改变计划版本、修订发布、日期校验、市场维度和技术项目作用域。
- 不改变转维流程及离开项目空间时的转维状态重置。
- 不引入第二套组件库，不迁移到 Fluent、Carbon、Material 或其他设计系统。
- 不新增自动播放、磁吸、视差、滚动劫持和装饰性循环动画。
- 不建设暗色主题。本次保持现有浅色产品主题。

## 5. 颜色系统

### 5.1 品牌紫色

用户提供的参考图使用明亮蓝紫到柔和薰衣草紫的横向过渡。本次锁定以下 Web 近似色：

- 强紫：`#5D49F6`
- 主紫：`#7562FF`
- 柔紫：`#AD98EE`
- 浅紫底：`#F5F3FF`
- 浅紫边：`#DCD6FF`

顶部品牌面使用：

```css
linear-gradient(106deg, #5d49f6 0%, #7562ff 50%, #ad98ee 100%)
```

该渐变是全系统唯一品牌渐变。正文区域不引入另一套深靛紫或蓝紫渐变。

### 5.2 中性色

统一使用偏冷的紫灰中性色，避免冷灰和暖灰混用：

- 主文本：`#27243A`
- 次文本：`#625D70`
- 辅助文本：`#817B90`
- 禁用文本：`#AAA5B5`
- 页面底色：`#F4F6FB`
- 实体表面：`#FFFFFF`
- 分隔线：`#E6E3EF`

### 5.3 语义色

浅紫是唯一品牌强调色。红、黄、绿、蓝只用于已有业务语义，例如错误、警告、成功、信息和项目状态。语义色不参与装饰性渐变，不与品牌紫争夺主操作层级。

### 5.4 对比度

- 正文和表格内容达到 WCAG AA 4.5:1。
- 大号文字和图形控件达到 3:1。
- 主按钮白色文字在全部渐变区间保持可读。
- 占位文字、禁用文字、表单标签和错误信息分别检查对比度，不以透明度代替颜色设计。

## 6. 材质与层级

### 6.1 玻璃表面

玻璃只用于表达悬浮、外壳或工具层级：

- 顶部导航与项目空间顶部栏。
- 页面级筛选区、视图切换区和工具栏。
- 侧栏与右侧辅助导航。
- 弹窗、下拉菜单、Popover、Tooltip 和锚定浮层。
- 工作台统计摘要和非数据型概览卡片。

建议基线：

- 背景白色透明度 72%-78%。
- `backdrop-filter: blur(14px) saturate(145%)`。
- 1px 亮色外边框。
- 1px 顶部内高光。
- 低透明紫色投影。

### 6.2 实体数据表面

以下区域使用白色或浅紫灰实体表面，不叠加大面积模糊：

- 表格正文、表头和固定列。
- 一级计划、二级计划、横版计划和甘特图。
- 权限矩阵和成员配置表格。
- 复杂表单、编辑单元格和日期输入。
- 版本对比结果和差异单元格。
- 日历网格和时间轴主体。

实体表面通过细边框、浅色表头、轻微紫色投影和行悬停表达层级。

### 6.3 透明度降级

在 `prefers-reduced-transparency: reduce` 下：

- 关闭 `backdrop-filter`。
- 玻璃面替换为 96%-100% 不透明实体表面。
- 保留边框、层级和对比度。
- 不依赖背景模糊才能看清文本或控件。

浏览器不支持该媒体查询时，默认背景仍保持足够不透明。

## 7. 形状、阴影与间距

### 7.1 圆角系统

- 页面大容器和主面板：16px。
- 普通卡片和区块：12px。
- 输入框、按钮、工具按钮和小面板：8px。
- 状态标签、分类标签和用户胶囊：999px。

业务组件允许继承现有特殊形状，但同一组件家族不得出现随机 6px、8px、10px、12px 和 16px 混用。

### 7.2 阴影系统

- 页面级浮层使用低透明紫色中等投影。
- 普通卡片使用轻投影或无投影，以边框和间距分组。
- 悬停只提升一档阴影并轻微上移 1px。
- 不使用纯黑重投影、霓虹外发光和大范围紫色光晕。

### 7.3 间距系统

基于 4px 网格统一为 4、8、12、16、20、24、32px。高密度页面默认使用 8-16px 内间距，页面级容器使用 20-24px。不得为了玻璃效果扩大表格行高或破坏当前每屏信息量。

## 8. 字体与图标

### 8.1 字体

使用系统中文无衬线字体栈：

```css
-apple-system, BlinkMacSystemFont, "SF Pro Text", "Segoe UI",
"PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", sans-serif
```

不再强制加载仅覆盖拉丁字符的 Inter。标题通过字重和颜色建立层级，不使用超大字号、渐变文字或衬线字体。

### 8.2 图标

继续使用现有 `@ant-design/icons`，不混入第二套图标库。统一常用图标尺寸、线条视觉重量、按钮间距和禁用颜色，不绘制自定义 SVG 图标。

## 9. 动效与交互状态

### 9.1 动效范围

- 悬停：150-200ms。
- 按压：轻微下移或缩放到 0.98，100-150ms。
- 浮层、弹窗和下拉：透明度加 4-8px 位移，180-250ms。
- 焦点：边框和焦点环过渡，150ms。

只动画 `transform` 和 `opacity`，不动画表格宽高和布局位置。

### 9.2 减少动效

在 `prefers-reduced-motion: reduce` 下取消位移、缩放、呼吸和循环动画，仅保留即时状态切换。现有交互时序和焦点恢复不受影响。

### 9.3 状态完整性

统一正常、悬停、按压、焦点、选中、禁用、加载、空状态和错误状态。视觉调整不得新增状态分支，也不得让禁用控件看起来可操作。

## 10. 组件架构

### 10.1 Ant Design 主题入口

在根 `ConfigProvider` 中配置共享主题 Token，包括品牌主色、字体、圆角、控件高度、焦点色、背景色和边框色。独立路由使用相同主题入口，避免页面各自维护一套颜色。

### 10.2 CSS 语义 Token

`src/styles/globals.css` 建立 `--pms-*` 语义 Token：

- 品牌与语义颜色。
- 页面、玻璃、实体和浮层表面。
- 文本与边框层级。
- 圆角、间距、阴影、模糊和动效。
- z-index 层级。

现有 Token 可暂时保留为别名，调用方迁移后再删除冗余定义，避免一次性破坏所有页面。

### 10.3 共享样式类

建立或统一以下视觉类：

- `pms-page-shell`
- `pms-topbar`
- `pms-glass-surface`
- `pms-solid-surface`
- `pms-toolbar`
- `pms-sidebar`
- `pms-section`
- `pms-table`
- `pms-modal`
- `pms-popover`
- `pms-empty-state`
- `pms-interactive-surface`

类名只表达视觉语义，不承载业务条件和事件逻辑。

### 10.4 内联样式迁移

组件中的事件处理、尺寸计算、定位和数据驱动样式保持原样。仅迁移重复出现的颜色、圆角、阴影、背景和视觉过渡。必须保留：

- `onClick`、`onChange`、`onMouseEnter` 等处理函数。
- Zustand store 读取与写入。
- Ant Design 组件 props 和表格列定义。
- `SortableRow` 的 props 转发顺序。
- 固定列、滚动宽度、行键和单元格校验类。

## 12. 响应式与尺寸

产品保持桌面优先，验证宽度为 1024、1440 和 1920px：

- 1024px 下压缩导航间距和非关键空白，不改变导航顺序。
- 顶部导航保持单行，按钮文字不换行。
- 表格继续横向滚动，固定列行为不变。
- 侧栏宽度和折叠行为保持现状。
- 弹窗和 Popover 最大宽度不超过视口，内部内容按现有规则滚动。
- 不为本次视觉优化新增移动端业务布局。

## 13. 数据、权限与错误边界

本次没有新的数据流和业务错误处理。必须保留：

- 数据为空时现有空状态语义和操作入口。
- 加载失败、表单校验、计划日期错误和权限不足的现有判断。
- 计划无版本、技术子项目待配置、转维状态异常等现有边界。
- 错误单元格的红色提示、原因 Tooltip 和发布阻止。
- 权限不足按钮的位置、禁用状态和原因提示。

只统一这些状态的表面、图标、间距和对比度，不修改触发条件和恢复路径。

## 15. 验收标准

### 15.1 视觉一致性

- 所有页面使用同一品牌渐变和浅紫衍生色。
- 玻璃只出现在外壳、工具和浮层层级。
- 数据密集区域保持白色实体表面和清晰边界。
- 圆角、阴影、字体、间距和状态样式符合本设计。
- 不出现深靛紫与参考亮紫并存、黑色重投影、霓虹光晕和随机渐变。

### 15.2 行为不变

- 所有按钮、标签、筛选、视图切换和弹窗行为与基线一致。
- 项目列表分类、固定列、卡片、日历和全屏不回归。
- 工作跟踪和待办中心不回归。
- 项目空间导航、市场切换、技术作用域和编辑保护不回归。
- 计划版本、修订发布、日期校验、导入导出、分享和版本对比不回归。
- 权限门禁、全局管理员绕过和用户切换不回归。
- 转维页面切换和项目导航时的状态重置不回归。
- 三个独立路由继续正常渲染和操作。

### 15.3 可访问性与性能

- 主文本、按钮、输入、错误和占位文本达到目标对比度。
- 键盘焦点清晰且不被玻璃边框覆盖。
- 减少动效和减少透明度降级有效。
- 不新增滚动监听、持续动画和大面积滚动容器模糊。
- 不改变图片、字体或脚本加载路径，不引入新的大型前端依赖。
