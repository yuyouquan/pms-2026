# 项目列表筛选、字段矩阵与一级计划交互统一设计

## 1. 背景与目标

本次迭代统一项目列表快捷筛选、列表字段顺序与默认显隐、系统筛选条件以及一级计划视图入口，并完成联合项目空间计划名称更新。

目标：

1. 在项目状态下方增加按项目类型动态变化的快捷筛选行。
2. 严格按业务清单调整整机产品项目、技术 TDT 项目列表字段顺序和默认显隐。
3. 将“里程碑”作为字段配置中的整体块，拖动和显隐时整体联动。
4. 统一全系统文本、枚举筛选条件，日期筛选保持现有规则。
5. 一级计划默认视图顺序改为横版、竖版、甘特图，并移除一级计划字段配置入口。
6. 将用户界面的“tOS&整机MR版本计划”统一改名为“tOS&整机1+N项目计划”。

本次不改变项目数据结构、权限规则、计划版本规则和日期业务校验。

## 2. 项目列表筛选区

### 2.1 位置和共享状态

快捷筛选行固定显示在“项目状态”下一行。筛选状态与高级筛选共用同一份条件数据，列表、卡片、日历和全屏视图共享筛选结果。切换项目分类或技术项目类型时，移除当前类型不可用的条件，保留仍有效的条件。

### 2.2 整机产品项目

快捷筛选顺序：

1. 项目名称：单行文本，模糊搜索；
2. 首销tOS版本：可搜索多选；
3. 芯片编码：可搜索多选；
4. 品牌：可搜索多选；
5. 产品系列：可搜索多选；
6. 产品类型：可搜索多选。

### 2.3 tOS 版本项目

仅显示“项目名称”单行文本模糊搜索。

### 2.4 技术项目

保留独立的“项目类型：TDT项目 / 子项目”切换行，下一行动态显示：

- TDT 项目：项目名称、技术赛道、项目阶段；
- 子项目：子项目名称、项目阶段。

项目名称和子项目名称为单行文本模糊搜索；技术赛道、项目阶段为可搜索多选。

## 3. 项目列表字段矩阵

### 3.1 字段配置原则

- 字段顺序由项目类型唯一矩阵定义，表格与字段配置共同读取该矩阵。
- “默认显示”与“是否允许隐藏”分离。默认显示为“是”的字段首次进入时显示，但用户仍可在字段配置中隐藏。
- 默认不显示字段仍在字段配置中，可以开启、隐藏和排序。
- 对受影响的项目列表字段设置增加版本迁移，使新默认顺序和显隐立即生效；其他页面配置不受影响。

### 3.4 里程碑整体块

字段配置中将当前计划模板派生出的全部里程碑列显示为一个“里程碑”配置块：

- 拖动“里程碑”时，所有阶段和活动列整体移动；
- 隐藏或显示“里程碑”时，所有里程碑列整体隐藏或显示；
- 表格内仍保留阶段分组表头和节点明细；
- 阶段及节点内部业务顺序不可通过项目列表拖动改变。

## 4. 全系统筛选条件

### 4.1 文本字段

条件为：等于、不等于、包含、不包含、为空、不为空。默认条件为“包含”。

### 4.2 枚举字段

条件与文本字段一致，默认条件为“包含”：

- 等于、不等于：下拉单选；
- 包含、不包含：下拉可搜索多选；
- 包含：实际值命中任意一个已选项即通过；
- 不包含：实际值不命中全部已选项才通过；
- 为空、不为空：不显示值输入控件。

### 4.3 日期字段

保持现有日期筛选规则和默认条件：等于、不等于、早于、晚于、为空、不为空，默认“等于”。

### 4.4 条件组合与兼容

- 多条筛选条件继续使用“且”关系；
- 旧的 `equalsAny` / “任一为”条件迁移为新的枚举“包含”多选；
- 切换字段类型时自动选择该类型合法的默认条件，并清理不兼容的旧值；
- 统一规则覆盖项目列表、一级/三级计划、项目路标及其他复用现有筛选条件组件的页面。

## 5. 一级计划交互

- 视图切换顺序调整为：横版表格、竖版表格、甘特图；
- 仅移除一级计划工具栏的“字段配置”入口；
- 横版、竖版、甘特图本身的数据、编辑能力和权限判断不变；
- 二级计划、三级计划以及其他独立业务表格的字段配置入口不受影响。

## 6. 名称更新

所有用户可见的“tOS&整机MR版本计划”改为“tOS&整机1+N项目计划”，覆盖：

- Header / TAB / 页面标题；
- 按钮、弹窗、空状态和提示文案；
- Mock 数据中的用户可见名称；
- 自动化校验中的新文案断言。

历史设计文档和 Git 提交记录不做批量改写。

## 7. 验证范围

1. 整机、tOS、技术 TDT、技术子项目分别验证快捷筛选字段、顺序、输入类型和视图联动。
2. 验证整机和技术 TDT 字段默认顺序、默认显隐、用户隐藏、恢复和拖动。
3. 验证里程碑整块拖动、整体显隐以及内部顺序不变。
4. 在文本、枚举、日期字段上逐项验证操作符、默认值和输入控件形态。
5. 验证旧筛选条件兼容、空值规则和多条件“且”关系。
6. 验证一级计划视图顺序和字段配置入口移除边界。
7. 全局搜索并浏览器检查新计划名称。
8. 执行仓库契约脚本、`npx tsc --noEmit`、`npm run build` 和真实浏览器验证。
