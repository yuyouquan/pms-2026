# 一级计划平铺列表、动态节点与甘特图交互设计

## 1. 背景与目标

本次调整统一项目空间中整机产品、tOS 产品、技术项目 TDT 项目计划和技术子项目计划的列表与甘特图口径。

目标如下：

1. 整机、tOS 和 TDT 的一级计划列表取消树形展示，改为每个里程碑独立一行的平铺表格。
2. 技术子项目继续使用单层活动结构，列表直接显示“活动名称”，不增加“阶段/里程碑点”两列。
3. 模板来源节点保持结构锁定，只开放明确允许的自动编号节点新增与删除。
4. 甘特图区分阶段、里程碑和技术子项目活动：阶段锁定，里程碑以点拖动，子项目活动以时间条移动或拉伸。
5. 版本历史与版本对比使用当前计划类型对应的新列表结构，不再回退到树形活动名称视图。

## 2. 范围

### 2.1 纳入范围

- 项目空间整机产品项目的一级计划。
- 项目空间 tOS 版本项目的一级计划。
- 技术项目空间的 TDT 项目计划。
- 技术项目空间的技术子项目计划。
- 上述计划的修订版本、最新发布版本、历史版本和版本对比。
- 配置中心技术子项目计划的内置 Mock 模板。
- 共享甘特图组件的逐任务类型与逐任务只读能力。

### 2.2 不纳入范围

- 二级计划、三级计划及其模板。
- 一级计划横版表格的视觉重做；横版继续使用当前逻辑。
- 分享链接页面的独立视觉重做。
- 后端数据库或 Feishu 通知接入。
- 模板编辑器自身的层级编辑交互重构。

## 3. 最终确认口径

后续确认覆盖最初提出的“隐藏甘特图”描述，最终规则为：

- 整机产品、tOS 产品、TDT 项目计划和技术子项目计划都保留甘特图。
- 整机、tOS、TDT 的阶段不能拖动或拉伸；里程碑以一个可拖动时间点展示。
- 技术子项目只有一级活动，甘特图以有开始和结束时间的活动条展示。
- 技术子项目列表直接使用“活动名称”，不显示“阶段”和“里程碑点”。

## 4. 数据模型与投影策略

采用“保留层级数据、按视图投影”的方案，不迁移现有版本数据结构。

### 4.1 整机、tOS、TDT

底层继续保存一级活动和二级活动：

- 一级活动：阶段。
- 二级活动：里程碑点。

列表投影时只生成里程碑行：

- `阶段` 取父级一级活动名称。
- `里程碑点` 取当前二级活动名称。
- `序号` 按最终可见里程碑顺序连续生成 `1、2、3…`，不使用底层 `1.1、1.2`。
- 相同阶段在每一条里程碑行中重复显示，不合并单元格。
- 搜索、筛选、导出和版本对比使用相同的投影结果，单行始终携带完整阶段信息。

平铺列表固定业务列为：

1. 序号
2. 阶段
3. 里程碑点
4. 状态
5. 计划完成时间
6. 计划开发周期
7. 实际完成时间
8. 实际开发周期
9. 操作（仅存在可删除自定义节点时显示按钮）

里程碑仍保留底层计划开始、实际开始和周期字段。列表不展示开始时间；计划/实际周期沿用现有任务时间口径，并在结束时间通过列表或甘特图变化时根据对应开始、结束时间重新计算。阶段时间继续由里程碑聚合，不允许直接写入。

### 4.2 技术子项目

技术子项目保持单层活动数组，每个活动直接生成一行，不制造虚拟父阶段或里程碑层级。

列表业务列为：

1. 序号
2. 活动名称
3. 状态
4. 计划开始时间
5. 计划完成时间
6. 计划周期
7. 实际开始时间
8. 实际完成时间
9. 实际周期
10. 操作（仅自定义转测版本显示删除按钮）

技术子项目修订中可填写计划开始时间、计划完成时间、实际开始时间和实际完成时间。最新已发布版本继续按照现有权限仅开放实际时间维护；历史版本全部只读。

## 5. 模板与结构权限

### 5.1 通用锁定规则

`source: 'template'` 的节点在项目计划中一律：

- 不可新增子节点。
- 不可删除。
- 不可改名。
- 不可拖拽排序。

整机和技术子项目的自动新增节点使用 `source: 'custom'`，但本次只开放删除：

- 名称由系统生成，不可编辑。
- 顺序由系统插入，不可拖拽。
- 可在修订版本中二次确认后删除。

tOS 和 TDT 不提供任何结构新增、删除或改名入口。

### 5.2 技术子项目模板

配置中心内置 Mock 模板固定改为：

1. 第1版转测
2. 第2版转测
3. TDR3

删除原模板中的“第X版转测”。模板任务继续使用稳定 ID；创建首次修订时按现有模板同步规则初始化，历史已发布版本不被回写修改。

## 6. 自动新增节点

### 6.1 整机上市阶段 MR 里程碑

仅满足以下条件时显示“添加上市阶段 MR 里程碑”：

- 当前项目是整机产品项目。
- 当前版本是修订中。
- 当前用户具备一级计划维护权限。
- 当前计划不是跟随市场只读计划。
- 计划中存在上市阶段；识别兼容稳定 ID 以及“上市阶段/上市收编阶段”名称。

点击后弹出二次确认，不提供名称输入框。确认后：

- 扫描上市阶段下名称严格匹配 `MR数字` 的节点。
- 下一编号为 `max(3, 当前最大 MR 编号) + 1`，因此模板只有 MR1、MR2 时首次生成 MR4，再次生成 MR5。
- 新节点加入上市阶段的里程碑序列末尾。
- 新节点结构来源标记为 `custom`，名称固定，仅显示删除操作。
- 删除节点不会重排其他 MR 名称；再次新增基于当前仍存在的最大编号计算。

若不存在上市阶段、生成名称重复或计划状态已变化，则不修改数据并显示明确提示。

### 6.2 技术子项目转测版本

仅在技术子项目修订版本且用户具备维护权限时显示“添加转测版本”。点击后弹出二次确认，不提供名称输入框。

确认后：

- 扫描名称严格匹配“第数字版转测”的活动。
- 使用当前最大编号加一，因此初始模板首次生成“第3版转测”，再次生成“第4版转测”。
- 新活动始终插入 `TDR3` 前；`TDR3` 保持最后一项。
- 新活动来源标记为 `custom`，名称固定、不可排序，仅允许删除。
- 删除活动不重排其他名称；再次新增基于当前仍存在的最大编号计算。

若缺少 `TDR3`、生成名称重复或计划状态已变化，则不修改数据并显示明确提示。

## 7. 甘特图

### 7.1 共享组件能力

扩展共享 `DHTMLXGantt`，支持：

- 为每条任务指定 `task`、`project` 或 `milestone` 类型。
- 使用逐任务只读属性，而不是只能全图只读。
- 在拖动开始前拒绝只读任务。
- 在拖动结束后将日期通过回调交还当前计划模块保存。
- 保存失败或校验失败时重新载入原任务数据，恢复拖动前位置。

### 7.2 整机、tOS、TDT

- 一级活动映射为阶段汇总条，标记只读，不能整体移动、拉伸或通过弹窗修改。
- 二级活动映射为 `milestone`，使用计划完成时间作为唯一时间点，以菱形显示。
- 仅修订中、具备维护权限且非跟随只读时允许拖动里程碑。
- 拖动只写回该二级活动的计划完成时间，不修改实际时间。
- 写回后重新计算任务计划周期和父阶段聚合时间，并执行既有里程碑顺序校验。
- 最新发布版、历史版和无权限状态下全图只读。

### 7.3 技术子项目

- 每个一级活动映射为普通任务时间条。
- 修订中且具备维护权限时允许：
  - 整体移动时间条，同时平移计划开始和计划完成时间并保持周期。
  - 拉伸左边界，修改计划开始时间。
  - 拉伸右边界，修改计划完成时间。
- 甘特图只表达计划时间；实际开始和实际完成时间在列表中维护。
- 最新发布版、历史版和无权限状态下甘特图只读。

## 8. 日期校验与异常处理

### 8.1 整机、tOS、TDT

- 继续使用现有里程碑顺序校验：后一个有效里程碑日期必须晚于前一个有效里程碑日期。
- 空日期允许存在，不因部分录入立即报错。
- 甘特图拖动产生非法日期时拒绝保存，恢复原位置并提示具体冲突节点。
- 发布时仍阻止包含日期冲突的修订版本。

### 8.2 技术子项目

- 计划开始时间不得晚于计划完成时间。
- 实际开始时间不得晚于实际完成时间。
- 空值允许部分录入；只有成对日期都存在时才比较先后。
- 列表中对应错误单元格标红，并在悬浮提示中显示原因。
- 甘特图移动或拉伸产生非法计划区间时拒绝保存并恢复原位置。
- 发布时阻止仍存在日期冲突的修订版本。

## 9. 版本历史与版本对比

版本对比不再直接比较树形活动行，而是先按计划类型投影：

- 整机、tOS、TDT：使用“阶段 + 里程碑点”的平铺行。
- 技术子项目：使用“活动名称”的单层行。

比对仍以稳定任务 ID 对齐，避免同名节点误配。模板节点与自定义节点的新增、删除、日期变化和状态变化继续使用现有颜色语义。历史版本只读，版本对比不提供任何编辑入口。

## 10. 权限与状态边界

- 所有新增、删除、日期编辑和甘特图拖动都复用现有一级计划或技术计划维护权限。
- 全局管理组仍按现有规则绕过项目级权限，但不能绕过历史版本只读、模板结构锁定和跟随计划只读。
- 创建修订、发布、取消修订继续使用现有编辑保护与版本状态机。
- 甘特图回调必须写入当前作用域的当前修订版本，不能误写其他市场、tOS 类型、技术子项目或历史版本。

## 11. 实现边界

优先新增纯规则函数处理：

- 平铺列表投影。
- MR/转测版本下一编号。
- 自动节点插入和删除权限。
- 甘特任务类型、逐任务只读状态和拖动结果转换。
- 技术子项目四日期校验。

React 组件只负责权限组合、确认弹窗、表格渲染和调用 store 写回，不在 JSX 中重复编号或日期规则。

## 12. 验证方案

### 12.1 自动化规则验证

在仓库现有 `scripts/verify-*.mjs` 模式下新增聚焦验证，覆盖：

- 整机/tOS/TDT 平铺投影与连续序号。
- 技术子项目活动投影与四个时间字段。
- MR4、MR5 编号及删除后的再次新增。
- 第3版、第4版转测编号及始终插入 `TDR3` 前。
- 模板节点和自定义节点的结构权限。
- 阶段、里程碑、子项目活动的甘特类型和只读状态。
- 里程碑拖动只更新计划完成时间。
- 子项目时间条移动、左右拉伸的日期转换。
- 版本对比使用平铺行和稳定 ID。
- 日期错误标记与发布阻断。

### 12.2 仓库验证

- `npx tsc --noEmit`
- `npm run build`

### 12.3 浏览器验收矩阵

分别验证整机、tOS、TDT 和技术子项目：

- 修订版、最新发布版、历史版。
- 有权限、无权限和跟随只读。
- 列表字段、平铺顺序、筛选、导出和版本对比。
- MR/转测版本添加、二次确认、自动命名和仅自定义节点可删除。
- 阶段不可拖动、里程碑点可拖动且刷新后保持。
- 技术子项目活动条可移动/拉伸且刷新后保持。
- 非法日期拖动回滚并阻止发布。

## 13. 已确认的验收结论

- 阶段逐行重复，不使用合并单元格。
- 自动新增节点固定名称、不可排序，只允许删除。
- 整机、tOS、TDT 和技术子项目均保留甘特图。
- 技术子项目只显示“活动名称”，并维护计划开始、计划完成、实际开始、实际完成四个时间字段。
- 版本历史和版本对比与当前计划类型的新列表结构保持一致。
