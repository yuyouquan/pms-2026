# 整机与 tOS 一级计划五阶段调整设计

**日期：** 2026-08-28
**目标分支：** `codex/level1-flat-milestones`
**状态：** 需求设计已确认，待用户复核文档
**覆盖关系：** 本文覆盖 `2026-08-27-machine-tos-level1-plan-refresh-design.md` 中与整机产品项目、tOS 版本项目的模板结构、横版、基础信息计划摘要、甘特图、动态节点和日期校验相关的旧规则。

## 1. 目标与范围

本轮只调整以下两类项目的一级计划：

- 整机产品项目；
- tOS 版本项目。

调整内容包括：

1. 配置中心一级计划默认 Mock 模板；
2. 与项目列表、市场或 tOS 类型关联的项目空间一级计划 Mock 数据；
3. 项目空间基础信息中的一级计划横版摘要；
4. 项目空间计划模块中的一级计划横版、竖版和甘特图；
5. 动态业务节点的新增、修改、删除和排序；
6. 节点命名、日期顺序、阶段交叠、权限和版本状态校验；
7. 已有默认数据的迁移和历史数据保护。

以下内容不在本轮范围内：

- 技术项目的 TDT 项目计划和子项目计划；
- 能力建设项目；
- 二级计划和三级计划；
- 项目空间计划模块中既有版本选择、修订、发布和历史版本展示逻辑的整体改版。

## 2. 核心设计原则

1. 配置中心模板是新项目、新市场或新 tOS 类型初始化一级计划的唯一默认结构来源。
2. 一级阶段的日期始终由二级节点自动聚合，不允许任何用户直接填写或拖动一级阶段日期。
3. 固定节点是单时间点，动态业务节点是时间段，两者在表格和甘特图中采用不同编辑方式。
4. 计划时间与实际时间独立校验，任何拖动、排序和保存都必须使用同一套校验规则。
5. 更新默认 Mock 时不破坏用户自行创建的项目、计划版本和自定义历史数据。

### 3.3 模板字段和初始化

- 配置中心仍按既有一级计划模板字段展示序号、任务名称和角色；本轮重点替换默认 Mock 的阶段与节点结构。
- 模板中的固定节点使用稳定标识，不能因展示序号变化而失去版本对比或历史匹配关系。
- 新建整机市场时，按整机最新已发布一级计划模板初始化一次该市场的一级计划。
- 新建 tOS 类型或 tOS 版本项目范围时，按 tOS 最新已发布一级计划模板初始化一次该范围的一级计划。
- 重复进入项目空间或重复执行数据水合不得再次插入模板节点。

## 4. 节点模型与日期字段

### 4.1 一级阶段

一级阶段本身不直接保存用户输入的日期，计划和实际日期均通过下属二级节点聚合获得。

| 字段 | 规则 |
| --- | --- |
| 计划开始时间 | 取本阶段最早有效计划时间；固定节点阶段由阶段顺序推导开始点 |
| 计划完成时间 | 取本阶段最后一个有效计划完成时间 |
| 预估工期 | `计划完成时间 - 计划开始时间`，日期不足时为 `-` |
| 实际开始时间 | 取本阶段最早有效实际时间；固定节点阶段由阶段顺序推导开始点 |
| 实际完成时间 | 取本阶段最后一个有效实际完成时间 |
| 实际工期 | `实际完成时间 - 实际开始时间`，日期不足时为 `-` |

一级阶段的所有聚合日期字段在竖版、横版和甘特图中均为只读。SPM 和系统超级管理员也不能直接修改一级阶段日期。

若前一个阶段没有任何有效日期，后一个阶段直接作为当前计划时间轴中的第一个有效阶段，不为缺失阶段虚构开始或完成时间。

### 4.2 固定二级节点

概念启动、STR1、STR2、STR3、STR4、STR4A、STR5 为固定时间点节点。

| 字段 | 规则 |
| --- | --- |
| 计划开始时间 | 不提供输入，显示 `-` |
| 计划完成时间 | 可按权限填写 |
| 预估工期 | 显示 `-` |
| 实际开始时间 | 不提供输入，显示 `-` |
| 实际完成时间 | 可按权限填写 |
| 实际工期 | 显示 `-` |

### 4.3 动态业务二级节点

整机 MR 节点和 tOS 版本节点为时间段节点。

| 字段 | 规则 |
| --- | --- |
| 计划开始时间 | 可按权限填写 |
| 计划完成时间 | 可按权限填写，不能早于计划开始时间 |
| 预估工期 | `计划完成时间 - 计划开始时间` |
| 实际开始时间 | 可按权限填写 |
| 实际完成时间 | 可按权限填写，不能早于实际开始时间 |
| 实际工期 | `实际完成时间 - 实际开始时间` |

日期不完整时不计算工期，显示 `-`。

## 5. 项目空间视图

### 5.1 基础信息中的计划横版

基础信息页面的计划横版只展示两行：

1. 当前业务范围的最新已发布一级计划版本；
2. 实际。

规则如下：

- 不展示修订中版本；
- 不展示历史已发布版本；
- 整机按当前市场读取最新已发布版本；
- tOS 按当前 tOS 类型或项目范围读取最新已发布版本；
- 没有已发布版本时，版本行展示空状态，不能回退显示草稿；
- 最新已发布版本的实际日期变化后，“实际”行同步刷新。

### 5.2 计划模块横版

项目空间“计划”模块中的横版版本选择、修订版、历史已发布版和实际行逻辑保持不变。

阶段表头规则：

- 概念阶段、计划阶段和开发验证阶段显示自动计算的预估工期；
- tOS 的上市迭代阶段、维护阶段不显示预估工期；
- 整机的上市阶段、生命周期阶段不显示预估工期；
- 不显示阶段时间范围；
- 固定节点继续以单个日期单元格展示；
- 动态业务节点根据当前视图层展示开始和完成时间，并遵循既有横版编辑权限。

### 5.3 计划模块竖版

竖版保持两级结构，一级行为阶段，二级行为节点。

- 一级阶段的日期、工期仅展示聚合值，不能直接编辑；
- 固定二级节点只开放计划完成时间和实际完成时间；
- 动态业务二级节点开放计划开始、计划完成、实际开始、实际完成时间；
- 日期选择框、错误红框、保存和发布阻断共用第 8 节的规则；
- 可扩展一级阶段行右侧显示 `＋`，点击后新增节点直接归属该阶段，不再使用无法确定目标阶段的统一底部入口。

### 5.4 甘特图

甘特图与表格使用同一份派生数据和权限判断。

#### 一级阶段

- 只展示由二级节点聚合出的时间范围；
- 不能整体拖动；
- 不能调整开始或完成边界；
- 不能通过点击或弹窗直接修改日期；
- 对 SPM、系统超级管理员和普通成员均执行同一只读规则。

#### 固定二级节点

- 有计划完成时间时，在计划层显示为里程碑点；
- 有实际完成时间时，在实际层显示为里程碑点；
- 具备当前日期字段编辑权限时，可以横向拖动里程碑点改变完成日期；
- 不提供宽度和开始边界调整能力。

#### 动态业务二级节点

- 开始和完成时间齐全时显示为时间条；
- 具备当前日期字段编辑权限时，可整体拖动时间条；
- 可调整开始边界或完成边界；
- 日期不完整时显示为待补充状态，不伪造时间条；
- 拖动或缩放结果必须先通过日期校验，再写入计划数据。

## 6. 动态节点交互

### 6.1 tOS 版本节点

tOS 版本项目仅在以下阶段向 SPM 开放动态节点管理：

- 上市迭代阶段；
- 维护阶段。

阶段行右侧分别显示 `＋`。点击哪个阶段的入口，新节点就归属哪个阶段。

名称规则：

- 格式固定为 `XX.X.0.XXX`；
- `XX.X` 必须等于项目空间项目名称中 `tOS` 后的数字版本；
- 第三个数字段固定为 `0`；
- 最后一个数字段必须为三位数字；
- 完整版本号最后一位必须为 `0` 或 `5`；
- 示例：项目 `tOS17.0` 可使用 `17.0.0.110`、`17.0.0.115`；
- 示例：项目 `tOS16.3` 可使用 `16.3.0.125`；
- 无法从项目名称解析 `XX.X` 时禁止保存，并明确提示项目名称无法生成版本前缀。

### 6.2 整机 MR 节点

整机产品项目仅在以下阶段向 SPM 开放动态节点管理：

- 上市阶段；
- 生命周期阶段。

阶段行右侧分别显示 `＋`。点击哪个阶段的入口，新节点就归属哪个阶段。

名称规则：

- 必须匹配 `MR+数字`；
- `MR` 使用大写；
- `MR` 后至少有一位数字；
- 不接受空格、小数、中文编号或其他前后缀。

### 6.3 新增、修改、删除和排序

- 动态节点数量不设上限；
- 创建时必须先通过名称格式校验；
- 创建后允许修改名称，修改时执行同一格式校验；
- 删除必须二次确认；
- SPM 仅能管理上述指定阶段内的动态节点；
- 动态节点仅支持在所属一级阶段内拖动排序，不跨一级阶段移动；
- 填写日期后仍允许排序，但新顺序必须通过日期校验；
- 排序失败时恢复到拖动前顺序，不产生历史脏数据；
- 每次成功新增、改名、删除或排序后，展示序号立即重新计算。

## 7. 权限与版本状态

### 7.1 日期编辑权限

- 项目 SPM 和系统超级管理员可以维护二级节点日期；
- 计划时间只允许在修订中版本修改；
- 实际时间按现有一级计划规则在最新已发布版本和修订中版本间同步；
- 历史已发布版本只读；
- 普通成员只读；
- 一级阶段日期对所有角色只读。

### 7.2 结构编辑权限

- SPM 不能新增、改名、删除或排序模板原有一级阶段和固定二级节点；
- SPM 可以在指定业务阶段新增、改名、删除和排序动态节点；
- SPM 的结构操作只允许发生在修订中版本；
- 系统超级管理员保留一级计划结构的全局新增、删除和排序权限；
- 系统超级管理员的结构权限不改变“一级阶段日期不可直接编辑”的硬规则；
- 所有结构按钮除界面隐藏或禁用外，保存处理函数必须再次执行权限校验。

## 8. 日期顺序与错误处理

计划时间和实际时间使用同一算法，但分别独立校验，互不替代。

### 8.1 单节点校验

- 动态节点开始时间不得晚于完成时间；
- 日期必须是有效的 `YYYY-MM-DD` 日历日期；
- 空日期允许作为未完成输入，不单独标红。

### 8.2 同阶段校验

- 固定时间点节点按当前顺序严格递增；
- 后一个固定节点完成时间必须晚于前一个固定节点完成时间；
- 不允许两个相邻固定节点使用同一天；
- 后一个动态节点开始时间必须晚于前一个动态节点完成时间；
- 动态时间段之间不允许交叠或首尾同日；
- 仅在参与比较的两侧日期都存在时执行顺序校验。

### 8.3 跨阶段校验

- 后一个阶段首个有效节点时间必须晚于前一个阶段最后一个有效节点时间；
- 阶段之间不允许交叠或共用同一天；
- 如果前一个阶段完全没有有效日期，则跳过该空阶段，由后一个有日期的阶段作为时间轴中的下一个有效阶段；
- 不能为了通过校验自动改写用户输入的节点日期。

### 8.4 反馈方式

- 表格中有冲突的日期选择框和单元格标红；
- 悬停提示具体节点、字段和冲突原因；
- 点击保存时保留可继续修改的草稿，但不得静默修正日期；
- 发布时仍有冲突则禁止发布，并定位到第一个错误字段；
- 排序、甘特拖动或缩放产生冲突时不写入数据，并恢复原状态；
- 顺序冲突统一弹出业务指定提示：`下一个子节点日期不允许超上一个子节点。`

## 9. 数据更新与迁移

### 9.1 默认 Mock 更新

- 配置中心整机和 tOS 默认模板替换为第 3 节五阶段结构；
- 项目列表中自带的整机、市场、tOS 项目 Mock 一级计划与新模板联动；
- Mock 日期必须满足严格递增和阶段不交叠规则；
- 可扩展阶段保留适量 MR 或 tOS 版本示例，用于直接验证时间段表格和甘特图；
- Mock 版本至少包含最新已发布版本与实际数据，以覆盖基础信息两行展示。

### 9.2 迁移规则

- 识别当前内置默认模板和默认 Mock，迁移为新的五阶段结构；
- 整机原开发、验证阶段的固定节点合并到开发验证阶段；
- tOS 移除旧默认规划阶段，概念启动至 STR5 映射到新的前三个阶段；
- 原业务阶段中的合法 MR 或 tOS 版本节点、日期和稳定标识尽量保留；
- 用户自建项目、非默认自定义节点和历史已发布版本不做破坏性重写；
- 迁移后展示序号根据结构重算，稳定标识保持不变；
- 迁移必须幂等，重复水合不能重复插入阶段或节点；
- 新市场、新 tOS 范围只初始化一次，后续模板修订不自动覆盖项目内已初始化计划。

## 10. 状态与版本数据来源

| 界面 | 版本来源 |
| --- | --- |
| 基础信息计划横版 | 最新已发布版本 + 实际，两行 |
| 计划模块横版 | 保持现有版本、修订和实际逻辑 |
| 计划模块竖版 | 当前选择版本或实际层 |
| 甘特图 | 当前选择版本或实际层，与表格使用同一数据 |

基础信息不得因为存在修订中版本而显示草稿日期。计划模块仍允许有权限用户查看和编辑修订中版本。

## 11. 验证策略

### 11.1 规则级验证

- 两类五阶段模板的阶段、固定节点、空业务阶段和稳定标识；
- 整机与 tOS 项目使用正确模板，不能串用；
- tOS 项目名解析、版本号格式和末位 `0/5`；
- MR 格式；
- 动态节点新增、改名、删除、同阶段排序和重编号；
- 固定节点严格递增且不允许同日；
- 动态时间段不交叠；
- 跨阶段不交叠；
- 计划与实际分别校验；
- 一级阶段聚合与不可编辑规则；
- 基础信息只选择最新已发布版本；
- 迁移保留数据且重复执行幂等。

### 11.2 权限验证

分别使用以下身份验证界面按钮和保存处理函数：

- 整机或 tOS 项目 SPM；
- 系统超级管理员；
- 普通项目成员。

覆盖修订中、最新已发布和历史已发布版本，确保界面可见性和实际写入权限一致。

### 11.3 静态和构建验证
