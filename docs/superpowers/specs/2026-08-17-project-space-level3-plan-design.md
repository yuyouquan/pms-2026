# 项目空间三级计划设计

## 1. 背景与目标

项目空间现有计划工作台包含一级计划、二级计划和计划总览。本次调整统一移除二级计划和计划总览入口，并为整机产品项目、tOS版本项目新增“三级计划”工作台。

“三级计划”是该业务模块的名称，其内部活动结构固定为两级：一级活动和二级活动。它不沿用原二级计划的模板、修订、发布、版本对比等模型，而是面向项目执行过程的活动维护表。

## 2. 范围

### 2.1 包含范围

- 所有项目的项目空间计划入口移除“二级计划”和“计划总览”。
- 整机产品项目、tOS版本项目的计划页显示“一级计划”和“三级计划”两个 Tab。
- 其他项目类型保留现有一级计划工作台，不显示三级计划。
- 三级计划支持活动创建、编辑、筛选、导出、列设置、展开、收起、拖动排序和历史修改记录。
- 整机产品项目按市场隔离三级计划数据，tOS版本项目按版本类型隔离三级计划数据。
- 三级计划沿用一级计划的主范围与跟随范围规则。

### 2.2 不包含范围

- 不给三级计划增加修订、发布、取消修订、版本选择或版本对比能力。
- 不允许活动超过两级。
- 不增加活动删除功能。
- 不改造配置中心的计划模板。
- 不物理删除原二级计划的持久化状态和兼容代码；本次仅停止项目空间入口和业务调用，避免破坏已有本地数据。

## 3. 方案选择

采用独立三级计划领域模块：三级计划拥有独立的数据模型、状态管理、业务规则和界面组件，由项目空间容器负责路由与范围上下文接入。

不复用原二级计划结构。原二级计划包含模板类型、里程碑绑定和版本生命周期，与本次执行活动表的语义不同。独立实现可避免旧行为泄漏，也能控制现有大型项目空间容器继续增长。

建议边界：

- `src/types/level3Plan.ts`：活动、范围、表单和历史记录类型。
- `src/lib/level3PlanRules.ts`：编号、聚合、工期、拖动、权限和日期校验等纯规则。
- `src/stores/level3Plan.ts`：按项目及范围持久化活动、列设置和历史记录。
- `src/components/plans/Level3PlanModule.tsx`：工具栏、表格、弹窗、筛选、历史抽屉和拖动交互。
- `src/containers/ProjectSpaceContainer.tsx`：控制 Tab 可见性，向三级计划模块传入项目、市场/类型、跟随来源、一级计划快照和当前用户权限上下文。

## 4. 导航与可见性

### 4.1 Tab 规则

| 项目类型 | 计划 Tab |
| --- | --- |
| 整机产品项目 | 一级计划、三级计划 |
| tOS版本项目 | 一级计划、三级计划 |
| 技术项目 | 保留该类型现有一级计划工作台 |
| 能力建设项目 | 保留该类型现有一级计划工作台 |

如果旧持久化状态中的当前 Tab 是二级计划或计划总览，进入项目空间计划页时回退到一级计划。

### 4.2 范围切换与跟随

- 整机产品项目使用当前市场作为三级计划范围。
- tOS版本项目使用当前版本类型作为三级计划范围。
- 主市场或主类型维护自己的三级计划数据。
- 跟随市场或跟随类型读取主范围的三级计划数据，不复制数据。
- 跟随范围内所有写操作、拖动操作均禁用，并展示与一级计划一致的来源提示，引导用户切换到主范围维护。
- 跟随来源无数据时展示只读空状态，不自动生成活动。

## 5. 数据模型

### 5.1 三级计划范围

三级计划以稳定范围键持久化：

```text
projectId + scopeType + scopeValue
```

- 整机：`scopeType = market`，`scopeValue = 市场名`。
- tOS：`scopeType = tosType`，`scopeValue = 版本类型`。

跟随范围解析到主范围键后读取数据。

### 5.2 活动

每条活动至少包含：

- 稳定内部 ID。
- `parentId`：一级活动为空，二级活动指向一级活动。
- 同级排序值 `order`。
- 活动名称。
- 责任人、责任部门。
- 计划开始时间、计划完成时间。
- 实际开始时间、实际完成时间。
- 关键节点 ID、关键节点名称快照、关键节点计划完成时间快照。
- 状态：待启动、进行中、已完成；默认待启动。
- 任务风险：无、高、中、低；默认无。
- 备注。
- 创建者、创建时间、最后修改人、最后修改时间。

显示序号不作为数据主键。序号根据树结构和同级顺序实时生成，例如 `1、1.1、1.2、2、2.1`。

### 5.3 历史记录

历史记录按三级计划范围持久化，包含：

- 操作类型：创建一级活动、创建二级活动、编辑活动、拖动活动。
- 操作人和操作时间。
- 活动稳定 ID、操作发生时的活动名称和显示序号。
- 编辑操作的字段级变更前后值。
- 拖动操作的原父级、目标父级、原位置、新位置和重新编号结果。

二级活动变化引起的父活动日期聚合不另记一条系统操作，相关结果可由该次二级活动变更追溯。

## 6. 表格

### 6.1 列顺序

表格默认按以下顺序展示 14 列：

1. 序号
2. 活动名称
3. 责任人
4. 责任部门
5. 计划开始时间
6. 计划结束时间
7. 预估工期
8. 关键节点
9. 实际开始时间
10. 实际完成时间
11. 实际工期
12. 状态
13. 任务风险
14. 创建者

备注仅在活动弹窗和历史记录中展示，不额外加入表格。

### 6.2 行展示

- 一级活动使用现有计划表的父行底色和加粗层级样式。
- 二级活动在活动名称前显示缩进。
- 活动名称单元格悬浮显示操作按钮。
- 一级活动可显示“编辑”和“新增二级活动”。
- 二级活动只显示“编辑”，不显示继续新增入口。
- 无对应权限时不显示操作按钮。
- 一级活动可折叠或展开其二级活动。

### 6.3 父活动聚合

一级活动的日期只从直属二级活动聚合，不在一级活动弹窗中直接填写：

- 计划开始时间：二级活动计划开始时间的最小值。
- 计划结束时间：二级活动计划完成时间的最大值。
- 预估工期：计划结束时间减计划开始时间的自然日差值。
- 实际开始时间：二级活动实际开始时间的最小值。
- 实际完成时间：二级活动实际完成时间的最大值。
- 实际工期：实际完成时间减实际开始时间的自然日差值。

缺少任一对应起止日期时工期显示 `—`；同一天起止时显示 `0` 天。没有二级活动时，一级活动的聚合日期和工期均显示 `—`。

## 7. 活动弹窗

### 7.1 新增或编辑一级活动

字段：

- 活动名称：必填。
- 责任人：必填。
- 责任部门：通过责任人自动带出，只读。
- 状态：必填；待启动、进行中、已完成；默认待启动。
- 任务风险：必填；无、高、中、低；默认无。
- 备注：可选，多行文本。

确认新增后，一级活动追加到表格最后。编辑保留稳定 ID、创建者和创建时间。

### 7.2 新增或编辑二级活动

字段：

- 活动名称：必填。
- 责任人：必填。
- 责任部门：通过责任人自动带出，只读。
- 计划开始时间：必填。
- 计划完成时间：必填。
- 实际开始时间：可选。
- 实际完成时间：可选。
- 关键节点：必填，下拉单选。
- 状态：必填；待启动、进行中、已完成；默认待启动。
- 任务风险：必填；无、高、中、低；默认无。
- 备注：可选，多行文本。

新增二级活动时追加到目标一级活动的子活动末尾。保存后立即重算目标一级活动聚合字段。

### 7.3 关键节点来源和校验

- 关键节点选项来自当前有效范围最新已发布一级计划的二级任务名称。
- 计划开始时间不得晚于计划完成时间。
- 计划完成时间不得晚于所选关键节点的计划完成时间。
- 尚无最新已发布一级计划时，允许创建一级活动，但禁用新增二级活动，并提示“请先发布一级计划后再新增二级活动”。
- 已有活动引用的关键节点从后续最新发布一级计划中消失时，表格继续显示保存的名称快照；再次编辑时必须重新选择当前有效节点。

## 8. 权限

### 8.1 角色能力

| 用户身份 | 创建一级活动 | 编辑一级活动 | 新增其下二级活动 | 编辑二级活动 | 拖动 |
| --- | --- | --- | --- | --- | --- |
| SPM、管理员 | 全部 | 全部 | 全部 | 全部 | 全部 |
| 一级活动责任人 | 否 | 自己负责的一级活动 | 自己负责的一级活动下 | 自己负责的一级活动下全部二级活动 | 自己负责范围内 |
| 二级活动责任人 | 否 | 否 | 否 | 自己负责的二级活动 | 否 |
| 其他用户 | 否 | 否 | 否 | 否 | 否 |

管理员包含全局管理组及项目权限体系中的管理员。SPM 从项目固定角色成员中识别。所有写操作必须同时通过跟随范围只读检查。

### 8.2 跨父活动拖动权限

- 仅允许同层级拖动。
- 一级活动可在一级活动之间排序，拖动时携带其全部二级活动。
- 二级活动可拖入另一个一级活动，变更 `parentId` 并进入目标父活动的指定同级位置。
- SPM、管理员可执行任意合法拖动。
- 一级活动责任人调整二级活动时，必须同时拥有来源父活动和目标父活动的管理权限；否则不能跨组拖动。
- 二级活动责任人不能拖动，避免通过移动自己的活动改变其他活动顺序或父活动聚合。

## 9. 拖动与编号

拖动完成时以一次原子状态更新执行：

1. 验证跟随范围、活动层级和用户权限。
2. 从来源同级列表移除活动。
3. 插入目标同级位置，必要时更新二级活动 `parentId`。
4. 规范化来源和目标同级 `order`。
5. 重新计算整棵两级活动树的显示序号。
6. 重算受影响父活动的聚合日期和工期。
7. 写入一条拖动历史记录。

失败时不进行部分写入，并用轻提示说明原因。

## 10. 工具栏

### 10.1 左侧

- “新增活动”按钮位于左上角。
- 仅 SPM、管理员可用；无权限时保留禁用态与原因提示，保持工具栏稳定。

### 10.2 右侧

按以下顺序展示，并沿用一级计划的按钮尺寸、图标语言和工具栏样式：

1. 筛选
2. 导出
3. 列设置
4. 全部展开
5. 全部收起
6. 历史修改记录

筛选支持表格业务字段。命中二级活动时保留父活动上下文；命中一级活动时保留其当前可见子活动。

导出沿用一级计划的当前视图/全部字段选择方式，导出结果保持当前筛选顺序和层级序号。

列设置支持显隐和排序；序号、活动名称为不可隐藏的基础列。展开收起状态按三级计划范围保存。

历史修改记录使用右侧抽屉，按时间倒序展示创建、编辑和拖动记录及字段差异。

## 11. 状态、风险与视觉

- 状态沿用项目现有 Tag 视觉：待启动、进行中、已完成。
- 任务风险按无、高、中、低展示，不新增其他枚举。
- 表格、弹窗、抽屉、筛选器和按钮复用现有 `pms-table`、`pms-modal`、工具栏与主题样式，不引入另一套视觉语言。
- 宽表支持横向滚动，序号和活动名称固定在左侧，避免滚动后丢失活动上下文。

## 12. 错误处理

- 无有效项目、市场或版本类型范围时展示明确空状态，不写入兜底范围。
- 跟随范围内所有写入口禁用并说明数据来源。
- 保存表单前统一验证必填项和日期约束，失败时保留用户输入。
- 关键节点没有计划完成时间时不能用于新增或重新保存二级活动，并说明原因。
- 拖动权限或层级不合法时恢复原位置，不改变序号、聚合字段或历史记录。
- 自动带出的责任部门缺失时显示 `待补充`，不虚构部门。

## 13. 验证策略

项目当前没有通用测试框架，因此将纯规则写成可由仓库脚本直接调用的模块，并增加专用验证脚本覆盖：

- 两级编号生成与重排。
- 一级活动日期和工期聚合。
- 同级一级活动拖动及携带子活动。
- 二级活动同父排序和跨父移动。
- 跨父移动后的来源/目标聚合。
- SPM、管理员、父活动责任人、二级活动责任人的权限矩阵。
- 计划日期和关键节点日期约束。
- 整机市场、tOS类型的独立范围和跟随范围解析。
- 历史记录变更内容。

完成实现后执行：

```bash
npx tsc --noEmit
npm run build
```

浏览器走查至少覆盖：

- 整机主市场创建、编辑、拖动、筛选、导出、列设置和历史记录。
- 整机跟随市场只读与来源提示。
- tOS主类型创建、编辑、跨父拖动和关键节点约束。
- tOS跟随类型只读与来源提示。
- 非目标项目不出现三级计划。
- 二级计划和计划总览在所有项目中不再出现。

## 14. 验收标准

1. 所有项目空间计划页不再展示二级计划和计划总览入口。
2. 仅整机产品项目、tOS版本项目展示三级计划。
3. 三级计划严格使用一级、二级两层活动结构。
4. 表格字段、顺序、默认值和必填规则符合本设计。
5. 一级活动日期和工期完全由二级活动聚合。
6. 关键节点仅来自最新已发布一级计划的二级任务，日期约束生效。
7. 权限矩阵在按钮可见性和实际写操作两层均生效。
8. 一级活动拖动携带子活动，二级活动可跨父活动拖动，位置、父级和序号同步更新。
9. 整机市场与tOS版本类型数据相互隔离，跟随范围与一级计划一致且只读。
10. 筛选、导出、列设置、全部展开、全部收起、历史修改记录交互可用且风格与一级计划一致。
11. 当前已有工作区改动不被覆盖或清理。
