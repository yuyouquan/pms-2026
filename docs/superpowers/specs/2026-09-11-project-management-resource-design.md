# 项目统一配置与项目空间资源设计

状态：按用户确认与里程碑更正进入实施准备。
工作分支：`codex/feature-project-management-space`。
依据：2026-09-11 用户需求及本轮三项补充确认。

## 1. 已确认的补充规则

1. 配置表格“移除后确认”指移出编辑框（失焦）后弹出二次确认；确认才保存，取消恢复原值。
2. 原“人力资源管道 → 人力投入”保留跨项目汇总，与项目空间共用数据。
3. 路标项目的“项目预估投入”本期只显示空状态，不允许新建版本。
4. 正式项目里程碑直接从本项目一级计划读取，新增版本及最新版本表格均不可编辑；历史版本保留原有快照规则。
5. 预算项目里程碑在新增版本与最新版本表格中手动维护；即使绑定正式项目也不从正式项目同步。
6. 仅绑定同类型正式项目、关联年度预算只读及来源编辑、名称进入空间与旁侧编辑图标分离，均已确认。

## 2. 方案选择

推荐方案 A：统一项目档案，复用现有人力计算与版本模块。项目配置管理项目身份、属性、责任人、正式项目绑定和历史；项目视图、路标和人力汇总通过同一项目 ID 读取。四类人力投入保留各自的阶段与计算规则，共用项目范围、权限、版本归属和关联展示逻辑。

备选方案 B：同时将四类人力投入重写成一个通用引擎。可减少长期重复代码，但需要额外重做各类型的阶段、模型、月度分摊和历史数据迁移。本期建议选择 A，优先完成业务调整。

当前 IPM 来源为仓库中的外部项目池 Mock；本期沿用该接口和项目类型映射。真实 IPM 接口接入未在本次需求中提供，不将 Mock 映射表描述为在线 IPM 集成。

## 3. 导航与页面

Header 顺序：工作台 → 项目管理 → 项目组合管理 → tOS路标 → 人力资源管道 → 配置中心。

- 删除此前新增的空白“项目管理”入口。
- 将原“项目列表”改名为“项目管理”。该入口内设置“项目配置”“项目视图”两个页签，建议默认进入项目配置，并记住本次会话选择。
- “项目视图”复用现有项目列表，包括分类、筛选、列表/日历/卡片、字段配置、权限和进入空间能力，仅显示正式项目。
- “联合项目空间”改名为“项目组合管理”，相关返回文案一起改名，原有聚合功能保留。
- 新增项目统一从“项目配置 → 新项目”发起。项目视图、tOS 路标及人力投入原有独立建档入口收口到这里。
- 项目配置内点击项目名称进入对应项目空间；非正式项目名称旁提供编辑图标，避免进入空间与编辑名称相互冲突。
- 从项目配置或项目视图进入空间后，返回时恢复原页签、筛选与分页。
- 各类项目空间“资源”下设置“项目预估投入”“项目资源看板”；后者本期留空。
- 统一配置中心增加“人力资源管道”分类，其下迁入“整机人力模型”。原人力投入中的其他配置项本期保留现有位置。

## 4. 统一建档

点击“新项目”打开“新增项目”Modal。确认成功后关闭弹窗，在项目配置中新增记录，不自动跳转项目空间。

| 字段 | 正式项目 | 预算项目 | 路标项目 |
| --- | --- | --- | --- |
| 项目属性 | 下拉单选：正式项目、预算项目、路标项目 | 同左 | 同左 |
| 项目名称 | 从现有外部项目池下拉单选，排除已建档的外部项目标识 | 手动填写 | 手动填写 |
| 项目类型 | 根据外部项目分类及现有映射自动带出，不可手改 | 四类项目单选 | 只能选择整机产品项目 |
| 责任人 | 人员下拉多选，至少一人 | 同左 | 同左 |

四类项目类型的准确名称为：整机产品项目、tOS版本项目、技术项目、能力建设项目。

选中的责任人写入项目责任人，并按类型同步字段和角色：

| 项目类型 | 赋值目标 |
| --- | --- |
| 整机产品项目 | SPM、系统管理员 |
| tOS版本项目 | 版本项目经理、系统管理员 |
| 技术项目 | 技术项目负责人、系统管理员 |
| 能力建设项目 | 系统管理员 |

外部项目类型映射失败时展示原因并禁止提交；切换项目属性时清理不适用的项目选择和类型值。新增 Modal 不再要求填写首销 tOS、安卓版本、里程碑、项目扩展信息等字段。现有建档校验需区分“最小建档”和“补充完整信息”，项目空间中的详细编辑规则继续用于后续补充。

## 5. 项目配置列表

字段顺序固定如下：

| 字段 | 展示与编辑规则 |
| --- | --- |
| 项目名称 | 正式项目只读；非正式项目可进入单元格编辑，失焦后确认保存；名称可进入对应空间 |
| 项目类型 | 只读显示建档时的类型 |
| 项目属性 | 只读显示正式项目、预算项目或路标项目 |
| 项目编码 | 正式项目读取 IPM 来源字段并只读；非正式项目可手工填写，失焦后确认保存，不可重复 |
| 创建人 | 记录实际创建人，只读 |
| 创建时间 | 记录实际创建时间，只读 |
| 绑定正式项目 | 正式项目不可选择；非正式项目下拉单选正式项目，失焦后确认保存；可清除并确认解绑 |
| 操作 | 历史、删除；删除必须二次确认 |

单元格编辑统一规则：值未变化时不弹窗；非法值展示错误并留在编辑态；确认后再执行最终校验和写入；取消恢复修改前值；同一时刻仅有一个待确认修改，避免失焦重复弹窗。名称不能为空，非正式项目编码未填写时允许为空；填写后去除首尾空格，并在全部有效项目记录范围内校验唯一性。项目属性、类型、创建信息不在表格上编辑。

正式项目的外部项目标识和项目编码分开存储，不将显示名称或外部标识擅自冒充项目编码。外部数据缺少编码时显示“—”，仍保留已建档记录；外部项目标识不可重复建档。不同正式外部项目的来源编码允许按 IPM 原值重复；非正式项目的手工编码不可与任何有效记录冲突。

### 绑定规则

- 一个非正式项目最多绑定一个正式项目。
- 同一个正式项目最多被一个预算项目及一个路标项目分别绑定；预算项目和路标项目可以同时绑定它。
- 只允许绑定相同项目类型的正式项目，避免跨类型阶段与人力模型混用。
- 已被同属性项目绑定的正式项目不可重复选择，写入时再次校验。
- 绑定、改绑、解绑均记录历史。解绑不删除预算项目及其年度预算版本。
- 建议删除正式项目时在确认框列明关联项目；确认后解除关联，保留预算/路标项目及各自历史。删除任何项目均保留删除前的审计快照，其他视图同步移除该项目。

### 历史记录

历史 Modal 按时间倒序展示创建、字段修改、绑定、改绑、解绑等操作，包含操作人、操作时间、字段、修改前值和修改后值。数据写入成功后才记历史；取消修改不记历史。项目空间补充字段时的修改也需要能够在配置历史中追溯。

## 6. 项目视图、路标和空间的一致性

- 现有正式项目纳入统一配置后，继续显示在项目视图。
- 预算项目只在项目配置及相关人力视图中展示，不进入正式项目视图或 tOS 路标。
- 现有“待规划项目”对应项目属性为“路标项目”的统一项目记录；tOS 路标的业务状态与项目属性分开保存。
- 路标项目也能进入整机项目空间补充原路标创建 Modal 的字段；原有其他字段在空间中维护。
- 简化建档后允许项目资料不完整。tOS 路标对缺少日期的记录保留表格展示，演进图待日期补充后再定位，不生成虚假日期或静默丢弃项目。
- 项目名称、编码、绑定或空间字段变化通过项目 ID 联动到相关展示，不按显示名称匹配数据。
- 项目组合管理沿用原正式项目及 MR 聚合范围，预算项目和路标项目不因统一存储而自动混入既有计划聚合。

## 7. 项目空间中的预估投入

同一套版本记录支持两种范围：原人力投入为跨项目汇总，项目空间限定当前项目。项目空间移除“项目名称”“品牌”“产品线”筛选，新增版本也不可切换到其他项目。两种入口互相可见修改，筛选状态相互隔离。

| 项目属性 | 可新增预算类型 | 项目空间显示内容 |
| --- | --- | --- |
| 预算项目 | 仅年度预算 | 该预算项目自身年度预算版本 |
| 正式项目 | 项目概算、项目预算 | 自身版本，以及绑定预算项目的年度预算版本 |
| 路标项目 | 不允许新增 | 空状态 |

正式空间中的年度预算是对来源预算项目版本的关联展示，不复制版本。标明来源预算项目，并在正式空间只读展示；需要修改时进入来源预算项目。关联年度预算的里程碑始终来自预算项目手工值，不随正式一级计划变化。绑定后展示来源的全部年度预算历史版本；解绑后从正式空间消失，来源数据保留。跨项目汇总按实际版本 ID 去重，同一年度预算不会因在正式空间可见而重复统计。

### 整机预算项目的品牌信息

- 未绑定正式项目时，新增版本需填写品牌、产品线、市场名，选项沿用现有枚举配置及品牌/产品线联动规则。
- 绑定正式项目后，品牌、产品线、市场名跟随正式项目并只读；正式项目缺少值时提示在正式项目空间补充，不允许在预算项目中覆盖。
- 建议解绑时保留最后一次有效的三项值，恢复可编辑状态，并记录来源变化。

### 新增版本与详情

- 新增版本的表单字段按一行三个排列；长表格独占整行，窄屏允许换行。
- 按项目类型展示相应的里程碑日期字段。正式项目的新建及最新版本直接读取本项目一级计划并只读；预算项目的新建及最新版本可手工填写。
- 沿用现有各预算类型独立的 `V0.n` 版本序列、复制、导出、批次和月度投入规则。
- 沿用仅最新版本可编辑的历史保护范围。正式项目各预算类型最新版本里程碑跟随本项目一级计划，不接受手工覆盖；预算项目可沿用自己的上一版本，始终手工维护，绑定、改绑及正式计划变化均不覆盖预算项目里程碑。双方人力版本也不反向修改一级计划。
- 整机项目的“项目年份”增加到预估投入版本表格，使用该行版本的概念启动及 STR5 时间计算，避免历史版本全部显示最新版本的年份。
- tOS 新增版本中的部门/阶段投入表保留手工填写，合计自动计算。
- 整机新增版本中展示同类部门/阶段投入表：使用配置中心所选整机人力模型、项目等级和等级系数计算，表格只读，随模型选择更新。
- 技术项目保留其现有阶段投入结构；能力建设项目保留开始/结束时间及部门投入，不套用整机阶段。
- 四类版本详情在版本基础信息后增加里程碑信息；能力建设项目展示开始/结束时间。
- 删除最后一个人力版本后，统一项目档案仍然存在，可继续在项目配置中管理。

## 8. 配置与权限

- “配置中心 → 人力资源管道 → 整机人力模型”复用原人力模型数据、版本和计算逻辑，迁移入口不重建配置数据。
- 人力投入原人力模型入口移除，其他尚未要求迁移的配置保留。
- 建议项目配置创建与全局管理沿用现有管理组权限；项目空间的查看、编辑及资源操作按项目权限控制，责任人同时拥有本项目系统管理员角色。
- 配置表、项目空间、人力汇总中的同一操作应用同一权限判断；关联展示预算时也检查来源项目的可见权限，不能从正式项目入口绕过来源权限。
- 模型编辑复用原配置编辑权限；本次不因新增导航位置扩大权限。

## 9. 数据兼容与实现边界

统一项目档案复用现有项目存储，增加项目属性、绑定正式项目 ID、创建信息和档案历史等元数据。正式来源、路标扩展信息和人力版本使用稳定项目 ID 关联；筛选及弹窗状态与持久化业务记录分离。

四类人力存储继续负责各自版本、阶段和月度数据，新增共享的项目适配、预算类型判断与版本范围选择。禁止只隐藏按钮而不更新存储层校验。

兼容迁移需在写入前检查旧数据：原 PMS 项目默认正式项目，原待规划项目迁为路标项目；旧人力记录按年度预算和已绑定正式项目的概算/预算拆分归属，保留版本 ID、日期、投入、月度编辑和历史。发现旧绑定不唯一、无可确定正式项目等冲突时保留原记录并明确报告，不按名称猜测、自动删数或覆盖。迁移重复执行不得重复建档。

本次只做当前前端 Mock 应用及其持久化联动；交付范围为当前 feature 分支。主干合并和生产发布不属于本次新增需求。

## 10. 验收

1. Header 只有一个项目管理入口，各项名称和顺序正确；内部两个页签与返回路径正确。
2. 三种属性的最小建档可用，正式类型自动带出，路标类型受限，责任人和角色赋值正确。
3. 配置字段顺序、单元格编辑失焦确认、取消恢复、唯一编码、绑定冲突、解绑、历史及删除联动符合规则。
4. 项目视图仅显示正式项目；路标项目可从配置进入空间，补充字段后同步反映到 tOS 路标。
5. 四类项目资源空间正确隔离项目；预算类型受限；正式空间显示关联年度预算，解绑后消失但源记录保留。
6. 品牌/产品线/市场名的未绑定录入、绑定只读和解绑行为正确。
7. 正式项目新建及最新版本里程碑只读并跟随本项目一级计划；预算项目新建及最新版本里程碑可编辑，绑定后仍独立，正式计划变化不影响其手工值；关联年度预算保持源日期。项目年份按版本显示，详情里程碑可见。
8. tOS 阶段投入可手改，整机模型明细只读，模型计算及月度投入与现有规则一致。
9. 汇总与单项目视图数据联动、不重复计数、不串筛选；页面刷新后持久化记录一致。
10. 新旧数据迁移无版本丢失、无重复建档；非授权身份无法通过其他入口编辑。
11. 路标预估投入及项目资源看板保持本期约定的空状态，整机人力模型迁移后数据不变。
12. 完成类型检查、生产构建、相关业务校验脚本和浏览器交互验证，检查运行错误；在当前 feature 分支提交推送并核对远端提交。

## 11. 实施顺序

1. 统一项目属性、最小建档、权限、绑定及兼容迁移；接入项目配置和导航。
2. 接通正式项目视图与路标项目空间，收口各旧建档入口。
3. 将现有人力模块支持单项目范围，落实预算归属、关联年度预算、里程碑和模型明细。
4. 迁移整机人力模型配置入口，完成跨入口权限、持久化与浏览器验证。

本稿记录设计与实施依据，不代表功能实现完成或上线；用户最新里程碑更正优先于此前草案表述。

## 12. 后续确认：Mock 数据与交付

用户要求结合新功能刷新 Mock 数据，覆盖三种项目属性、四种类型、绑定与独立预算里程碑等实际场景。修改完成后进行功能交互测试，测试通过后提交推送到 feature 分支。继续保留已约定的旧存储数据兼容迁移，不按名称猜测关联。
