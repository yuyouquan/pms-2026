# 个人工作台目录式任务表格设计

## 1. 背景与目标

现有个人工作台使用“待办中心 / 工作跟踪”模块切换，待办区域以筛选工具栏和单一表格为主。新版工作台参考用户提供的 ONES 截图所体现的“左侧目录 + 右侧状态页签 + 高密度表格”信息架构，但不复制其视觉样式，继续使用 PMS 现有的浅紫色玻璃视觉系统。

本次改造目标：

1. 移除工作台中的“工作跟踪”入口，个人工作台只承载任务处理。
2. 左侧任务目录只保留“计划”和“转维护”。
3. 工作台任务状态只保留“待处理”和“已完成”。
4. 右侧表格严格展示任务名称、所属项目、状态、任务节点、任务内容、处理人、生成时间、操作八列。
5. 保留当前用户、权限、项目空间路由、编辑离开保护和计划版本定位能力。

## 2. 范围

### 2.1 本次包含

- 重构 `WorkbenchContainer` 与 `TodoCenter` 的页面信息架构。
- 聚合当前登录用户可见的计划任务与转维护任务。
- 将工作台状态统一为“待处理 / 已完成”，并展示已完成历史任务。
- 实现目录、状态、搜索、所属项目、生成时间共同筛选。
- 实现目录和状态的智能默认选中规则。
- 保留直接进入计划或转维护页面的操作路径。
- 补齐加载、错误、空状态、分页、响应式和无障碍行为。

### 2.2 本次不包含

- 不新增任务详情弹窗。
- 不新增任务转派、批量处理、工作台内完成任务或评论功能。
- 不修改计划、转维护的业务状态机和业务页面。
- 不新增后端接口、持久化或通知能力。
- 不删除 `WorkTracker` 源文件；只移除其工作台入口和渲染，避免扩大无关代码范围。
- 不改动项目列表、路标、项目空间、配置中心和权限中心的界面。

## 3. 页面结构

### 3.1 页面标题

- 顶部保留“个人工作台”标题。
- 移除“待办中心 / 工作跟踪”胶囊切换。
- 标题区继续使用 PMS 的玻璃容器样式，保持主导航和用户切换器不变。

### 3.2 主体布局

主体为一个统一的玻璃容器，桌面端分成左右两区：

- 左侧：固定宽度的任务目录。
- 右侧：状态页签、筛选工具栏、结果表格和分页。

左侧目录按固定顺序展示：

1. 计划
2. 转维护

每个目录展示该目录的待处理数量。目录不支持新增、删除、排序、折叠或树形层级。

窄屏下，目录转换为表格上方的“计划 / 转维护”横向切换，不改变功能和选中状态。

### 3.3 状态页签

状态页签固定为：

1. 全部
2. 待处理
3. 已完成

数量按当前选中的目录统计。页签采用紧凑下划线选中样式，不使用大面积按钮或卡片。

## 4. 默认选中规则

默认目录顺序为“计划 → 转维护”。首次进入工作台或切换登录用户时，按以下顺序计算：

1. 在经过当前用户和权限过滤后的任务中，查找第一个存在待处理任务的目录。
2. 若找到，选中该目录并打开“待处理”页签。
3. 若两个目录都没有待处理任务，选中“计划”并打开“全部”页签。

用户手动切换目录或状态后，不因普通筛选条件变化而重置选择。切换登录用户时重新执行默认规则，避免保留上一用户的无效视图。

切换目录或状态时，分页回到第一页；搜索、项目或生成时间筛选变化时同样回到第一页。

## 5. 工作台任务状态

工作台任务状态类型只允许：

```ts
type TodoStatus = 'pending' | 'completed'
```

界面映射：

- `pending` → 待处理
- `completed` → 已完成

工作台不展示“未开始”“进行中”“失败”等第三种任务状态。底层计划或转维护流程仍可保留自己的业务状态；聚合到工作台时按以下规则归一化：

- 计划任务满足“状态为已完成”或“进度达到 100%”时为 `completed`，其他需要当前用户负责的计划任务为 `pending`。
- 转维护节点为 `success` 时为 `completed`。
- 转维护节点为 `in_progress` 或 `failed` 时为 `pending`。
- 转维护节点为 `not_started` 时不生成工作台任务，避免把未来节点提前暴露为待处理。
- 已取消的转维护申请不生成工作台任务。

## 6. 任务来源与聚合规则

### 6.1 通用规则

- 只展示当前登录用户为处理人的任务。
- 只展示当前用户拥有对应项目和模块查看权限的任务。
- 管理组绕过项目权限的既有逻辑保持不变。
- 转维护检查项、评审要素、Block 任务和遗留任务不逐条拆成工作台行。
- 默认排序为：待处理优先、生成时间倒序、任务名称和任务 ID 稳定排序。

### 6.2 计划任务

- 继续从一级计划、二级计划、整机市场计划和 tOS 类型计划中聚合。
- 保留项目、计划层级、计划实例、版本、市场和 tOS 类型的精确路由信息。
- 聚合时不再排除已完成任务；已完成任务进入“全部”和“已完成”页签。
- 计划任务没有真实生成时间时显示“未记录”，不再使用工作台当前日期作为替代值。

### 6.3 转维护任务

每个未取消申请最多按流程节点生成三类任务：

- 资料录入：处理人为申请人映射后的 PMS 用户。
- 维护审核：处理人为维护团队中的 SPM 映射用户。
- SQA 审核：处理人为研发团队中的 SQA 映射用户。

只有当前节点或已经真实完成的历史节点生成任务。外部转维护用户与 PMS 用户继续通过显式映射表匹配；无法可靠映射时不生成任务，不根据项目负责人猜测处理人。

## 7. 表格字段契约

表格列顺序和表头固定如下：

| 顺序 | 表头 | 数据规则 | 展示规则 |
| --- | --- | --- | --- |
| 1 | 任务名称 | 计划使用真实任务名；转维护使用对应节点的任务名称 | 单行省略，悬浮展示全文 |
| 2 | 所属项目 | `projectName` | 无关联项目时显示“未关联项目” |
| 3 | 状态 | 工作台归一化状态 | 仅显示“待处理”或“已完成”标签 |
| 4 | 任务节点 | 计划层级/具体二级计划，或转维护节点名称 | 单行省略，悬浮展示全文 |
| 5 | 任务内容 | 计划名称、市场、tOS 类型、版本等上下文；转维护使用申请备注 | 无内容时显示“—”，长文本省略并悬浮展示全文 |
| 6 | 处理人 | 当前任务处理人 | 显示真实映射后的 PMS 用户名 |
| 7 | 生成时间 | 计划 `generatedAt`；转维护申请 `createdAt` | 格式化为 `YYYY-MM-DD`，无值显示“未记录” |
| 8 | 操作 | 根据状态和路由生成 | 待处理显示“前往处理”，已完成显示“查看详情” |

建议的核心表格模型：

```ts
interface WorkbenchTodo {
  id: string
  source: 'plan' | 'transfer'
  title: string
  projectId: string
  projectName: string
  status: 'pending' | 'completed'
  nodeLabel: string
  taskContent: string
  assignee: string
  generatedAt: string
  completedAt?: string
  route: WorkbenchTodoRoute
}
```

`dueDate` 可继续保留在内部模型中供既有兼容逻辑使用，但本次界面不显示截止时间，也不基于逾期生成第三种状态。

## 8. 筛选与分页

### 8.1 筛选顺序

筛选从外到内组合生效：

1. 当前登录用户与权限。
2. 左侧任务目录。
3. 状态页签。
4. 搜索、所属项目、生成时间。

搜索匹配：任务名称、所属项目、任务节点、任务内容和处理人。

所属项目为单选下拉，可清空；选项只来自当前用户可见任务。生成时间为日期范围，开始和结束日期均为包含关系。保留“清空筛选”按钮，但清空只重置搜索、项目和日期，不改变当前目录与状态页签。

### 8.2 分页

- 默认每页 10 条。
- 支持 10、20、50 条。
- 显示筛选后的总条数。
- 数据变化导致当前页超出范围时，回到最后一个有效页；筛选主动变化时回到第一页。
- 操作列固定在右侧；窄宽度下表格横向滚动。

## 9. 操作与路由

### 9.1 计划任务

- 待处理和已完成任务均直接进入对应项目的计划模块。
- 恢复精确的计划层级、计划实例、版本、市场或 tOS 类型。
- 待处理按钮文案为“前往处理”；已完成按钮文案为“查看详情”。
- 进入后继续使用现有权限检查、`navigateWithEditGuard`、项目激活和一次性 `planNavigationIntent`。

### 9.2 转维护任务

- 待处理任务进入资料录入、维护审核或 SQA 审核的对应处理页。
- 已完成任务进入该转维护申请的详情页，不重新打开已完成节点的编辑态。
- 继续验证项目、申请和权限存在性；验证失败时显示明确警告并停止跳转。

### 9.3 返回来源兼容

保留工作台来源标记，使用户从任务进入项目空间后返回个人工作台。原有 `workbenchTab: 'todo'` 可作为内部兼容值继续存在；不再渲染或恢复 `workTracker`。历史的 `workTracker` 来源统一回退到工作台任务页。

## 10. 组件边界

### 10.1 `WorkbenchContainer`

- 负责读取项目、计划、转维护、权限和当前用户状态。
- 负责构建并过滤任务候选。
- 负责智能默认目录/状态所需的输入。
- 负责直接进入计划或转维护页面的路由。
- 移除 `WorkTracker` 的导入、切换和渲染。

### 10.2 `TodoCenter`

- 负责目录、状态、搜索、项目、日期和分页的页面状态。
- 负责桌面左右布局和窄屏横向目录布局。
- 负责八列表格、状态标签、加载、错误和空状态。
- 不直接读取业务 Store，不负责项目空间导航。

### 10.3 `todoAggregation`

- 保持纯函数，不读取系统当前时间。
- 负责计划和转维护候选生成、权限前过滤输入、状态归一化、排序和组合筛选。
- 增加可独立验证的默认目录/状态选择函数。
- 生成时间只格式化真实输入；缺失时返回空值。

## 11. 视觉与响应式

- 沿用 `pms-glass-surface`、`pms-solid-surface`、`pms-table` 和现有主题变量。
- 主体使用单一玻璃容器，左侧目录与右侧数据区通过轻边框区分。
- 使用紫色目录选中态、紫色状态下划线、浅橙待处理标签和浅绿已完成标签。
- 表格保持紧凑行高和清晰列分隔，不复制 ONES 的灰色企业后台样式。
- 所有可点击元素具有可见的悬浮、键盘焦点和选中状态。
- 窄屏时目录移动到表格上方；表格不强制压缩八列，使用横向滚动保证字段可读性。
- 遵守 `prefers-reduced-motion`。

## 12. 状态与错误反馈

- 加载：使用骨架屏保留表格最终占位。
- 加载失败：显示错误说明和“重新加载”按钮。
- 当前目录无任务：显示“暂无计划任务”或“暂无转维护任务”。
- 当前状态无结果：显示“暂无待处理任务”或“暂无已完成任务”。
- 筛选无结果：显示“暂无符合条件的任务”。
- 结果数量使用 `aria-live` 通知辅助技术。
- 操作按钮辅助文本包含任务名称和操作目的。

## 13. 测试与验收

### 13.1 聚合与筛选验证

- 计划未完成状态全部归一为 `pending`，计划完成状态归一为 `completed`。
- 转维护 `in_progress/failed` 节点归一为 `pending`，`success` 节点归一为 `completed`，`not_started` 不生成任务。
- 已取消转维护申请不生成任务。
- 当前用户、权限、目录、状态、搜索、项目和生成时间筛选可组合生效。
- 缺失生成时间显示“未记录”，不使用当前日期兜底。
- 智能默认规则覆盖：计划有待处理、仅转维护有待处理、两类均有待处理、两类均无待处理。

### 13.2 源码契约验证

- 工作台不再渲染“工作跟踪”或模块切换。
- 左侧目录严格为“计划 / 转维护”。
- 状态严格为“全部 / 待处理 / 已完成”。
- 表头严格为任务名称、所属项目、状态、任务节点、任务内容、处理人、生成时间、操作。
- 不出现第三种工作台状态。
- 待处理与已完成操作分别显示“前往处理 / 查看详情”。

### 13.3 项目验证命令

```bash
npm run verify:workbench-split
npm run verify:todo-center
node node_modules/typescript/bin/tsc --noEmit
node node_modules/next/dist/bin/next build
git diff --check
```

若 `.bin/tsc` 或 `.bin/next` 在当前环境中可执行，也可使用仓库常规命令 `npx tsc --noEmit` 和 `npm run build`。

### 13.4 浏览器验收

1. 当前用户默认进入第一个有待处理任务的目录和“待处理”页签。
2. 两类均无待处理时进入“计划 / 全部”。
3. 计划和转维护目录切换正确更新状态数量、项目选项和表格数据。
4. 全部、待处理、已完成页签只显示对应状态。
5. 搜索、项目、日期和清空筛选正确组合，分页按规则重置。
6. 待处理任务直接进入精确处理页；已完成任务进入只读查看路径。
7. 切换用户后重新计算默认目录与状态，且不泄露其他用户任务。
8. 桌面左右布局、窄屏目录切换、横向表格滚动和固定操作列均可用。
9. 页面无未预期控制台错误或 hydration 错误。

## 14. 验收结论

当且仅当以下条件同时满足时，本次工作台改造视为完成：

- 页面结构、目录、状态、筛选和八列表头符合本规格。
- 计划与转维护的待处理、已完成数据均可正确聚合和过滤。
- 直接处理/查看路由、权限和编辑离开保护没有回归。
- 契约验证、类型检查、生产构建和浏览器验收全部通过。
