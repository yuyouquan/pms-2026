# tOS 路标两位版本聚合设计

## 目标

将“项目路标视图”统一改名为“tOS 路标视图”，以 tOS 版本维护中的两位版本为唯一主数据，并将待规划项目和正式项目按业务规则聚合到对应版本中。

## 命名与工具栏

- 项目视图 Tab、页面标题及相关可见文案统一使用“tOS 路标视图”。
- 工具栏文案调整为：
  - “展开全部目标 / 收起全部目标”改为“展开目标 / 收起目标”。
  - “解决冲突”改为“冲突”。
  - “修改记录”改为“记录”。
  - “创建待规划项目”改为“创建项目”。
- 抽屉、弹窗内的业务标题仍可使用“修改记录”“待规划项目”等完整语义，避免操作含义不清。

## tOS 版本主数据

- tOS 版本维护只允许填写两位版本，标准格式为 `tOS 16.3`、`tOS 17.0`。
- tOS 路标视图只展示维护列表中的版本，不根据项目数据动态生成版本列。
- 旧三位版本迁移为相同 `major.minor` 的两位版本；相同两位版本只保留一条维护配置，优先保留最近更新的数据。
- 所有指向旧三位版本的项目引用迁移到对应的两位维护版本。
- 删除保护、排序、筛选和版本目标均基于两位维护版本。

## 项目版本映射

- 待规划项目创建和编辑字段由“首销 tOS 版本”改为“tOS 版本”，直接选择维护中的两位版本。
- 正式项目为新品时，取“首销 tOS 版本”的前两位。
- 正式项目为老品时，取“当前 tOS 版本”的前两位。
- 项目只有在对应两位版本已存在于维护列表中时才进入该版本列。
- 冲突识别仍按项目名、Android 版本、产品类型判断，不受版本聚合方式影响。

## 日期预估

- 待规划项目的 STR5 时间和上市时间均提供独立“预估”复选框。
- 预估状态随项目保存、编辑和持久化。
- 表单视图与版本演进卡片中，预估日期显示金色“预估”标签。
- 日期预估状态不进入修改记录字段白名单。

## 版本演进卡片

- 卡片固定标题为“市场名（项目名）”。
- 删除标题右侧的“正常项目 / 待规划 / 只读”等来源状态标签。
- STR5 时间和上市时间保留字段标题。
- 其他已选择字段只显示值，不显示字段标题。
- 产品线字段在版本演进视图列设置中默认不勾选；用户仍可手动启用。
- 表单视图既有默认列配置不受该项影响。

## Mock 数据

- tOS 维护 mock 全部刷新为两位版本。
- 待规划项目 mock 使用维护版本 ID。
- 正式新品 mock 通过首销 tOS 版本进入路标。
- 正式老品 mock 补充当前 tOS 版本，并通过当前版本进入路标。
- 增加上市时间预估样例，并保留 STR5 预估样例。
- mock 中至少包含多个项目聚合到同一两位版本列，以及正常项目与待规划项目冲突的场景。

## 数据迁移与兼容

- 持久化版本升级，迁移时规范化旧版本名称、稳定 ID、项目引用、筛选条件和修改记录展示值。
- 同一 `major.minor` 的旧维护项合并时，以最近更新时间记录的项目周期和目标为准，不计算日期并集。
- 无法映射到维护版本的项目保留在源数据中，但不进入 tOS 路标视图。

## 验收

- 全量路标校验通过。
- TypeScript 检查通过。
- 本地浏览器验证改名、短工具栏、两位版本维护、版本聚合、正式新品/老品映射、双日期预估及卡片布局。
- 本地开发服务保持可访问，CSS 资源返回 200。
