# 技术项目基础信息与计划界面统一设计

日期：2026-08-03  
状态：待用户最终复核  
范围：技术项目空间的“基础信息”和“计划”两个入口

## 1. 背景与问题

当前技术项目空间虽然已经具备技术项目核心字段、IPM 子任务、团队、交付物、TDT 计划和子任务计划的数据结构，但页面信息架构与原始需求不一致：

- “基础信息”只显示子任务基础信息 Tab。
- 核心信息、团队信息和交付物信息被放在“概况”。
- 完整计划被放在独立的技术计划组件中，页面框架和整机计划不一致。
- 技术计划组件只实现了部分整机计划能力，横版、筛选、计划克隆、展开收起、完整版本对比、分享等能力缺失或弱化。
- 当前测试明确断言“技术基础信息只显示子任务”，反而固化了错误实现，导致测试通过但页面不符合原始需求。

本次修复不改变已确认的技术项目业务模型，而是纠正页面归属和组件复用边界。

## 2. 最高设计原则

技术项目与整机产品项目的基础信息、计划页面只有个别功能模块和填写内容不同，大体显示框架、交互方式、反馈状态和操作位置必须一致。

实现上禁止继续维护一套独立简化的技术项目页面。应抽取并复用公共页面骨架，通过项目类型适配器和扩展插槽表达业务差异。

## 3. 基础信息页面结构

### 3.1 公共框架

技术项目基础信息页沿用整机项目框架：

1. 顶部核心板块。
2. TDT／子任务 Tab 区。
3. 当前 Tab 的项目计划模块。
4. 当前 Tab 的基础信息模块；无内容的 Tab 不渲染该模块。
5. 项目公共团队信息模块。
6. 项目公共交付物信息模块。
7. 与整机一致的内容宽度、卡片标题、留白、右侧锚点导航、编辑按钮和滚动行为。

基础信息、团队信息和交付物信息默认折叠；当前 Tab 的项目计划模块默认展开。

### 3.2 核心板块

核心板块固定展示 TDT 主项目字段：

- 项目名称。
- 项目分类：显示项目二级分类。
- 技术赛道：来自 IPM。
- TMG 及技术领域。
- 子领域。
- 项目阶段：从最新已发布 TDT 计划的一级任务日期计算。
- 前置项目。
- 项目年份。
- 项目价值：独占一整行。

字段为空时展示统一空值，不改变布局。编辑仍使用技术项目创建／编辑字段规则，技术项目负责人继续同步为项目责任人。

### 3.3 Tab 与模块联动

Tab 顺序固定为：

1. `TDT`。
2. IPM 返回的活动子任务，按 IPM 顺序排列。
3. 开启“显示已停用”后，在原顺序中补充已停用子任务并标记只读。

Tab 控制计划模块和基础信息模块的内容：

| 当前 Tab | 项目计划模块 | 基础信息模块 |
| --- | --- | --- |
| TDT | 展示 TDT 项目计划摘要 | 不展示 |
| 活动子任务 | 展示该子任务计划摘要 | 展示该子任务四项基础信息，默认折叠 |
| 已停用子任务 | 展示历史计划摘要，只读 | 展示历史基础信息，只读，默认折叠 |

切换 Tab 时计划摘要和基础信息必须同步切换，不能保留上一个 Tab 的内容。

### 3.4 子任务基础信息与配置

子任务基础信息仅包含：

- 核心价值。
- 开发模式。
- 首导 tOS。
- 首导整机产品。

配置按钮紧邻对应子任务 Tab。配置 Modal 沿用整机市场配置的交互规格：打开、校验、保存、取消、焦点恢复和保存反馈一致。子任务不可删除。

核心价值和开发模式未完成时，Tab 显示“待配置”，且该子任务不可创建计划修订。已停用子任务不显示可编辑配置入口。

### 3.5 团队信息

团队信息属于 TDT 主项目，不跟随 Tab 切换，使用与整机项目一致的人员卡片布局，默认折叠。

固定显示：

- 技术项目负责人。
- 技术项目经理。
- 测试代表。
- 质量代表。
- 产品代表。
- 标准化代表。

权限配置中维护的其他角色追加在固定角色之后。空角色显示统一“未配置”状态。

### 3.6 交付物信息

交付物信息属于 TDT 主项目，不跟随 Tab 切换，使用与整机信息模块一致的折叠卡片，默认折叠。

固定显示：

- 项目 KPI 文件。
- 概设。
- charter 报告。
- PDCP 报告。
- TDCP 报告。
- EDCP 报告。

链接和附件沿用现有安全打开及附件元数据展示规则。

### 3.7 “概况”入口调整

现有技术项目“概况”中的核心信息、团队和交付物迁回“基础信息”。“概况”不再保留一套重复的技术项目专属内容，其行为与整机项目保持一致，避免同一数据在两个入口分别维护。

## 4. 基础信息中的计划摘要

基础信息页只展示当前 Tab 的计划摘要，不承载修订、发布、导入导出等完整维护操作。

摘要采用与整机基础信息中“计划信息”相同的卡片、版本行和里程碑横表框架：

- TDT 使用当前 TDT 计划作用域的版本和任务。
- 子任务使用当前子任务独立计划作用域的版本和任务。
- 版本、阶段、里程碑、计划时间和实际时间取当前作用域数据。
- 没有版本或计划数据时展示统一空状态。
- 已停用子任务只展示最后有效的历史摘要。

完整计划维护仍在左侧“计划”入口进行。

## 5. 完整计划页面统一

### 5.1 公共计划工作台

抽取整机计划的公共工作台骨架，由整机和技术项目共同使用：

- 分类／作用域 Tab。
- 版本选择和版本状态。
- 自动保存提示。
- 创建修订、发布、取消修订。
- 计划克隆。
- 筛选悬浮框。
- 列设置悬浮框。
- 全部展开、全部收起。
- 竖版表格、横版里程碑、甘特图。
- 完整版本对比。
- 导入、导出、分享。
- 新增任务、拖拽排序和删除。
- 编辑离开保护。
- 权限禁用、原因提示和操作反馈。
- 日期范围、父子层级和发布前校验。

布局、控件顺序、按钮形态、Tooltip、空状态、加载状态、滚动区域和浮层交互与整机保持一致。

### 5.2 技术项目作用域差异

技术项目只通过适配器提供以下差异：

- `TDT项目计划` 固定为第一个作用域。
- 活动子任务按 IPM 顺序排列在 TDT 后。
- 子任务配置按钮紧邻对应 Tab。
- TDT 计划最多支持两级任务。
- 子任务计划只支持一级任务。
- TDT 与每个子任务分别维护独立版本序列、草稿和列配置。
- 未配置完成的子任务不可创建修订。
- 已停用子任务只读，可查看历史版本。
- 技术项目阶段仅由最新已发布 TDT 计划的一级任务计算。

整机的市场、tOS 类型、一级／二级计划等专属选择器不出现在技术项目中。

### 5.3 版本与编辑规则

- 每个作用域同时最多一个“修订中”版本。
- 仅“修订中”版本可编辑。
- 切换 Tab 或版本前沿用现有编辑离开保护。
- 发布前验证日期顺序及子任务日期位于父任务范围内。
- TDT 允许新增一级和二级任务；子任务计划只能新增一级任务。
- 发布、取消修订、导入、删除等操作沿用整机相同确认和反馈方式。

## 6. 组件与数据边界

### 6.1 公共组件

从现有整机实现中提取：

- 基础信息页面外壳。
- 核心信息卡片。
- 计划摘要卡片。
- 可折叠信息模块。
- 团队人员卡片。
- 计划作用域 Tab。
- 版本与修订工具栏。
- 计划筛选、列设置和视图切换工具栏。
- 任务表格、横版和甘特容器。
- 完整版本对比。

### 6.2 类型适配器

整机适配器继续提供市场、tOS 类型、一级／二级计划和现有字段；技术项目适配器提供 TDT／子任务作用域、技术模板层级、子任务配置状态和停用状态。

公共组件不直接判断大量项目类型字符串，只依赖适配器返回的能力开关和数据接口。

### 6.3 数据兼容

保留当前技术项目、子任务和技术计划 Zustand 存储结构。此次调整主要改变展示与公共交互，不清空现有技术项目数据，也不重置已发布计划和修订历史。

## 7. 错误与边界状态

- IPM 同步失败：保留最后一次有效子任务列表，不新增、停用或覆盖数据。
- 重复子任务 ID：阻止本次同步并显示冲突。
- 子任务待配置：可查看基础信息和历史计划，不可创建修订。
- 子任务已停用：计划和基础信息均只读。
- 无计划版本：计划摘要和完整计划显示统一空状态。
- 计划日期不合法：沿用整机红色单元格、原因 Tooltip 和发布阻止。
- 无权限：按钮保持原位置但禁用，并显示具体权限原因。

## 8. 验收与测试

### 8.1 基础信息

- 技术项目基础信息页面框架与整机一致。
- 核心板块精确显示九项字段，项目价值独占一行。
- TDT／子任务 Tab 顺序正确，计划和基础信息同步切换。
- TDT 不展示基础信息模块。
- 子任务展示四项基础信息，默认折叠。
- 团队和交付物为项目公共模块，默认折叠。
- 子任务配置 Modal、待配置、停用和恢复行为正确。

### 8.2 计划页面

- 整机与技术项目的计划工作台框架、工具栏和视图切换位置一致。
- 技术项目具备版本、修订发布、克隆、筛选、列设置、展开收起、三种视图、完整版本对比、导入导出和分享能力。
- TDT 两级和子任务一级限制有效。
- 每个作用域版本独立，切换不串数据。
- 待配置与停用限制有效。
- 日期、父子范围和发布校验与整机一致。

### 8.3 验证方式

- 更新现有技术项目契约脚本，移除“基础信息只显示子任务”的错误断言。
- 增加基础信息结构、Tab 联动、默认折叠和公共模块测试。
- 增加公共计划工作台能力矩阵测试。
- 浏览器并排检查整机与技术项目的基础信息和计划页面。
- 执行技术项目、计划、权限和项目空间相关回归脚本。
- 执行 `npx tsc --noEmit`、`npm run build` 和 `git diff --check`。

## 9. 非目标

- 不修改技术项目创建字段和 IPM 分类映射。
- 不改变技术项目权限角色规则。
- 不改变配置中心 TDT／子任务计划模板数据。
- 不重做整机市场、tOS 类型或二级计划的业务模型。
- 不把子任务升级为独立项目空间或独立权限实体。
