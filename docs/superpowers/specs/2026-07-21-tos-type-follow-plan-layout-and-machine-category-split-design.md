# tOS 主类型跟随、基础信息计划布局与整机类型拆分设计

## 1. 背景与目标

本轮在已发布的项目创建与项目空间字段改造基础上，继续完成三类调整：

1. 调整整机和 tOS 项目空间基础信息页的信息顺序，使计划信息紧跟核心模块。
2. 为 tOS 类型增加“跟随主类型”能力，同时保留计划模块的独立类型入口，并在基础信息计划摘要中合并展示跟随关系。
3. 将原“整机产品项目”拆分为“整机产品-手机”“整机产品-PAD”“整机产品-笔电”，三个类型继续共用整机业务能力。

本设计修订 `2026-07-15-tos-type-plan-dimension-design.md` 中“类型没有跟随主类型”的旧边界。未在本文明确修改的类型隔离、权限、版本和历史数据规则继续沿用原设计。

## 2. 已确认范围

### 2.1 包含

- 整机和 tOS 项目空间基础信息页的模块顺序。
- tOS 项目空间展示态隐藏“基础信息”分类。
- tOS 类型编辑增加“跟随主类型计划”。
- tOS 一级计划按主类型跟随；二级计划和版本火车继续按类型独立。
- tOS 基础信息计划摘要按跟随关系合并 Tab。
- tOS 计划摘要移除计划开始、计划结束、开发周期和健康状态。
- 三种新整机项目类型的创建、编辑、筛选、展示和整机能力路由。
- 旧“整机产品项目”数据向“整机产品-手机”的兼容迁移。

### 2.2 不包含

- tOS 二级计划或版本火车跟随主类型。
- 将整机三种项目类型拆成三套字段 Schema、三套市场规则或三套计划模板。
- 正式数据库表、迁移脚本或后端接口；当前仍使用 Mock/Zustand 状态，但保留可迁移的数据结构。
- 新增 Full、Slim、PAD、GO 之外的自定义 tOS 类型。
- 修改非目标项目类型的基础信息布局。

## 3. 方案选择

采用“类型配置增加跟随标记 + 一级计划解析有效来源 + 基础信息派生合并 Tab”的方案。

### 3.1 推荐方案

- tOS 类型配置继续保存每个类型自身的数据，只新增 `followsMain` 标记。
- 跟随类型在一级计划场景解析到当前主类型；自身历史计划不覆盖、不清空。
- 计划模块保留每个类型的独立 Tab；基础信息计划摘要根据跟随关系动态生成合并 Tab。
- 二级计划和版本火车继续使用当前选中类型作为存储作用域。

该方案能同时满足“计划模块独立展示”“基础信息合并展示”和“取消跟随恢复原计划”，且不会因为复制计划产生不可逆数据覆盖。

### 3.2 未采用方案

- **勾选跟随后立即复制主类型计划**：实现简单，但主类型后续变化容易与复制数据失步，取消跟随后也无法可靠恢复原独立计划。
- **把跟随类型和主类型合并为同一存储键**：能天然同步，但破坏既有按类型隔离的数据模型，也无法保留取消跟随后的历史数据。
- **所有计划层级全部跟随**：影响范围大，并与已确认“仅一级计划跟随”的规则冲突。

## 4. 页面信息架构

### 4.1 整机项目基础信息页

三个整机类型统一采用以下顺序：

1. 核心模块。
2. 计划信息。
3. 基础信息。
4. 扩展信息。
5. 团队信息。
6. 其他既有模块，例如转维信息，继续按原业务位置展示。

核心模块、计划信息和分类模块不得重复渲染。右侧锚点导航顺序同步调整为页面实际顺序。

### 4.2 tOS 项目基础信息页

tOS 采用以下顺序：

1. 核心模块。
2. 计划信息。
3. 团队信息。
4. 其他既有配置模块。

项目空间展示态不渲染“基础信息”折叠分类，也不显示对应字段数量和配置入口。

tOS 的基础信息字段仍保留在统一 Schema 中，并继续用于：

- 新建项目 Modal。
- 编辑项目 Modal。
- 自动聚合和只读字段回填。
- 数据保存和后续接口迁移。

因此，本次只隐藏项目空间展示分类，不删除字段定义或业务数据。

### 4.3 组件组织

- `TargetProjectInformationView` 增加核心模块后的内容插槽，用于插入计划信息。
- `ProjectInfoSections` 支持由调用方过滤展示分组；tOS 项目空间只传入团队分组。
- 新建/编辑 Modal 继续直接读取完整 Schema 分组，不受展示态过滤影响。
- `renderProjectPlanInfo()` 由基础信息页统一插入核心模块之后，移除原页面下方的重复调用。

## 5. tOS 跟随主类型规则

### 5.1 数据模型

`TosTypeConfigRow` 扩展为：

```ts
type TosTypeConfigRow = {
  id: string
  type: TosPlanType
  isMain: boolean
  followsMain: boolean
}
```

兼容规则：

- 历史配置没有 `followsMain` 时按 `false` 处理。
- 主类型的 `followsMain` 永远归一化为 `false`。
- 至少保留一个类型，且恰好存在一个主类型。
- 非主类型可独立选择是否跟随。
- 修改主类型时，清空全部既有跟随关系，行为与整机切换主市场一致，避免从类型静默改绑到新主类型。
- 删除主类型后由剩余第一项接管主类型，并清空剩余跟随关系。

项目对象中的 `versionTypes` 继续保存类型顺序，`versionType` 继续保存主类型。`followsMain` 在 Mock 阶段保存到项目级类型配置仓储；正式环境需保存到数据库的项目类型配置记录。

### 5.2 类型编辑 Modal

基础信息和计划模块的“类型编辑”继续打开同一个 Modal。表格列调整为：

| 列 | 交互 |
| --- | --- |
| 类型 | Full / Slim / PAD / GO 单选，禁止重复 |
| 主类型 | Radio，整项目唯一 |
| 跟随主类型 | Checkbox；主类型禁用并保持未选中 |
| 操作 | 删除非唯一类型 |

保存时一次性校验和归一化。取消不写入项目和类型配置。

### 5.3 一级计划有效来源

新增纯规则函数解析一级计划有效来源：

```text
独立类型 -> 自己
主类型 -> 自己
跟随类型 -> 当前主类型
```

例如：

- Full：主类型。
- GO：跟随主类型。
- PAD：不跟随。

则一级计划来源为：

- Full -> Full。
- GO -> Full。
- PAD -> PAD。

一级计划的任务、版本列表、当前版本、发布快照、计划总览中的一级部分以及基础信息横排计划均使用有效来源类型。跟随类型自己的原一级计划数据仍保存在原作用域中，不参与当前跟随展示。

取消跟随时，该类型重新使用自身作用域，恢复跟随前的独立计划和版本数据。

二级计划、二级计划元数据、二级里程碑和版本火车始终使用当前选中类型，不解析主类型来源。

### 5.4 计划模块展示

计划模块保留每个配置类型的独立入口，不合并 Tab：

- Full 显示“主”标记。
- GO 显示“跟随”标记。
- PAD 无额外标记。

选择 GO 后：

- 一级计划展示 Full 的当前一级计划。
- 一级计划区域显示“当前类型跟随 Full”的来源提示，避免用户误认为正在查看 GO 的独立数据。
- GO 下的一级计划仅允许跟随查看，不能发起修订，也不能从 GO 入口编辑或发布 Full 的计划。
- “创建修订”等一级计划维护入口禁用，并提示“当前类型跟随 Full，请切换到 Full 维护一级计划”。
- 如需编辑、修订或发布一级计划，用户必须切换到 Full；行为与整机项目的跟随主市场保持一致。
- 二级计划和版本火车仍展示 GO 自己的数据。

同时校正整机现有 Mock 交互中的规则缺口：跟随主市场的市场不能发起一级计划修订。整机跟随市场已存在的实际开始、实际结束独立维护能力保持不变，本轮不扩大为整机一级计划整体只读。

所有类型切换继续经过 `navigateWithEditGuard`。权限仍按既有基础信息和一级/二级计划权限控制。

## 6. tOS 基础信息计划摘要

### 6.1 合并 Tab 规则

基础信息计划摘要根据类型配置生成展示分组：

- 主类型和所有跟随它的类型合并为一个 Tab。
- Tab 名称按类型配置顺序使用 `&` 连接。
- 非跟随类型各自形成独立 Tab。
- 分组的 `key` 使用计划来源类型，展示文案和数据来源分离。

示例配置：Full 为主类型、GO 跟随、PAD 独立，展示：

```text
Full&GO | PAD
```

- `Full&GO` 展示 Full 的一级计划。
- `PAD` 展示 PAD 的一级计划。
- 若计划模块最后选中 GO，返回基础信息时自动映射并高亮 `Full&GO`。

### 6.2 摘要内容

tOS 摘要移除以下四项：

- 计划开始时间。
- 计划结束时间。
- 开发周期（工作日）。
- 健康状态。

Tab 内容只保留“里程碑计划（横排视图）”及其现有横排计划表格。整机计划信息的字段和配置能力不受此调整影响。

## 7. 整机项目类型拆分

### 7.1 新类型

用户可选择的整机项目类型改为：

- `整机产品-手机`
- `整机产品-PAD`
- `整机产品-笔电`

原 `整机产品项目` 不再作为新建选项展示。

### 7.2 整机能力族

增加统一的整机类型判断，例如：

```ts
isMachineProjectType(type)
```

该判断识别三个新类型，并兼容历史值 `整机产品项目`。以下能力统一改用该判断，不再直接比较单一字符串：

- 项目空间目标项目判断。
- 核心模块整机字段。
- 整机字段 Schema 和创建/编辑 Modal。
- 市场配置、主市场和跟随主市场。
- 市场维度一级计划、版本、快照和分享页。
- 项目工作台筛选、卡片和待办跳转。
- 路线图、计划汇总、配置中心和模板读取。
- 整机状态转换与其他整机专属操作。

三个新类型显示为独立项目类型值，但本轮共用同一套整机字段、市场规则和计划模板。配置中心和路线图继续将它们归入同一个整机能力族；不复制三份模板。

### 7.3 兼容迁移

- 现有 Mock 项目的 `整机产品项目` 更新为 `整机产品-手机`。
- 读取历史持久化数据时，旧值继续按整机能力族处理，并在进入编辑或再次保存时规范化为 `整机产品-手机`。
- 模板和快照读取先使用整机能力族的规范键，并兼容旧 `整机产品项目` 键，防止历史模板失效。
- 三个新类型使用同一视觉色系，但项目卡片和筛选显示完整类型名称。
- tOS 的“首发项目”候选集合包含三个新整机类型以及尚未迁移的旧整机记录。

## 8. 状态与数据流

### 8.1 选择类型

1. 用户选择一个计划模块类型 Tab。
2. 保存 `selectedTosTypeTab` 为实际类型，例如 GO。
3. 一级计划计算有效来源；GO 跟随时得到 Full。
4. 二级计划继续使用 GO。
5. 离开计划页进入基础信息时，摘要分组把 GO 映射到 `Full&GO`。

### 8.2 修改跟随配置

1. 打开统一类型编辑 Modal，复制项目当前配置到草稿。
2. 用户设置主类型和跟随关系。
3. 保存时归一化唯一主类型和跟随标记。
4. 补齐新增类型的独立计划种子，但不覆盖任何历史类型计划。
5. 当前类型若仍存在则保持选中；若被删除则切换到主类型。
6. 一级计划有效来源和基础信息合并 Tab 立即重新计算。

### 8.3 删除与重新添加

删除类型只从配置中隐藏，不删除该类型的计划、版本或快照。重新添加时恢复历史数据。该规则同时适用于独立类型和曾经跟随过的类型。

## 9. 权限、保护与错误处理

- 类型编辑继续受 `basicInfo:编辑` 控制。
- 一级和二级计划操作继续使用各自计划权限。
- 跟随类型的一级计划即使用户具备一级计划编辑权限，也不能发起修订、编辑或发布；权限不能绕过跟随只读规则。
- 类型切换和项目导航继续使用编辑离开保护。
- 至少保留一个类型；类型不可重复；主类型唯一。
- 主类型不可跟随；非法历史配置在读取时自动归一化。
- 当前类型被删除时切到主类型；当前摘要分组失效时也切到主类型分组。
- 若主类型不存在有效计划，沿用现有 tOS 模板初始化兜底，不借用其他从类型数据。
- 跟随期间不得删除、覆盖或清空从类型原历史计划。

## 10. 验证策略

按本轮快速迭代要求保留最小必要门禁。

### 10.1 纯规则验证

- 历史类型配置默认 `followsMain=false`。
- 主类型不可跟随，且始终只有一个主类型。
- 修改或删除主类型时跟随关系清空。
- Full 主、GO 跟随、PAD 独立时，摘要分组为 `Full&GO` 和 `PAD`。
- 跟随类型的一级有效来源为主类型，二级有效来源仍为自身。
- 取消跟随后恢复自身一级计划作用域。
- 删除并重新添加类型不会删除历史计划。
- 三个新整机类型和旧整机值都被识别为整机能力族。

### 10.2 集成验证

- 整机页面顺序为核心、计划、基础、扩展、团队，且计划只渲染一次。
- tOS 页面顺序为核心、计划、团队，不显示“基础信息”分类。
- tOS 新建和编辑 Modal 仍显示可编辑基础字段。
- 基础信息摘要合并 Tab，计划模块保持独立类型 Tab。
- 跟随类型一级计划展示主类型数据，二级计划保持自身数据。
- 跟随类型的一级计划创建修订、编辑和发布入口禁用，并引导切换主类型。
- 整机跟随市场不能发起一级计划修订，但既有独立实际时间维护不回退。
- tOS 计划摘要不再出现四个统计字段。
- 新建项目可选择三个新整机类型，三者都进入现有整机字段和市场流程。
- 旧整机数据不丢失，默认规范化为“整机产品-手机”。

### 10.3 工程门禁

- 聚焦规则和集成验证脚本。
- `npx tsc --noEmit`。
- `npm run build`。
- 浏览器聚焦冒烟：一个整机项目、一个 tOS 跟随项目、新建项目类型下拉。

## 11. 验收标准

- 整机和 tOS 的计划信息均紧跟核心模块。
- tOS 项目空间不再出现“基础信息”折叠分类，但编辑弹窗字段不丢失。
- 类型编辑可配置唯一主类型和多个跟随类型。
- 计划模块类型入口不合并，基础信息摘要按规则合并。
- 跟随只影响一级计划；二级计划和版本火车保持独立。
- 跟随类型不能发起一级计划修订，也不能编辑或发布主类型一级计划。
- 整机跟随市场同样不能发起一级计划修订。
- 取消跟随后恢复从类型原独立计划。
- tOS 摘要仅展示横排里程碑计划。
- 三个新整机项目类型均可创建，并完整继承现有整机能力。
- 旧整机项目兼容为“整机产品-手机”。
