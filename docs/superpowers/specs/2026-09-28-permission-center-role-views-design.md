# 权限中心角色授权与人员视图

## 已确认需求

人员配置属于角色，包含“授权人员”和“授权部门”，选择后立即生效。角色内所有功能菜单共用成员范围。右侧分为功能权限和数据权限：功能权限使用合并父菜单单元格的表格，每个子菜单显示其实际支持的功能勾选；数据权限只列出支持数据范围和列设置的菜单，保留现有筛选、列设置及紧凑标签样式。

顶部“角色视图 / 人员视图”沿用项目管理的分段切换样式。角色视图可编辑；人员视图左侧列出已授权人员（含部门覆盖人员），右侧只读显示其有效权限及来源。角色侧栏保留窄布局和收起能力，移除“角色分组”标题。功能与数据配置都在同一个内容模块中。人力资源管道仍不出现在权限配置菜单中。

## 授权与数据约束

- `PermissionCenterRole.members` 表示直接授权人员，新增 `departments` 表示角色授权部门；有效角色是直接成员或任一部门匹配。
- `MenuPolicy` 只存角色与菜单对应的功能、筛选条件和可见列；不再存人员和部门。运行时模型升级为 version 2。
- 只有固定系统超级管理员拥有全部权限。超级管理员必须保留至少一位已知人员，仍按人员授权；普通管理员没有隐式绕过。
- 多角色功能权限取并集；数据权限保留每个角色完整的行与列授权，禁止将不同角色的行条件与列做笛卡尔扩大。人员视图按来源角色显示数据规则，并注明多角色取并集。
- 人员视图只读；未授予任何功能的已配置人员仍在列表中。人员、角色和数据菜单选择、视图切换继续使用未完成筛选草稿离开保护。
- 已识别的旧版有效 mock 权限在首次载入时刷新为明确的 v2 演示角色与授权，不生成历史兼容角色。不重置项目空间权限或业务数据。已保存 v2 配置保留。损坏缓存继续拒绝授权，不能通过刷新恢复默认超级管理员。
- 初始角色分组为管理组、tOS路标组、项目组；超级管理员为演示用户01和07。其他演示授权应与实际 mock 人员、部门、品牌对应，品牌名使用实际示例品牌A/B/C。

角色创建、必填与重名校验、创建后选中、删除撤权、即时保存及保存失败状态沿用。父菜单保持真实多层结构，表格合并只允许相同完整父路径的相邻行。数据菜单目前为项目视图、项目配置、路标表单视图、版本演进图，字段以动态注册表为准。
