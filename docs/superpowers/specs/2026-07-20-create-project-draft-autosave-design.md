# 新增项目草稿实时保存设计

## 目标

新增项目弹窗中的填写内容实时保存。用户关闭弹窗或刷新页面后，再次打开时自动恢复；只有创建成功，或点击 Header 中的“重新填写”并二次确认后，才清空草稿。

本阶段使用 `localStorage` 模拟持久化。正式实现时，草稿必须存入数据库，前端只替换 Repository 实现，不改变表单交互。

## 方案选择

- 采用方案 A：按当前登录用户保存一份新增项目草稿。
- 不采用 `sessionStorage`，因为关闭浏览器后仍需恢复。
- 不只保存到 Zustand，因为页面刷新后不能丢失。

## 数据模型与边界

新增 `ProjectCreationDraftRepository`，提供 `get`、`save`、`clear` 三个异步方法。Mock 实现使用 `localStorage`，Key 由固定前缀和当前登录用户组成；正式实现替换为数据库 API。

草稿记录包含：

- `schemaVersion`
- `ownerId`
- Form 的完整值，包括项目名、项目类型、项目责任人、健康状态、各分组字段及自动推导字段
- 当前展开的分组
- `updatedAt`

草稿只作用于 `mode="create"`。编辑项目不读取、不写入、也不清除新增草稿。

## 交互与数据流

1. 打开新增项目弹窗时，根据当前登录用户读取草稿。
2. 有有效草稿时恢复完整 Form 值和展开分组，再继续执行现有的项目类型、来源回填和条件字段逻辑。
3. 无草稿时使用现有默认值：责任人为空、健康状态正常、状态待立项。
4. 表单值或展开分组变化后，延迟约 300ms 保存，合并连续输入，避免每次按键立即写存储。
5. Hydration 完成前禁止自动保存，避免默认值覆盖已有草稿。
6. 如果草稿中的项目已不在可选项目池中，则丢弃该无效草稿并恢复默认状态。
7. 关闭新增弹窗时直接关闭并保留草稿；原“关闭后内容丢失”的确认不再适用于新增模式。编辑模式继续沿用原有放弃修改确认。
8. 创建成功后清空草稿并重置 Form；提交失败时保留草稿。

## Header 与重新填写

新增模式的 Modal Header 使用左右布局：左侧“新增项目”，右侧“重新填写”按钮。按钮使用轻量危险提示样式，不与右上角关闭按钮冲突。

点击后弹出二次确认：

- 标题：`重新填写？`
- 内容：`将清空当前已填写并自动保存的全部内容，此操作不可撤销。`
- 确认按钮：`确认清空`
- 取消按钮：`继续填写`

确认后同时清除 Repository 草稿、Form 值、校验错误、聚合告警、展开分组以及项目类型/来源相关引用，并恢复新增默认值。

## 异常处理

- 读取草稿失败：回退默认空表单，不阻塞打开，并提示“项目草稿读取失败”。
- 自动保存失败：保留当前 Form 内容并提示“项目草稿自动保存失败”。
- 清空持久化草稿失败：不清空当前 Form，保持二次确认前状态并提示“项目草稿清空失败”。
- 数据库正式实现需沿用同样的成功/失败语义。

## 验证

- 新增表单填写后关闭、重开，所有字段和展开分组恢复。
- 刷新页面后草稿仍恢复，且不同登录用户之间互不影响。
- “重新填写”取消不清空；确认后 Form 与存储同时清空。
- 创建成功清空草稿；创建失败保留草稿。
- 编辑项目不受新增草稿影响。
- `npx tsc --noEmit`、`npm run build` 和聚焦浏览器路径通过。
