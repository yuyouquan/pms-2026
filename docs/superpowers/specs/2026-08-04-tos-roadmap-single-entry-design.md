# tOS 路标单入口设计

## 目标

将当前“项目视图”收敛为单一的“tOS路标”导航入口，隐藏项目计划汇总看板，并移除项目汇总看板与 tOS 路标之间的切换交互。

## 范围

- 修改主 Header 的导航名称和路标页面外壳。
- 移除用户进入项目计划汇总看板的所有当前 UI 路径。
- 不修改 tOS 路标内部的筛选、维护、版本演进、冲突处理和项目操作。
- 不删除 `ProjectPlanSummaryBoard` 组件源码及其独立业务工具，避免扩大本次变更范围。

## 导航

- Header 中 `roadmap` 模块的展示名称由“项目视图”改为“tOS路标”。
- 导航 key 和模块状态继续使用 `roadmap`，不引入状态迁移，也不影响现有 Header 选中逻辑和编辑离开保护。
- 项目空间中涉及返回该模块的通用文案同步改为“返回tOS路标”，避免出现旧名称。

## 页面结构

- `RoadmapView` 不再维护 `summary | roadmap` 本地状态。
- 删除“项目计划汇总看板 / tOS 路标视图”选项数组和顶部切换按钮组。
- 页面标题固定为“tOS路标”。
- 副标题只说明 tOS 路标、版本演进和规划信息，不再提及项目计划汇总。
- 内容区固定挂载 `ProjectRoadmapModule`，继续保留现有卡片外壳、圆角和 sticky 控件所需的 `overflow: visible`。

## 历史入口

- `RoadmapView` 不再读取项目汇总看板分享状态。
- 历史汇总看板分享 URL 进入当前应用后仍落到 `roadmap` 模块，但页面统一展示 tOS 路标，不恢复隐藏看板。
- tOS 路标自身的分享解析与业务能力仍由内部路标模块处理，本次不调整其数据协议。

## 可访问性与交互

- Header 保留文字标签和现有键盘导航能力。
- 移除切换控件后不留下空白占位、隐藏按钮或不可达焦点。
- 页面只保留一个明确标题，避免 Header、页面标题和切换选项使用三个不同名称。

## 验证

- 专项契约验证 Header 包含“tOS路标”且不再包含 `roadmap` 导航项的“项目视图”标签。
- 专项契约验证 `RoadmapView` 仅导入并挂载 `ProjectRoadmapModule`。
- 专项契约验证不存在 `activeProjectView`、`ProjectPlanSummaryBoard`、`PROJECT_VIEW_OPTIONS` 和汇总/路标切换按钮。
- TypeScript、生产构建和浏览器检查通过。
- 浏览器确认点击“tOS路标”直接进入路标页面，页面内无视图切换控件。
