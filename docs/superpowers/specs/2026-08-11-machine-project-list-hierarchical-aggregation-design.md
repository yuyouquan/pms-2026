# 整机产品项目列表多级聚合设计

## 1. 目标与范围

本次仅调整“项目列表 → 列表视图 → 整机产品项目”的表格结构、默认字段和聚合交互。tOS 版本项目、技术项目、能力建设项目，以及卡片视图和日历视图不改变展示规则。

目标是将现有按产品系列单级聚合，升级为“品牌 → 产品线 → 产品系列 → 项目明细”的多级聚合，并严格按 UI 截图调整整机产品项目表格的默认字段顺序。截图中出现的字段全部为必显字段，在“字段配置”中不可隐藏；其他基础信息字段继续允许用户配置显隐和排序。

## 2. 表格字段与顺序

整机产品项目列表默认字段按以下顺序展示：

1. 品牌
2. 产品线

4. 项目数
5. 市场名
6. 项目名
7. 版本类型
8. 首销 tOS 版本
9. 产品类型
10. 研发模式
11. 安卓版本
12. 芯片编码
13. 概念启动
14. STR1
15. STR2
16. STR3
17. STR4
18. STR4A
19. STR5
20. 产品上市
21. SPM
22. SPM 部门（二级部门）

以上字段全部标记为必显且不可隐藏。字段配置面板仍显示这些字段、保留其“必显”标识和排序位置，但关闭显隐操作。其他项目基础信息字段可通过字段配置搜索、显示、隐藏和排序。

“必显”仅表示字段配置锁定，不代表横向滚动时全部固定在左侧。表格继续沿用现有固定列策略，不因本次必显规则扩大固定区域。

## 3. 多级聚合规则

### 3.1 排序与分组

筛选后的整机产品项目先按品牌、产品线、产品系列稳定分组，同组内保持当前项目排序。分组键为空、`-` 或 `—` 时分别归入“未配置品牌”“未配置产品线”“未配置产品系列”，避免空值生成多个不可识别分组。

聚合层级为：

```text
品牌
└── 产品线
    └── 产品系列
        ├── 项目明细 1
        ├── 项目明细 2
        └── 项目明细 N
```

### 3.2 合并单元格

- 品牌单元格跨该品牌下所有可见产品线、产品系列和项目明细行合并。
- 产品线单元格跨同品牌、同产品线下所有可见产品系列和项目明细行合并。
- 产品系列单元格跨该系列下所有可见项目明细行合并。
- 项目数与产品系列使用相同 `rowSpan`，值为该产品系列在完整筛选结果中的项目明细数量，不因分页或折叠减少。
- 市场名及其后的字段按项目明细逐行展示，不参与合并。

分页在聚合前作用于项目明细结果。每页仅对本页项目重新计算品牌、产品线、产品系列的 `rowSpan`，不允许合并单元格跨页；项目数仍读取完整筛选结果中的系列数量。同一系列跨页时，每页首条可见明细重复展示系列聚合单元格和完整项目数。

### 3.3 展开与收起

仅产品系列提供展开/收起操作，品牌和产品线只承担层级合并展示，不提供独立折叠入口。

- 展开：展示该产品系列在当前页的全部项目明细。
- 收起：保留该产品系列的第一条项目明细作为摘要行，隐藏同系列的其余项目行。
- 收起后项目数仍显示筛选结果中的完整数量，不随隐藏行减少。
- 切换分类、筛选条件或分页后，继续沿用当前产品系列折叠状态；已经不在结果集中的分组不产生空白行。

## 4. 字段来源

| 展示字段 | 数据来源或计算规则 |
|---|---|
| 品牌 | 项目基础信息 `brand` |
| 产品线 | 项目基础信息 `productLine` |
| 产品系列 | 项目基础信息 `productSeries` |
| 项目数 | 完整筛选结果中同品牌、同产品线、同产品系列的项目明细数量 |
| 市场名 | 项目基础信息 `marketName` |
| 项目名 | 项目名称 |
| 版本类型 | 项目基础信息 `versionType` |
| 首销 tOS 版本 | 项目基础信息 `firstSaleTosVersion` |
| 产品类型 | 项目基础信息 `productType` |
| 研发模式 | 项目基础信息 `developMode`；缺失时显示 `-` |
| 安卓版本 | 项目基础信息 `androidVersion` |
| 芯片编码 | 项目基础信息 `chipCode` |
| 里程碑 | 整机产品项目对应计划模板的最新已发布任务及项目计划日期 |
| SPM | 项目基础信息 `spm` |
| SPM 部门（二级部门） | 项目基础信息 `machineSpmDepartment`；缺失显示 `-` |

## 5. 里程碑分组

里程碑继续由整机产品项目计划模板驱动，不复制为静态业务数据。默认字段按截图分组：

| 阶段分组 | 节点 |
|---|---|
| 概念 | 概念启动、STR1 |
| 计划 | STR2、STR3 |
| 开发 | STR4 |
| 验证 | STR4A、STR5 |
| 上市保障 | 产品上市 |

节点无计划版本或无日期时显示 `-`。节点已逾期且未完成时继续使用现有红色高亮规则。字段配置不得改变同一阶段内里程碑节点的业务顺序。

## 6. 组件与实现边界

本次在现有 `ProjectSummaryTable` 和项目列表矩阵定义上扩展，不新建独立整机列表组件：

- `projectListMatrix.ts` 负责整机默认字段、必显属性、顺序及字段来源定义。
- 新增通用的多级分组/行合并计算函数，输入项目行和分组键，输出每行各层级的 `rowSpan`、系列项目数和系列索引。
- `ProjectSummaryTable` 根据整机列表变体启用多级聚合；其他项目类型沿用现有普通表格逻辑。
- 原单级 `groupBy` 产品系列能力升级为明确的整机多级聚合配置，避免把整机规则扩散到 tOS 和技术项目。
- 表头与内容共用同一字段宽度定义，保持固定列、横向滚动和分组表头对齐。

## 7. 筛选、分页与字段配置联动

- 分类、项目状态、高级筛选和“我的/全部”先得到统一项目结果集，再执行分页和本页聚合。
- 筛选变化后分页回到第一页，并基于新结果重新计算项目数和行合并。
- 分类数字仍按统一筛选结果计算，不使用聚合后的可见行数。
- 字段配置中截图字段全部带“必显”标识，显隐按钮禁用；其他字段允许配置。
- 重置字段配置恢复本设计规定的默认字段顺序和必显集合。

## 8. 异常与降级

- 品牌、产品线、产品系列为空时进入对应“未配置”分组。
- 研发模式、安卓版本、市场名、SPM 部门等普通字段为空时显示 `-`。
- 计划模板缺少截图中的某个里程碑节点时仍保留必显列，单元格显示 `-`，避免不同项目间表格结构变化。
- 同名产品系列位于不同品牌或不同产品线时必须分别统计，不可跨品牌或产品线合并。

## 9. 验收与测试

### 9.1 数据聚合

- 同品牌、同产品线、同产品系列的三条项目合并为一个系列单元格，项目数为 3。
- 同品牌、同产品线但不同产品系列分别计算项目数。
- 同产品系列名称出现在不同品牌或不同产品线时不合并。
- 空品牌、空产品线、空产品系列分别进入对应未配置分组。

### 9.2 展开收起

- 产品系列默认展开，点击后只保留摘要行，再次点击恢复全部明细。
- 折叠时项目数保持完整值。
- 品牌和产品线没有额外折叠入口。

### 9.3 字段与表格

- 默认字段、顺序和阶段分组与 UI 截图一致。
- 截图字段在字段配置中全部标记为必显且不可隐藏。
- 其他基础信息字段可搜索、显示、隐藏和排序。
- 表头和内容列宽对齐，横向滚动无重叠、空行或固定列错位。

### 9.4 联动与回归

- 筛选、我的/全部、分页切换后项目数和合并单元格正确重算。
- tOS 版本项目、技术项目和能力建设项目列表不受影响。
- 卡片视图和日历视图的结果集、分页及权限逻辑不受影响。
- 执行 `npx tsc --noEmit`、`npm run build`，并在浏览器中验证整机列表的聚合、折叠、字段配置和横向滚动。
