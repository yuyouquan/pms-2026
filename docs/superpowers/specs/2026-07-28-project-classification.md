# 项目分类与二级分类设计说明

## 背景

现有系统把“整机-手机、整机-平板”等值直接作为项目类型使用，无法同时表达 PMS 一级项目分类和 IPM 项目分类的映射结果。本次升级统一界面术语为“项目分类”，新增“项目二级分类”，并让工作台新建项目、tOS 路标创建项目、工作台筛选和配置中心遵循同一套分类规则。

## 已确认方案

采用兼容式升级：

- 保留现有内部 `type` 字段作为项目分类载体。
- 新增 `secondaryCategory` 字段保存项目二级分类。
- 旧数据仍可携带历史明细分类值，通过统一解析函数转换成项目分类和项目二级分类，避免清空浏览器已有数据。
- 所有用户界面把原“项目类型”统一改名为“项目分类”。

## 分类模型

一级项目分类固定为：

1. 整机产品项目
2. tOS版本项目
3. 技术项目
4. 能力建设项目

二级分类为：

- 整机产品项目：整机-手机、整机-平板、整机-笔电、整机-功能机、整机-AIOT扩品类、整机-基线项目、整机-N+1项目、整机-预研项目
- tOS版本项目：tOS版本项目
- 技术项目：中长期技术、技术项目
- 能力建设项目：能力建设项目

## tOS 路标创建项目

- 只允许创建整机产品项目下的待规划项目。
- 项目分类固定显示“整机产品项目”，不可修改。
- 项目二级分类由用户单选，候选项为整机产品项目的二级分类。
- 现有待规划项目的创建、编辑、删除和冲突检查保持不变。

## 配置中心

配置中心只按四个一级项目分类维护模板，不展示项目二级分类：

- 整机产品项目
- tOS版本项目
- 技术项目
- 能力建设项目

## 工作台筛选

筛选区从上到下为：

1. 项目分类
2. 项目二级分类
3. 状态

交互规则：

- 项目分类默认“全部”。
- 只有选择具体项目分类后才显示项目二级分类行，默认“全部”。
- 每次切换项目分类，项目二级分类和状态都重置为“全部”。
- 状态选项按项目分类独立配置，切换分类时不保留上一分类的状态。
- 整机产品项目状态为：全部、待立项、在研、上市、转维、EOS、暂停、已取消、规划中。
- 其他分类状态为：全部、待立项、在研、上市、EOS、暂停、已取消、规划中。
- 项目分类为“全部”时不显示二级分类行，状态保持“全部”。

## 兼容与边界

- 统一分类解析函数负责识别旧的整机明细 `type` 值，并补全对应一级、二级分类。
- 新建项目保存规范化后的一级分类和二级分类。
- 正式项目与待规划项目的既有权限、只读边界和冲突规则不因分类升级而改变。
- 本仓库当前使用 Mock IPM 项目池；本次把 IPM 项目分类名称加入 Mock 数据，并将映射封装成独立纯函数，后续接入真实接口时复用。

## 验收标准

- 工作台新建项目选择项目名后，分类字段立即自动填充且不可编辑。
- 未映射项目无法提交，并显示管理员提示。
- tOS 路标创建项目固定为整机产品项目，可选择对应二级分类。
- 配置中心只出现四个一级分类。
- 工作台分类、二级分类、状态三行筛选联动正确。
- 刷新后新建项目的分类数据仍然存在，旧项目仍能正确归类。
- `npx tsc --noEmit` 与 `npm run build` 通过。
