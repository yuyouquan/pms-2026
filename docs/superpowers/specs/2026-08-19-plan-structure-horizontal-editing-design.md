# 一级计划结构锁定与横版编辑设计

## 目标

统一项目空间基础信息与计划页的一级计划横版展示，锁定模板初始化活动的结构，同时保留整机产品和技术项目子项目的明确修订特例，并修复技术子项目自定义活动序号与名称编辑问题。

## 范围

- 项目空间基础信息中的一级计划横版视图。
- 项目空间计划中的一级计划横版、竖版修订视图。
- 技术项目的 TDT 项目计划与子项目计划。
- 不修改三级计划及配置中心模板编辑流程。

## 横版展示

1. 阶段表头只显示阶段名称，不再显示阶段时间范围。
2. 阶段名称右侧原百分比改为阶段预估工期，格式为 `N天`；没有可计算工期时显示 `-`。
3. 开发周期显示所有一级活动预估工期之和；实际行仍按现有实际周期逻辑展示。
4. 基础信息和计划页复用同一规则，整机、tOS、能力建设、技术 TDT 与技术子项目样式保持一致。
5. 去除修订版本横版的“横版只读”标签；甘特图只读提示不在本次范围内。

## 模板任务结构锁定

任务保留来源语义：模板初始化任务为 `template`，用户在项目修订中新增的任务为 `custom`。现有持久化数据通过当前项目计划对应的模板任务 ID 安全回填来源，不覆盖用户已有字段。

模板任务在项目空间修订中遵守以下规则：

- 不可新增同级活动。
- 不可删除。
- 不可修改活动名称。
- 不可参与排序；拖拽自定义任务时也不得改变模板任务之间的相对顺序。
- 日期字段继续执行现有一级计划治理规则和权限规则。

## 结构特例

### 整机产品项目

- 仅“上市收编阶段”允许新增二级任务。
- 新增二级任务标记为 `custom`，可改名、同级排序和删除。
- “上市收编阶段”及其模板原有二级任务仍为 `template`，不可改名、排序或删除。
- 其他阶段不能新增任务。

### 技术项目 TDT 项目计划

- 不开放一级或二级活动的结构新增、删除、改名、排序。
- 日期编辑继续沿用已有修订权限。

### 技术项目子项目计划

- 允许新增一级活动，不允许新增二级活动。
- 新增活动标记为 `custom`，名称可编辑、可同级排序、可删除。
- 模板原有一级活动保持锁定。
- 序号是展示与业务序号，不再暴露内部 UUID。新增后按当前根任务顺序连续编号，拖动后重新编号为 `1、2、3……`。

## 技术项目基础信息横版编辑

- 横版展示所有用户可查看的已发布版本；有计划维护权限的用户还可看到修订版本。
- 仅当前修订版本行的节点计划完成时间可编辑。
- “实际”行的节点实际完成时间可编辑。
- 历史已发布版本保持只读。
- 修改写入技术计划 Zustand 实例，与计划页同一作用域、同一版本数据同步。
- 编辑继续执行技术计划日期校验；非法日期单元格使用现有红色错误样式，发布前仍会阻断。
- 编辑入口按技术计划维护权限控制，不使用基础信息编辑权限替代计划权限。

## 数据与兼容性

- 模板任务来源由初始化链路写入；旧数据按计划对应模板的稳定任务 ID 回填。
- 自定义活动生成内部唯一 ID，但展示序号由同级顺序派生，持久化时同步标准化序号与 order。
- 修订复制、发布和取消修订均保留任务来源，避免后续修订把自定义任务误判为模板任务。
- 不清空、不重建现有用户计划数据。

## 验收标准

1. 基础信息和计划页横版阶段不显示时间范围，只显示阶段名与 `N天` 工期。
2. 横版不出现“横版只读”。
3. 普通模板任务无新增、删除、改名或拖拽入口，直接调用更新动作也被拒绝。
4. 整机“上市收编阶段”自定义二级任务可增、改名、排序、删，模板任务不可操作。
5. 技术子项目自定义一级活动显示连续数字序号，可改名、排序、删除；模板活动锁定。
6. 技术基础信息横版的修订计划完成时间和实际完成时间可编辑，并在计划页同步出现。
7. 专项契约、TypeScript、生产构建和真实浏览器流程全部通过。
