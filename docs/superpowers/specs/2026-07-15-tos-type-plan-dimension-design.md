# tOS 版本项目类型维度计划设计

## 1. 背景与目标

整机产品项目已经支持在基础信息和计划模块中维护市场，并按市场隔离计划数据。tOS 版本项目需要增加相似的“类型”维度：用户可维护 Full、Slim、PAD、GO，指定唯一主类型，并在基础信息及计划模块中按类型查看、编辑和发布计划。

本次目标是：

- 为 tOS 版本项目增加“类型编辑”入口和 Modal。
- 支持 Full、Slim、PAD、GO 四种固定类型。
- 每个项目至少保留一个类型，且只能有一个主类型。
- 一级计划、二级计划、计划总览及对应版本数据全部按类型隔离。
- 新增类型从最新已发布的 tOS 项目计划模板初始化，之后独立演进。
- 保持整机产品项目现有市场、跟随市场和市场版本行为不变。

## 2. 范围

### 2.1 包含

- 项目空间“基础信息”中的 tOS 计划信息卡片。
- 项目空间“计划”中的一级计划、二级计划和计划总览。
- 类型配置、主类型、默认选中类型和类型切换。
- 类型级的任务、二级计划定义、元数据、里程碑、版本链和发布快照。
- 现有 tOS 模拟项目的兼容初始化。
- 基本信息编辑权限和编辑离开保护。

### 2.2 不包含

- 类型跟随主类型、自动同步或自动发布。
- Full、Slim、PAD、GO 之外的自定义类型。
- 整机产品项目市场逻辑重构。
- 独立软件产品项目的类型维度。
- 只读分享页新增类型切换；分享页不属于本次“计划编辑”范围。
- 后端数据库或接口改造；当前实现继续使用前端 Mock/Zustand 状态。

## 3. 方案选择

采用“独立类型维度 + 复用现有交互模式”的方案。

- 类型配置使用独立的纯规则模块，不把类型伪装成市场。
- Zustand 使用以项目 ID 和类型为边界的类型计划状态。
- UI 沿用市场编辑的 Tabs、标签、Modal 表格和添加/删除交互。
- 整机市场的跟随、版本来源和发布逻辑不做通用化重构。

该方案比重构通用维度引擎更少触碰现有市场链路，也避免使用特殊市场键造成数据语义混乱。

## 4. 数据模型

### 4.1 类型配置

新增固定枚举：

```ts
export const TOS_TYPE_OPTIONS = ['Full', 'Slim', 'PAD', 'GO'] as const

export type TosPlanType = typeof TOS_TYPE_OPTIONS[number]

export type TosTypeConfigRow = {
  id: string
  type: TosPlanType
  isMain: boolean
}
```

项目状态新增：

```ts
selectedTosTypeTab: string
tosTypeConfigsByProjectId: Record<string, TosTypeConfigRow[]>
```

tOS 项目对象新增 `versionTypes?: TosPlanType[]`。现有标量 `versionType` 继续保留，并始终写入主类型，用于兼容当前基础信息、项目视图和其他已有消费者。

### 4.2 类型计划数据

类型计划不能沿用只按市场名索引的 `marketPlanData`。新增按项目隔离的状态：

```ts
type TosTypePlanEntry = {
  level1Tasks: any[]
  level2PlanTasks: any[]
  level2PlanMilestones: string[]
  createdLevel2Plans: Level2Plan[]
  activeLevel2Plan: string
  level2PlanMeta: Record<string, any>
}

type TosTypePlanData = Record<
  string, // projectId
  Record<string, TosTypePlanEntry> // type
>
```

版本状态使用包含项目、类型和计划层级的作用域键：

```text
project::{projectId}::tos-type::{type}::{planLevel}::versions
project::{projectId}::tos-type::{type}::{planLevel}::{versionId}::snapshot
```

这样可以保证不同 tOS 项目、不同类型、一级和二级计划之间互不串数据。

### 4.3 兼容初始化

当 tOS 项目没有类型配置时：

1. 优先读取项目现有的 `versionTypes`。
2. 若不存在，使用当前 `versionType` 作为唯一类型。
3. 若 `versionType` 也为空，使用 Full。
4. 第一个有效类型自动成为主类型。
5. 进入项目时默认选中主类型。

配置规则会过滤非法值和重复值，并保证非空配置中恰好存在一个主类型。

## 5. 类型编辑交互

### 5.1 入口

tOS 版本项目在以下两处显示“类型编辑”：

- 基础信息的计划信息卡片右上角。
- 计划模块的类型切换栏右侧。

两个入口打开同一个 Modal，使用同一份草稿和保存逻辑。

### 5.2 Modal

Modal 标题为“类型编辑”，宽度和视觉样式与“市场编辑”一致。表格列为：

| 列 | 交互 |
| --- | --- |
| 类型 | 下拉单选 Full / Slim / PAD / GO；已被其他行选择的选项禁用 |
| 是否主类型 | Radio；选中后取消其他行的主类型 |
| 操作 | 删除当前行 |

底部提供“添加类型”按钮。

校验和边界：

- 至少保留一个类型。
- 同一类型不可重复。
- 只能有一个主类型。
- 删除主类型后，剩余第一行自动成为主类型。
- 四个类型全部添加后，点击添加提示“可选类型已全部添加”。
- 删除类型只从当前项目配置中隐藏，不立即清除该类型的计划数据；重新添加时优先恢复历史数据。
- 类型编辑受 `basicInfo:编辑` 权限控制。无权限时按钮禁用并显示原因。

类型没有“是否跟随主类型”，也不会因为修改主类型而复制、覆盖或发布其他类型计划。

## 6. 基础信息

### 6.1 计划信息卡片

tOS 版本项目的原单一“计划信息”卡片改为类型 Tabs：

- Tab 文案为 Full、Slim、PAD 或 GO。
- 主类型显示“主”标签。
- 当前 Tab 展示该类型的计划开始、计划结束、开发周期、健康状态和里程碑横排视图。
- “类型编辑”放在 Tab 栏右侧。
- 切换类型通过现有 `navigateWithEditGuard`，避免未完成编辑丢失。

原有 tOS 配置信息卡片保持不变。

### 6.2 项目字段同步

保存类型配置后：

- `versionTypes` 写入当前类型顺序。
- `versionType` 写入主类型。
- 项目列表和当前选中项目同步更新。
- 若当前选中类型已被删除，切换到主类型。

## 7. 计划模块

### 7.1 类型切换栏

tOS 版本项目在一级计划、二级计划和计划总览上方显示类型切换栏：

- 左侧为“类型”标签和类型 Tag。
- 主类型 Tag 内显示“主”。
- 右侧为“类型编辑”。
- 切换类型走编辑保护。

整机产品项目继续显示市场切换栏；其他项目不显示维度切换栏。

### 7.2 全部计划隔离

切换类型后，以下数据全部指向当前 `TosTypePlanEntry`：

- 一级计划任务。
- 二级计划任务。
- 二级计划列表和当前激活计划。
- 二级计划元数据和里程碑。
- 计划总览中的一级、二级融合结果。
- 一级和二级计划的当前版本、版本列表及发布快照。

计划的搜索、过滤、甘特图、表格编辑、日期校验、创建修订、发布、版本对比和自定义列继续使用现有逻辑，但读写当前类型作用域。

切换到某个类型时，如果其 `activeLevel2Plan` 不存在，则自动选择该类型的第一个二级计划。

## 8. 新增类型初始化

新增类型时先检查该项目是否保留过对应类型的数据：

1. 存在历史数据：恢复历史数据，不重新初始化。
2. 不存在历史数据：从最新已发布的 tOS 版本项目模板创建独立副本。

一级计划初始化遵循现有模板克隆规则：

- 复制结构字段、默认值、责任角色和预估工期。
- 不复制实际开始、实际完成、实际工期、状态和进度等执行态字段。
- 没有已发布一级模板时创建空白一级计划，不读取修订中模板。

二级计划从 tOS 对应二级计划模板初始化：

- 复制固定和已配置的二级计划定义及任务结构。
- 清除项目实例执行态字段。
- 没有已发布二级模板时保留固定二级计划入口，任务为空。

每种类型得到深拷贝，后续编辑互不影响。

## 9. 权限与导航保护

- 查看和切换类型不要求编辑权限。
- 打开和保存类型编辑要求 `basicInfo:编辑`。
- 计划内的任务编辑、创建修订和发布继续使用现有一级/二级计划权限。
- 类型切换、项目切换和离开计划页均使用现有编辑保护。
- 切换项目时重新根据目标项目的主类型设置默认类型，并重置不属于目标类型的当前二级计划选择。

## 10. 错误处理

- 无有效类型：阻止保存并提示“请至少配置一个类型”。
- 重复类型：选项层禁用，规则层再次过滤。
- 可选类型用尽：提示“可选类型已全部添加”。
- 当前类型被删除：保存后切换到主类型。
- 模板不存在：使用空白计划，不借用其他类型的运行中计划。
- 历史数据存在：恢复历史数据，不覆盖用户先前编辑。

## 11. 测试与验收

### 11.1 纯规则验证

新增验证脚本覆盖：

- 合法类型枚举。
- 默认 Full 初始化。
- 从现有 `versionType` 初始化主类型。
- 去重和非法值过滤。
- 唯一主类型归一化。
- 删除主类型后的主类型接管。
- 新类型初始化与历史数据恢复。
- 不同项目、不同类型的数据深拷贝隔离。
- 版本和快照作用域键包含项目、类型、计划层级。

### 11.2 静态验证

- `npx tsc --noEmit`
- `npm run build`

### 11.3 浏览器验收

至少使用一个现有 tOS 项目验证：

1. 基础信息显示当前主类型。
2. 打开类型编辑，添加 Slim、PAD、GO，不能重复添加。
3. 修改主类型并保存，重新进入项目后默认选中新的主类型。
4. 基础信息按类型切换计划信息。
5. 一级计划分别编辑两个类型，数据互不影响。
6. 二级计划分别新增或编辑内容，数据互不影响。
7. 计划总览仅融合当前类型的数据。
8. 创建修订、发布和版本切换不会串到其他类型。
9. 删除类型后重新添加可恢复原计划。
10. 无基本信息编辑权限时不能打开类型编辑，但仍可查看和切换类型。
11. 整机产品项目的市场编辑、跟随市场和计划切换行为无回归。

## 12. 预期修改边界

预计涉及：

- 新增 tOS 类型规则模块。
- 扩展项目类型和项目 Store 的类型配置状态。
- 扩展计划 Store 的类型计划及类型版本状态。
- 修改项目空间基础信息、计划切换和类型编辑 Modal。
- 调整项目切换时的默认类型初始化。
- 增加规则验证脚本。

不会把 `ProjectSpaceContainer` 中现有市场逻辑整体重写为通用维度系统，也不会修改无关的工作台、转维、权限配置和项目视图功能。
