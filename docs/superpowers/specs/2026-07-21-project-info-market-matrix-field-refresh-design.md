# 项目信息矩阵、团队多人及字段规则刷新设计

## 目标

在现有项目基础信息迭代上完成六项收口：移除项目标题右侧重复状态标签、居中基础/扩展字段、支持团队角色多人、将市场编辑改为市场列矩阵、为计划信息增加字段配置，并以飞书字段参考文档为唯一业务口径刷新字段顺序、默认显示、可隐藏、整体必填和创建时必填。

参考文档：`https://transsioner.feishu.cn/wiki/Lwprw9vqKiLiDJkn05NcAUTEnLf`

## 已确认的界面方案

### 项目名称与核心板块

- 项目标题继续直接显示真实项目名称，例如 `X6877-D8400_H991`。
- 移除标题右侧的“在研”“正常”标签；项目状态和健康状态仍在下方核心字段中展示，避免重复。
- 核心字段的现有视觉结构、字段顺序和样式保持不变。
- 桌面项目空间内压缩字段间距和最小宽度，全部核心字段固定在一行内完整展示，不产生横向滚动。
- 本轮不改变“申请转维”“编辑”的权限和行为。

### 基础信息与扩展信息

- 分类标题、字段配置入口、折叠交互保持现有设计。
- 基础信息和扩展信息的每个单元格统一水平居中；字段名和值作为一个垂直组合整体居中。
- 字段区域采用“均衡分行”而不是固定列网格：根据当前可见字段数自动计算行数和每行字段数，最后一行的字段自动等宽铺满，不保留空白占位。例如 7 个字段显示为 `4 + 3`，8 个字段显示为 `4 + 4`，13 个字段显示为 `5 + 4 + 4`。
- 桌面端每行最多 6 个字段；中等宽度最多 4 个，窄屏最多 2 个。字段显隐变化后立即重新计算卡片宽度和行数。
- 空值继续显示 `-`，保持单元格高度一致。
- tOS 基础信息采用相同的居中规则。

### 团队信息

- 每个团队字段按“角色名｜成员列表”组织，角色名与人员信息分开，不再把角色放在人员卡片副标题中。
- 一个角色可配置零个、一个或多个人员；成员列表逐个展示头像和姓名。
- 人员过多时在角色行内自然换行，不压缩姓名，不改变其他角色的语义顺序。
- 未配置成员时显示 `未配置`，不展示问号头像。
- 新建和编辑项目时，团队角色字段统一使用人员多选控件。
- 兼容旧数据：历史单人字符串读取时标准化为单元素数组，保存后按数组写入；空字符串标准化为空数组。

### 市场编辑矩阵

- 市场编辑 Modal 改为二维表格：首列为字段名，后续每列代表一个市场，例如 OP、TR、RU。
- 市场列头展示市场标识；主市场展示“主市场”标记，非主市场提供删除按钮。
- 表格顶部提供“新增市场”选择和按钮，新增后立即追加市场列。
- 字段行固定按以下顺序展示：主市场、跟随主市场、Google Launch Date、是否运营商定制、是否锁卡、是否取消暂停、取消暂停时间、是否 MADA 管控、分支信息、Jenkins 构建、版本地址。
- “是否取消暂停”为否时，该市场列的“取消暂停时间”禁用并清空。
- 主市场不可删除；切换主市场及删除市场继续复用现有草稿保护规则。
- 点击“确定”一次性保存所有市场列；点击“取消”丢弃本次矩阵草稿。
- Modal 在常用桌面宽度完整展示三至四个市场；市场继续增加时，仅表格内容区允许横向滚动，Modal 外层不溢出。

### 计划信息字段配置

- “计划信息”标题同行右侧增加“配置字段”按钮，使用与一级计划“列设置”一致的右侧 Drawer。
- Drawer 支持勾选、取消、确定和恢复默认；不可隐藏字段置灰并标记“固定显示”。
- 配置偏好按“登录用户 + 项目”保存，同一项目的所有市场共用一套计划字段显示配置。
- Mock 阶段沿用本地偏好仓储；正式环境需要写入数据库的用户项目偏好表。
- 桌面端计划信息始终最多两行：显示字段不超过 5 个时为一行，6–9 个时按 `5 + 余数` 两行展示。
- 字段显隐不会改变字段业务值，也不会影响市场编辑中的字段可编辑性。

### 新建与编辑项目 Modal

- 桌面端由每行 3 个字段调整为每行 4 个字段，减少纵向滚动并提高录入效率。
- Modal 继续只展示可手工填写字段；自动获取、只读字段不展示。
- 1200px 以上为 4 列，900–1199px 为 3 列，640–899px 为 2 列，640px 以下为 1 列。
- 复杂字段、长文本和需要完整说明的字段可按现有 Schema 配置跨整行，不强制压缩到单列。
- 新建实时草稿保存、Header“重新填写”、二次确认清空、编辑回填和条件字段联动保持不变。

## 字段规则转换

Schema 增加独立的 `required`（整体必填）元数据，保留 `requiredOnCreate`（创建时必填）：

- 新建模式仅校验 `requiredOnCreate`。
- 编辑模式校验 `required`。
- 文档标记“自动获取”的字段为只读来源，不进入新建/编辑 Modal，也不参与手工必填校验。
- 文档单元格为空时按“否”处理；只有明确写“是”的属性才启用。
- `是否默认显示=是` 决定项目首次打开的初始显示字段。
- `是否可隐藏显示=否` 或空白时，字段固定显示且配置控件不可操作；仅明确为“是”时允许隐藏。
- 项目名称、项目类型、项目责任人继续遵循项目创建公共字段规则，不被分类字段表中的空白属性覆盖。

## 数据结构与兼容

- `ProjectInfoFieldDefinition` 增加 `required`，并继续保留 `requiredOnCreate`、`defaultVisible`、`hideable`、`readOnly`。
- 团队角色值升级为 `string[]`；读取层同时接受旧的 `string` 和新的 `string[]`，避免历史 Mock 项目丢人。
- 市场配置继续以“项目 ID + 市场标识”保存，每列对应一条 `MarketConfigRow`；矩阵只是编辑视图，不改变现有市场数据粒度。
- 计划字段偏好新增独立分组键，Mock 阶段进入现有本地偏好仓储；正式数据库键建议为 `user_id + project_id + section_key`。
- 删除市场时随市场行删除计划与构建配置；不得删除当前主市场。

## 权限与状态

- 项目信息编辑继续受 `basicInfo:编辑` 权限控制。
- 市场矩阵的新增、删除、编辑和保存沿用现有市场编辑权限。
- 计划字段配置只改变当前用户视图，不改变项目业务数据，不要求项目编辑权限；若现有字段配置入口已有权限规则，则保持一致。
- 有未保存计划草稿时，切换主市场继续弹出原有确认或阻止提示。
- Drawer 或 Modal 取消时不写入偏好和业务数据。

## 验证策略

- Schema 聚焦校验：字段顺序、枚举、默认显示、可隐藏、整体必填、创建必填与参考文档一致。
- 表单校验：创建只检查创建必填，编辑检查整体必填，自动字段不渲染且不误报。
- 团队兼容：旧单人值显示为一人，多人保存重开不丢失，空角色显示正确。
- 市场矩阵：新增/删除列、主市场保护、条件禁用、11 个字段跨市场独立保存。
- 计划字段：Drawer 取消/确定/重置，固定字段不可隐藏，刷新和切换市场后偏好保持，九字段最多两行。
- UI 冒烟：标题无重复 Tag；核心字段单行无横向滚动；基础、扩展字段名和值居中。
- 布局冒烟：展示字段 7/8/13 项时无空白占位；新建与编辑 Modal 在桌面端稳定为 4 列。
- 发布门禁：`npx tsc --noEmit`、`npm run build`、聚焦浏览器冒烟，然后推送 dev、合并并推送 master。
- 发布后更新飞书 PRD，把最新截图穿插到对应功能章节，并复查字段表、交互、持久化、验收和发布记录。

## 不在本轮范围

- 正式数据库表和后端接口实现；本轮仅保持可替换的 Mock 仓储契约。
- 非整机项目的市场维度。
- 计划字段业务值的新增计算逻辑。
- Vercel 发布；本次用户仅要求 dev 与主干推送。
