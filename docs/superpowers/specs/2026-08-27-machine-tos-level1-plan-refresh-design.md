# 整机与 tOS 一级计划更新设计

**日期：** 2026-08-27
**需求来源：** [飞书文档](https://transsioner.feishu.cn/wiki/GIK0wOTV7iIZJLkvkjnc5I9YnCe)，读取版本 `3401`
**目标分支：** `codex/level1-flat-milestones`

## 1. 目标与范围

依据飞书文档更新以下两类项目的一级计划：

- tOS 版本项目；
- 整机产品项目。

本轮恢复树形竖版，保留横版和甘特图，并同步模板、结构权限、日期规则、版本历史、筛选、导出及项目空间基础信息。技术项目、技术子项目、二级计划和三级计划不在本轮范围内。

## 2. 视图结构

### 2.1 默认视图

进入整机或 tOS 一级计划时默认显示横版。用户仍可切换竖版和甘特图。

### 2.2 竖版

竖版为两级树形结构，一级行为阶段，二级行为阶段下的节点。表格固定为以下 9 列：

1. 序号；
2. 阶段/节点；
3. 计划开始时间；
4. 计划完成时间；
5. 预估工期；
6. 实际开始时间；
7. 实际完成时间；
8. 实际工期；
9. 是否延期。

阶段支持展开和收起。树形行键使用稳定节点标识，展示序号可在结构变化后重新编号，但不得改变历史匹配身份。

### 2.3 横版

横版继续显示版本、开发周期、阶段及阶段内节点。阶段名称居中，阶段工期显示在阶段单元格右侧。

以下动态业务阶段不展示阶段工期：

- 整机：上市阶段、生命周期阶段；
- tOS：上市迭代阶段、维护阶段。

### 2.4 甘特图

- 阶段由子节点自动汇总，始终只读，不允许直接拖动或调整边界；
- 固定节点只维护完成时间，在甘特图中显示为可拖动的里程碑点；
- 整机 MR 与 tOS 版本节点维护开始和完成时间，在甘特图中显示为时间条；
- 时间条支持整体拖动、调整开始边界和调整完成边界；
- 甘特编辑能力遵循版本状态和权限规则。

## 4. 动态业务节点

### 4.1 整机 MR

整机在上市阶段和生命周期阶段新增 MR 节点。

- 入口文案保持“添加MR里程碑”；
- 点击后先二次确认，再进入名称输入；
- 默认建议下一个 MR 编号；
- 名称可修改，但必须匹配 `MR+数字`；
- 两个阶段均允许无限新增；
- 新增节点可排序和删除。

### 4.2 tOS 版本

tOS 在上市迭代阶段和维护阶段新增版本节点，两个阶段使用相同规则。

- 入口文案为“添加tOS版本”；
- 项目名称中的前两个数字段构成版本前缀；
- 第三个数字段固定为 `0`；
- 尾号为三位数字，最后一位必须为 `0` 或 `5`；
- 完整格式为 `<主版本>.<次版本>.0.<三位尾号>`；
- 例如项目 `tOS17.0` 可新增 `17.0.0.110`、`17.0.0.115`；
- 例如项目 `tOS16.3` 可新增 `16.3.0.120`、`16.3.0.125`；
- 无法从项目名称解析两个数字段时禁止保存并显示明确错误；
- 两个阶段均允许无限新增，新节点可排序和删除。

## 5. 日期与工期

### 5.1 固定节点

规划KO、CDCP、概念启动、STR1～STR5仅维护计划完成时间和实际完成时间。计划开始、实际开始、预估工期和实际工期显示为 `-`。

### 5.2 动态节点

MR 与 tOS 版本节点维护以下四个日期：

- 计划开始时间；
- 计划完成时间；
- 实际开始时间；
- 实际完成时间。

预估工期和实际工期分别按 `完成时间 - 开始时间 + 1` 计算。日期不完整时工期显示为 `-`。

### 5.3 阶段汇总

阶段日期由其节点及相邻阶段顺序自动计算，不允许手工编辑。计划和实际分别采用相同逻辑：

- 阶段开始时间取本阶段首个有效节点时间；
- 无节点开始时间的固定里程碑阶段，首阶段从首个完成点开始，后续阶段从上一阶段完成时间次日开始；
- 阶段完成时间取本阶段最后一个有效节点完成时间；
- 阶段工期按 `完成时间 - 开始时间 + 1` 计算；
- 阶段没有足够日期时对应值显示为 `-`。

## 6. 日期校验与错误反馈

计划日期和实际日期分别独立校验：

- 同一动态节点的开始时间不得晚于完成时间；
- 后一节点的完成时间不得早于前一节点的完成时间，同日允许；
- 相邻 MR 或 tOS 版本时间段不得交叠；
- 相邻阶段不得交叠；
- 日期必须为真实的 `YYYY-MM-DD`；
- 空值属于未完成输入，不单独报错。

编辑过程中允许暂存有问题的日期。存在问题时：

- 对应日期选择框和单元格标红；
- 悬停显示包含节点名称和错误原因的提示；
- 发布操作被阻止；
- 页面滚动并聚焦到第一个错误单元格。

甘特图产生非法日期时不写入计划数据，任务恢复到拖动前位置，并显示同一校验原因。

## 7. 权限与版本状态

### 7.1 日期权限

- SPM和系统超级管理员可以维护日期；
- 计划时间仅在修订中版本可修改；
- 实际时间可在修订中版本和最新已发布版本修改；
- 历史已发布版本完全只读；
- 普通成员仅可查看有权限访问的计划。

### 7.2 结构权限

- 系统超级管理员可新增、删除任意阶段和节点，用于特殊项目处理；
- SPM不能修改固定模板结构；
- SPM可在整机上市/生命周期阶段操作 MR；
- SPM可在 tOS 上市迭代/维护阶段操作 tOS 版本；
- SPM对业务节点可新增、删除和排序；
- 所有结构修改仅允许发生在修订中版本；
- 删除和排序操作需要二次确认。

## 8. 项目空间基础信息

项目空间基础信息中的以下四个时间字段只读取当前业务范围的最新已发布一级计划：

- 计划开始时间；
- 计划完成时间；
- 实际开始时间；
- 实际完成时间。

范围解析规则：

- 整机按当前市场读取；
- tOS 按当前 tOS 类型读取；
- 计划开始和实际开始取最早有效日期；
- 计划完成和实际完成取最晚有效日期；
- 没有最新已发布版本或没有有效日期时显示 `-`；
- 修订中版本的任何变更都不得影响基础信息；
- 最新已发布版本的实际时间修改成功后，基础信息立即刷新。

## 9. 版本历史、筛选与导出

- 竖版筛选、当前竖版导出和页面表格使用同一树形 9 列字段定义；
- 筛选命中子节点时保留所属阶段，命中阶段时保留该阶段节点；
- 横版导出保留版本、开发周期、阶段和节点矩阵；
- 甘特图筛选保留命中节点及其所属阶段；
- 版本对比按 `stableId` 优先、`id` 兜底匹配；
- 版本对比使用竖版 9 列并增加“变更类型”；
- 新增、删除、改名、排序和日期变化均参与比较；
- 重编号本身不得误报为新增或删除。

## 10. 数据迁移

计划存储版本升级，并按项目类型迁移一级计划：

- 空模板、空项目计划和当前已知默认 mock 替换为新模板；
- 当前标准模板按稳定节点标识迁移为整机或 tOS 专属模板；
- 对应固定节点的已有日期保留；
- 原“上市收编阶段”按项目类型映射为整机“上市阶段”或 tOS“上市迭代阶段”；
- 已有非空自定义节点和历史版本不直接删除；
- 已有自定义节点保留原稳定标识和日期，新操作开始执行新命名与权限规则；
- 迁移必须幂等，重复加载不得继续新增、删除或重编号节点；
- 市场范围、tOS 类型范围、项目快照和配置中心模板使用一致迁移入口。

## 11. 验证策略

### 11.1 规则验证

- 两类模板的阶段、节点、稳定标识和初始留空区域；
- tOS 项目名解析和版本号格式；
- MR 与 tOS 版本新增、删除、排序；
- 阶段汇总、包含首尾的工期计算；
- 计划/实际顺序、节点区间和阶段交叠校验；
- 迁移保留数据和幂等性；
- 最新已发布基础信息选择器。

### 11.2 静态与构建验证

- 一级计划相关聚焦验证脚本；
- `npx tsc --noEmit`；
- `npm run build`。

### 11.3 真实浏览器验证

分别验证整机和 tOS：

- 默认横版以及三种视图切换；
- 树形 9 列、展开收起和红框提示；
- 合法日期保存、非法日期发布阻断；
- 固定里程碑点、动态时间条和阶段只读；
- SPM、超级管理员和普通成员权限；
- MR/tOS 版本新增、排序、删除；
- 页面重开后的持久化；
- 历史版本只读和非空版本差异；
- 筛选、竖版导出、横版导出；
- 基础信息仅反映最新已发布版本。
