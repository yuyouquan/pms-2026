# 市场级构建配置编辑设计

## 目标

在整机产品项目的“市场编辑”中增加“分支信息”“Jenkins 构建”“版本地址”三个字段，并将它们由项目级共享展示调整为按市场独立保存、独立展示。用户切换 OP、TR、RU 等市场后，页面展示当前市场自己的构建配置。

本设计采用用户确认的方案 A：每个市场独立维护三个字段，已有项目平滑初始化，不建立主市场继承或跨市场联动。

## 范围

- 整机产品项目的市场纵向编辑 Modal。
- 整机产品项目“计划信息与配置信息”中的配置信息展示。
- 现有项目级构建配置到市场级构建配置的 Mock 数据兼容。
- 对应验证脚本、界面截图和飞书 PRD 更新。

本轮不修改非整机项目的构建配置逻辑，不改变市场计划字段，不接入正式数据库，也不新增主市场继承规则。

## 数据模型

`MarketConfigRow` 增加三个可选字符串字段：

- `branchInfo`：分支信息。
- `jenkinsUrl`：Jenkins 构建地址。
- `buildAddress`：版本地址。

Mock 阶段沿用 `marketConfigsByProjectId`，以“项目 ID + 市场行”保存。正式环境应将三个字段保存到数据库的项目市场配置记录中，并以项目 ID、市场标识作为稳定关联键。

### 已有数据初始化

- 已有市场行尚未包含新字段时，将项目当前的项目级分支信息、Jenkins 构建、版本地址复制到该项目的每一个现有市场。
- 初始化只补齐值为 `undefined` 的旧数据；用户明确清空后保存的空字符串必须保留，后续打开编辑器时不得再次被旧项目值回填。
- 本轮新增的市场默认三个字段均为空，避免错误继承其他市场配置。
- 主市场与跟随主市场关系不联动这三个字段，各市场始终独立编辑和保存。

## 交互设计

### 市场编辑

- 保持当前市场纵向卡片结构，在每个市场卡片中新增“构建配置”区域。
- 三个字段使用文本输入框按纵向编辑表单的网格规则排列：分支信息、Jenkins 构建、版本地址。
- 三个字段均为非必填；Jenkins 构建和版本地址不新增格式拦截，以兼容现有内部链接及历史数据。
- 点击“确定”统一保存当前 Modal 内全部市场修改；点击“取消”不写入本次草稿。
- 保持现有市场编辑权限控制、市场名称校验和取消暂停时间校验。

### 项目空间展示

- 用户切换市场 Tab 后，“配置信息”中的三个字段展示所选市场的值。
- Jenkins 构建和版本地址有值时继续显示为可在新窗口打开的链接；空值统一显示 `-`。
- 整机项目的三个字段只在“市场编辑”中修改，不再通过项目基础信息编辑状态进行内联编辑，避免项目级值覆盖市场级值。
- 非整机项目继续读取并编辑原项目级字段，行为不变。

## 状态与异常

- 未保存关闭：不更新 Store，重新打开恢复最近一次已保存值。
- 旧项目首次打开：每个已有市场看到相同的历史项目级值，可分别修改后保存。
- 用户清空字段：保存空值，展示为 `-`，再次打开仍为空。
- 新增市场：三个字段为空，不从主市场或历史项目级字段复制。
- 删除市场：随该市场配置行一并删除，保持现有市场删除行为。

## 验证策略

- 先增加失败验证，覆盖三个字段的数据结构、旧数据初始化、显式空值保留、新市场空值和市场编辑控件。
- 通过聚焦验证脚本、`npx tsc --noEmit`、`npm run build`。
- 浏览器重点验证：打开整机项目市场编辑，分别修改两个市场，保存后切换市场确认展示不同；清空一个市场字段后重开确认不被回填。
- 截取更新后的市场纵向编辑界面，用于飞书 PRD。

## PRD 与截图调整

- 在“市场纵向编辑”章节补充三个市场级字段、初始化规则和独立保存规则。
- 在“计划信息与配置信息”章节补充按当前市场展示三个字段的规则。
- 将全部现有截图从文档末尾的截图汇总区移动到对应功能章节；更新后的市场编辑截图插入市场编辑功能说明之后，不在末尾重复堆放。
- 发布完成后更新 dev、主干提交、Vercel 生产部署和验收记录。

## 验收标准

- 整机项目每个市场均可编辑并保存分支信息、Jenkins 构建、版本地址。
- 两个市场填写不同值后，切换市场展示对应值，无串值。
- 已有项目三个历史项目级值只在旧市场字段未初始化时复制到各现有市场。
- 清空已保存值后再次进入不被自动恢复；新增市场默认空值。
- 非整机项目原构建配置编辑与展示不回归。
- 飞书 PRD 字段、交互、迁移规则、验收与截图位置同步完成。
