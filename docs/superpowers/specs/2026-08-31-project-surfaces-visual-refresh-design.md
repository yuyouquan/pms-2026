# 项目列表与项目空间视觉调整设计

## 目标

在不改变既有字段顺序、字段配置、筛选、分页、拖动、权限、编辑和创建逻辑的前提下，对项目列表卡片视图、列表视图、新增项目弹窗和项目空间基础信息进行统一视觉调整，并完成三个明确的展示逻辑修正。

## 范围

### 展示逻辑修正

1. 技术项目项目空间基础信息顶部核心板块：
   - `前置项目`紧随`项目年份`显示；
   - 仅从该核心板块删除`TDT和子项目名称`卡片；
   - 新建项目、子项目配置、计划 TAB 及其他位置的名称和功能不受影响。
2. 技术项目子项目计划横版视图：
   - 子项目仅有一级活动时，不显示虚拟的`子项目计划`分组表头行；
   - `版本`、`开发周期`、一级活动名称、版本数据与实际数据保持不变。
3. 整机产品项目与 tOS 版本项目的项目空间基础信息：
   - 各市场信息区域不展示`计划开始`、`计划完成`、`实际开始`、`实际完成`；
   - 一级计划、横版计划、计划 TAB 和日期编辑能力不受影响。

### 视觉调整

1. 项目列表卡片视图：白色圆角卡片、轻边框和轻阴影；项目名、市场名、类型、核心属性、日期、负责人和更新时间形成明确层级；状态继续使用语义色胶囊。
2. 项目列表列表视图：保留现有列顺序、固定列、里程碑整块拖动、层级和横向滚动；仅统一淡紫分组表头、行高、边框、选中/悬浮态、表格容器和分页视觉。
3. 新增项目弹窗：保留字段定义、顺序、必填规则和提交逻辑；使用白色大弹窗、紫色分组标题、紧凑栅格、清晰标签与固定底部操作区。
4. 项目空间基础信息：保留信息架构和编辑入口；统一项目标题区、核心信息卡、计划信息容器、折叠分组标题和字段展示网格。

## 实现方式

采用共享样式层方案：优先复用现有组件和 DOM，通过语义 class、CSS 变量与集中样式完成视觉统一。仅在现有结构无法表达目标状态时增加小型 class 或条件渲染，不进行组件重写，不引入新依赖。

## 视觉规则

- 延续现有紫色品牌色，不替换产品主题。
- 内容表面使用白色或浅紫背景；圆角、边框和阴影保持同一层级体系。
- 使用现有 Ant Design 图标，不引入 Emoji 或新的图标体系。
- 交互控件保留可见焦点、禁用态、悬浮态和原有 ARIA 标签。
- 动效仅使用 150–250ms 的颜色、阴影或透明度过渡，并兼容 `prefers-reduced-motion`。
- 桌面端维持当前信息密度；窄屏允许既有横向滚动，不隐藏核心字段或改变字段顺序。

## 数据与兼容性

- 不修改 Store schema、持久化键、Mock 数据结构和项目字段值。
- 不修改字段配置中的排序与显隐含义。
- 已删除的核心展示字段不再渲染，但历史值不清除，避免影响其他业务入口。
- 视觉 class 必须限定在项目列表、项目弹窗和项目空间基础信息作用域，避免影响配置中心、计划编辑表格及联合项目空间。

## 验收标准

1. 技术项目核心板块中`项目年份`后立即显示`前置项目`，且不存在`TDT和子项目名称`卡片。
2. 技术子项目横版计划第一层表头直接显示一级活动名称，不显示`子项目计划`分组。
3. 整机与 tOS 各市场信息中不存在四个计划/实际日期字段，计划页面仍正常显示日期。
4. 卡片、列表、弹窗、基础信息视觉与参考图保持同一紫色、白色卡片、轻边框、紧凑数据密度风格。
5. 项目字段顺序、字段配置、表头拖动、筛选、分页、层级、创建、编辑和权限回归全部通过。
6. `npx tsc --noEmit`、生产构建和真实浏览器验收通过。

## 非范围

- 不重做导航、路标、计划编辑器或联合项目空间。
- 不新增、重命名或重新排序用户未明确要求调整的字段。
- 不修改权限、业务校验、版本规则或日期计算逻辑。
