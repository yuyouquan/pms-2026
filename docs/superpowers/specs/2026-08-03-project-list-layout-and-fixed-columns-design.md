# 项目列表布局与固定列修正设计

## 背景

当前项目列表存在三类体验问题：新增项目与视图切换脱离项目分类筛选区；技术项目列表同时展示 TDT 项目和子项目两张表，且宽表出现表头错位与内容裁切；各项目分类的关键身份列未按业务要求固定。

## 目标与范围

本次仅修正项目列表页面，不改变项目空间、项目创建表单、数据模型、筛选器悬浮框或列设置规则。

## 交互设计

### 顶部操作区

- 将视图切换与“新增项目”按钮放入“项目分类”筛选首行。
- 项目分类选项保持左侧排列，操作按钮组在同一行最右侧对齐。
- 窄屏下允许分类选项换行，但操作按钮作为一个整体保持可见且不被挤散。

### 技术项目类型切换

- 技术项目的“项目类型”快捷筛选仅提供“TDT项目”和“子项目”，移除“全部”。
- 首次进入技术项目时默认选中“TDT项目”。
- 选择“TDT项目”时，仅渲染 TDT 项目表格及其快捷筛选。
- 选择“子项目”时，仅渲染子项目表格及其快捷筛选。
- 两类表格沿用各自独立的列设置与筛选状态，切换项目类型不互相覆盖。
- 列表内容区只保留一个横向滚动容器，避免双表同时出现造成页面纵向冗长、表头宽度失配或右侧裁切。

### 固定列

Ant Design 表格继续使用横向滚动，按项目类型配置左侧固定列：

| 项目列表 | 固定列 |
| --- | --- |
| 整机产品项目 | 产品系列、项目名称 |
| tOS版本项目 | tOS版本 |
| 技术项目 - TDT项目 | TDT项目名称 |
| 技术项目 - 子项目 | 子任务名称 |

固定列具备不透明背景和右侧分隔阴影，保证横向滚动时表头、单元格与后续列不会视觉叠加。上述列仍为默认展示且不可从列设置中删除。

## 状态与数据流

- 项目分类仍由现有项目列表状态驱动。
- 技术项目类型状态收窄为 `tdt | subproject`，由快捷筛选直接控制当前唯一表格。
- 快捷筛选与高级筛选继续使用同一筛选状态；本次不新增过滤字段。
- 非技术项目不读取或展示技术项目类型筛选状态。

## 验收标准

1. 项目分类首行最右侧同时显示视图切换和“新增项目”。
2. 技术项目的项目类型筛选没有“全部”，默认选中“TDT项目”。
3. 任意时刻技术项目页面只显示一张表，切换后表格与筛选内容同步变化。
4. 技术项目宽表表头与数据列对齐，横向滚动可到达最后一个里程碑列，无页面级裁切。
5. 整机、tOS、技术 TDT、技术子项目的指定列在横向滚动时保持固定。
6. 卡片视图、创建项目入口、筛选联动、列设置和进入项目空间功能无回归。

## 验证

- 更新项目列表矩阵与工作台拆分的源代码契约检查，覆盖项目类型选项、默认值、单表条件渲染和固定列。
- 运行项目现有验证脚本、`npx tsc --noEmit` 和 `npm run build`。
- 启动本地页面，在浏览器中分别检查整机、tOS、技术 TDT、技术子项目的横向滚动和固定列，并验证技术项目类型切换。
