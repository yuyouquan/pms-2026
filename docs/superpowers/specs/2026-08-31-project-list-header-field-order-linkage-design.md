# 项目列表表头与字段配置顺序联动设计

## 目标

项目列表的列表视图支持直接按住表头拖动以调整列顺序。表头顺序与“字段配置”中的顺序共用同一份配置，任意一侧调整后，另一侧立即保持一致。

计划相关的阶段和二级里程碑字段在字段配置中统一归为一个名为“里程碑”的原子区块。拖动该区块时，所有阶段表头及其子里程碑列整体移动，内部阶段、里程碑顺序保持模板定义顺序。

## 范围

- 适用于项目列表的列表视图及当前项目类型矩阵。
- 保留现有筛选、分页、分组、层级行、字段显示/隐藏和本地持久化逻辑。
- 项目名称等当前固定列继续锁定，不参与拖动，也不能成为非固定列的插入位置。
- 本次只调整列的展示顺序，不修改计划模板任务顺序、项目数据或字段值。

## 统一顺序模型

### 拖动单元

列配置从“所有叶子列平铺排序”提升为“展示单元排序”：

1. 普通字段：一个字段对应一个展示单元。
2. 里程碑：全部来源为计划模板的字段组成一个 `milestone` 展示单元，对外名称统一为“里程碑”。
3. 固定字段：沿用现有固定列定义，位于列表左侧并锁定顺序。

持久化仍复用项目列表现有的 `storageNamespace + projectType` 范围，不在不同项目类型之间串用。历史存储中的叶子列顺序在读取时归一化：保留普通字段相对顺序，把分散的计划字段收拢到其最早出现位置，形成单一“里程碑”区块。

### 展开规则

渲染表格时，把“里程碑”展示单元展开成模板定义的计划字段序列，再沿用现有阶段分组逻辑生成多级表头。因此移动区块不会改变阶段及子节点的内部顺序，也不会拆散同一阶段。

## 表头拖动交互

- 非固定普通字段表头可按住拖动。
- 计划阶段表头和其任一子里程碑表头都映射到同一个“里程碑”拖动单元；从其中任一位置开始拖动，移动的都是完整里程碑区块。
- 拖动时显示整块的占位和移动反馈，放下后立即更新表格列顺序并持久化。
- 不允许把非固定列拖到固定列区域，也不允许拖动固定列。
- 点击表头原有交互不变；只有达到拖动传感器的移动阈值后才触发排序，避免误操作。
- 键盘排序沿用 dnd-kit 的可访问性能力，并为拖动单元提供明确的中文标签。

## 字段配置交互

- 字段配置列表中，普通字段仍逐项展示。
- 所有计划相关字段只显示一项“里程碑”，不再逐个展示阶段或二级节点。
- 拖动“里程碑”时移动整个计划字段区块；应用后表头立即同步。
- “里程碑”的显示开关控制整个区块：关闭时隐藏全部计划字段，开启时按模板顺序恢复全部计划字段。
- 从表头完成拖动后，再打开字段配置时，其顺序必须与当前表头一致，无需刷新页面。

## 数据流

1. 根据项目类型和模板生成叶子字段定义。
2. 将叶子字段投影为固定字段、普通字段和“里程碑”展示单元。
3. 读取并迁移历史列设置，得到唯一的展示单元顺序和可见状态。
4. 表头拖动或字段配置拖动都调用同一个顺序更新函数。
5. 更新结果写入组件状态和原有本地存储。
6. 表格从展示单元顺序展开叶子列并生成阶段分组表头。

## 异常与兼容

- 模板新增或删除里程碑字段时，不改变“里程碑”区块所在位置；新增字段自动进入区块，删除字段自动消失。
- 没有计划模板字段的列表不显示“里程碑”配置项，也不生成空分组。
- 损坏、重复或旧格式的本地列配置通过统一归一化函数恢复，不阻塞项目列表渲染。
- 项目类型切换后使用各自独立的列配置和里程碑模板。

## 验收标准

1. 在表头拖动任一普通非固定字段后，表格立即按新顺序显示，字段配置打开后顺序一致。
2. 在字段配置拖动普通字段后，应用即更新表头顺序。
3. 字段配置只出现一个“里程碑”项，不出现单独的计划阶段或二级节点项。
4. 从任一计划表头开始拖动时，所有计划阶段及子里程碑列作为整块移动，内部顺序不变。
5. 在字段配置拖动“里程碑”时，表格中的全部计划列作为整块移动。
6. 隐藏“里程碑”会隐藏全部计划列；重新显示后按模板顺序恢复。
7. 固定列不可拖动，其他列不能进入固定列区域。
8. 刷新页面后保留最近一次顺序和可见状态。
9. 整机产品、tOS 版本和技术项目列表现有筛选、分页、层级/分组展示不回归。

## 验证方案

- 顺序模型单元验证：历史叶子顺序迁移、里程碑收拢、展开、显示/隐藏、模板字段增删。
- 静态契约验证：表头和字段配置使用同一更新入口，计划字段不再作为独立配置项。
- 浏览器验证：分别从表头和字段配置拖动普通字段与“里程碑”，核对双向同步、整块移动、刷新持久化和固定列约束。
- 项目级验证：`npx tsc --noEmit`、`npm run build`，以及项目列表现有验证脚本。
