# 项目管理系统 UI 规范

版本：0.1 · 提取日期：2026-09-20 · 用途：本地项目 UI 改造

## 1. 范围与使用方式

本规范来自 Figma「B端」文件中的「项目管理系统」页面，以「最新」表格界面、创建项目表单和状态标签组件为样本。它是一份**有来源的改造基线**，尚不代表已审计该文件中其他七个系统，也不代表本地项目已经完成改造。

[Figma 原始入口](https://www.figma.com/design/iUADTdAAn6AEAUW0LAxfLn/B%25E7%25AB%25AF?node-id=245-3473) · [主界面样本](https://www.figma.com/design/iUADTdAAn6AEAUW0LAxfLn/B%25E7%25AB%25AF?node-id=2214-72451) · [新增项目样本](https://www.figma.com/design/iUADTdAAn6AEAUW0LAxfLn/B%25E7%25AB%25AF?node-id=2214-78700)

来源分为三类：

- **实测**：从当前 Figma 浏览器 Properties 面板读取，或从画布直接观察到的结构。
- **标注**：设计师在该页面的评论要求。涉及特定区域时，只适用于对应区域。
- **建议**：为了形成可实现的规范而补全的工程规则，不宣称是 Figma 原始值。

本次 Figma 连接器因文件编辑权限不足无法返回完整图层数据，已改用浏览器只读检查。没有改动原稿。悬浮、按下、禁用等未检查到的状态不得标为已实测。

配套文件：`design-tokens.json` 保存数值、来源与待确认项；`theme.css` 提供隔离作用域的 CSS 变量；`本地UI改造指令.md` 可交给开发者或编码助手执行。

## 2. 视觉方向

界面以高信息密度的桌面业务操作为主：浅色页面背景、白色内容容器、靛紫色主操作、紧凑表格和分组表单。主界面采用顶部导航；项目空间截图中另有左侧业务导航，因此导航形式要跟随原有业务层级。

改造时保留现有中文名称、字段顺序、枚举、权限和业务交互。Figma 中的项目名、人员、日期和占位字段不能替换真实业务定义。

## 4. 字体与排版

| 场景 | 实测 | 实现规则 |
|---|---|---|
| 表格版本名称 | PingFang SC，14px，500，字距 0，文字框高 20px；面板行高显示 100% | 表格中具有相同层级的标识文字采用此规格 |
| 创建按钮 | PingFang SC，14px，400，白色，文字框高 20px；面板行高显示 100% | 普通操作文字保持 14px，避免所有按钮加粗 |
| 状态标签 | PingFang SC，12px，500，行高 16px，字距 0，居中 | 标签采用 12/16，不等比例缩小整个组件 |

**建议补全**：页面标题 20/28、分区标题及弹窗标题 16/24、普通正文 14/20、辅助信息 12/16；标题使用 600，正文使用 400，需要强调的标识使用 500。这些标题规格尚未逐项读取原稿。

Web 字体建议：`"PingFang SC", "Microsoft YaHei", -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif`。只有 PingFang SC 来自实测，其余为跨平台回退。Figma 的行高 100% 与文字框高度不能直接等同；正文/按钮在 Web 端先用 20px 行高，按实际基线验收。

## 5. 布局、间距、圆角、阴影

| 对象 | 实测规格 | 落地说明 |
|---|---|---|
| 桌面画板 | 1440×900 | 是对照尺寸，不要将应用固定成 900px 高 |
| 顶部 Header | 高 50px；左右 32px；子项 Gap 20px | 使用 Flex；保持顶部导航层级 |
| 主内容外层 | 宽度 Fill 1440px；左右 32px；Gap 8px | 页面内容随视口伸缩 |
| 主表格容器 | 宽 Fill 1376px；圆角 16px；Padding 12px；Gap 12px | 1440−32×2=1376；不要硬编码固定宽 |
| 表格内部内容组 | Gap 8px | 紧密关联的摘要、表格之间使用 8px |
| 主容器阴影 | X0 / Y0 / Blur20 / Spread0，`#D3D0FF` 50% | `0 0 20px 0 rgba(211,208,255,.5)` |
| 主容器顶部强调 | Inner shadow：X0 / Y2 / Blur0 / Spread0，`#4D41FF` | `inset 0 2px 0 #4D41FF`；只用于对应容器 |
| 按钮 | 圆角 6px | 不扩大为卡片的 16px |
| 表单分组 | 圆角 6px；边框 1px；Gap 8px | 分组层级与主内容卡片分开 |
| 弹窗操作区 | 高 64px；左右 24px；Gap 16px；底部两角 12px | 操作按钮靠右 |

间距可归入 `4 / 6 / 8 / 10 / 12 / 16 / 20 / 24 / 32`，按组件角色使用，不能全部替换为同一档。例：标签上下 4px；按钮左右 16px；表格左右 12px；弹窗左右 24px；页面左右 32px。

标签圆角在 Figma 中绑定 `Radius/XXS`，本次没有读到解析后的数值。CSS 将建议回退值 4px 单列为 proposal，不能记为已核实。

## 6. 组件规范

### 6.1 按钮

实测主按钮高 32px、圆角 6px、左右内边距 16px、内容 Gap 6px，背景为主色，文字 14px/400/白色。两字「创建」宽 60px；其他文案按内容增长，不能统一写死 60px。

次按钮同样高 32px、圆角 6px、左右内边距 16px，背景 `#F0EFFF`，样本 Gap 8px。建议次按钮文字使用主色，但该文字色未直接读取。

建议：同一操作区域只保留一个最主要的实心操作；加载时保留宽度并阻止重复提交；图标按钮具备可读名称和提示。悬浮、按下、禁用的颜色优先复用项目已有主题状态，待原稿补查后替换，不从主色随意推导并冒充设计值。

### 6.2 输入与表单

画布可见：标签在控件上方；必填星号在标签前；内容按「项目分类与识别」「产品与版本」「时间与备注」分组。示例中的首个分组是一行六个字段，而不是所有表单都固定四列或八列。

实测分组边框为黑色 12%、1px，圆角 6px，组内 Gap 8px，分组外围容器左右 Padding 24px。

建议输入框高 32px、圆角 6px，与按钮对齐；标签与输入间距 4px，字段横向间距 16px、纵向间距 12px；这些输入规格尚未逐项实测。错误提示放在相关字段下方；必填、只读、禁用保持不同语义；不要靠颜色单独区分。

保留业务中的字段依赖、可选值、日期校验、人员选择和提交行为。日期旁的「预估」在样本中是独立勾选项，不能在 UI 改造中合并掉。

### 6.3 表格

实测数据单元格高 40px，左右 Padding 12px、上下 10px、内部 Gap 8px，底边 1px / 黑色 3%。该样本的版本列宽 124px，只是一个列的宽度，不作为全部列的标准。

实现时以 **40px 最终行高** 为准，结合正文 20px 行高校正边框与 Padding 的 CSS 盒模型，避免 1px 边框把行高撑成 41px。不要简单同时叠加固定高度、全部 Padding 和不受控的最小高度。

画布可见浅紫色表头、表头排序标记、右侧操作列、底部分页、异常行浅红背景及图标提示。表头背景精确值与表头高度尚未读取；建议背景先映射 `brand.subtle`，作为待核对项。

建议：长文字省略并允许查看全文；链接/附件支持多项；数值和人月保留原有单位与格式；操作列在横向滚动时仍可访问；固定列与排序行为复用既有实现。不要为了对齐设计截图裁掉字段。

### 6.4 标签

实测高 24px、三字标签宽 52px、两字标签宽 40px；Padding 上下 4px/左右 8px；边框 1px；文字 12px/500、行高 16px。边框在 Figma 中向内绘制。

Web 建议使用内描边实现边框，避免「16px 行高 + 上下 8px Padding + 2px 实体边框」把高度变为 26px。标签宽度自适应，不设置固定字符数。

业务状态由原有枚举映射到表现类型，不把 Figma 的 `Variant2/Variant3` 或占位属性直接保存为业务状态。检查时发现多个变体的属性面板「标签」仍写着「进行中」，而画布实际分别为未开始、已完成、删除；业务标签以业务定义为准。

### 6.5 导航、切换与筛选

主界面有顶部应用导航、内容区视图切换、tOS 版本选择、品牌/产品类型切换，以及右侧筛选与字段配置工具。保持这四种层级的差别：应用入口、业务视图、条件选择、辅助操作。

建议将筛选条件放在左侧，显示/字段工具放在右侧；窄屏换行时仍保持分组，不能把筛选条件藏成不可发现的图标。切换表格、卡片、日历或路标视图时，筛选条件和业务选中项按现有产品规则保留。

品牌与产品类型的尺寸有设计师更新要求，具体选项宽高仍需补查。顶栏强紫色渐变是画布观察结果，端点、角度未实测，不能直接把页面浅色渐变用于顶栏。

### 6.6 弹窗与抽屉

新增项目样本的面板宽 1199px、高 688px，是复杂六列表单的大弹窗。它不能成为删除确认或简单编辑弹窗的统一宽度。

实测操作区高 64px、左右留白 24px、按钮间距 16px、底部圆角 12px。建议大型表单在 Web 中采用 `width: min(1199px, calc(100vw - 48px))`，内容超高时内部滚动并保持操作区可用；48px 视口预留属于工程建议。

建议普通确认弹窗与大型表单分别定义尺寸角色；所有弹窗有明确标题、关闭入口、取消与确认操作。焦点进入弹窗、关闭后返回触发位置，保留 Escape/键盘行为及未保存修改的原有处理逻辑。

### 6.7 卡片、路标、日历及详情

这些视图已经在图层列表中确认存在，本次没有完整测量全部内部组件。可先共享字体、按钮、标签和间距 Token；业务卡片颜色、里程碑、时间轴比例、计划单元格宽度应单独映射。

不要把主表格容器顶部的靛紫色强调线应用到每张业务卡片，也不要把所有日历/路标内容强制为普通 40px 行。

## 7. 设计师标注的适用边界

以下为当前页面评论的整理，后续改造要定位评论对应的具体容器：

| 评论 | 内容 | 执行边界 |
|---|---|---|
| #43、#45 | 容器上下左右/左右间距调整为 12dp；品牌、产品类型切换栏有调整 | 页面外侧 32px 与容器内侧 12px 不是冲突；分别核对 |
| #42 | 间距改为 8dp | 局部关联元素；不要替换全部 12px 间距 |
| #41 | 整体缩小，与列表视图一致 | 采用一致密度，不能直接 CSS transform 缩放整页 |
| #50、#56 | 指定表格单元格宽度 40 | 是特定计划表格的宽度要求，不是所有列宽；也不同于实测数据行高 40 |
| #52 | 一行八个，字段按业务排序，设计稿仅占位 | 适用于对应信息区，不能推广到所有弹窗表单 |
| #53 | 一行四个，最多显示三个人，超出省略 | 对应人员信息区；建议提供完整内容的查看入口 |
| #57 | 上市/维护阶段 MR 较多，超出右滑；增加生命周期天数 | 横向滚动与字段要求跟随对应业务表格 |
| #61、#64 | 存在多个链接/Jira 链接 | 不强制一条链接或用省略号丢掉其他项 |
| #63 | 甘特图参考原型 | Figma 不能独自决定时间轴交互 |
| #67 | 字段需要自查，设计稿仅占位 | 字段、枚举、排序回到已确认业务合同 |

评论中的 dp 在本 Web 规范中按相同数值的 CSS px 对照实现；这属于实现约定，不涉及设备物理像素换算。

## 8. 交互状态补全与响应式建议

本节全部为工程建议，需要与本地组件和产品行为对齐。

| 状态 | 规则 |
|---|---|
| Hover / Pressed | 使用项目主题内已有状态；待 Figma 状态值核验后统一替换 |
| Focus | 必须可见；输入、按钮、菜单和弹窗均能用键盘操作 |
| Disabled / Readonly | 保留原因或可理解的上下文；只读仍可复制有用信息 |
| Loading | 保持布局稳定；按钮防重复提交，表格保留表头和筛选上下文 |
| Empty | 区分首次无数据与筛选无结果，给出对应下一步 |
| Error | 给出错误对象和恢复入口；字段错误贴近字段 |
| Overflow | 文本可展开/提示完整值，宽表在内容区域横向滚动 |

1440×900 为主要对照视口。建议补测 1280×800、1920×1080；若项目现有 PAD/移动支持，再验证对应视口。小屏优先让筛选/表单重排，复杂表格允许横向滚动，不缩放文字。没有设计证据支持固定的全局断点，优先沿用本地项目约定。

## 9. 本地项目接入顺序

1. 读取仓库说明、现有 UI 规范、主题、公共组件、路由和未提交改动；确认真正的目标项目。
2. 创建“旧 Token → 本规范 Token”的映射，先接入颜色、字号、尺寸与间距变量。保留原有样式体系和组件库。
3. 首先改公共基础组件：Button、Input/Select、Tag、Table、Modal/Drawer；不要逐页复制一套近似样式。
4. 再改页面结构：外侧 32px、内容容器 12px/16px、筛选栏、分组和操作区。
5. 选“列表页 + 新增/编辑弹窗 + 项目详情”作为第一批对照样本，再覆盖卡片、路标、日历及配置页面。
6. 专项处理溢出、多链接、多人、MR 横向滚动、生命周期等原有业务展示要求。
7. 对照 1440×900 的真实页面验证，并运行项目要求的类型检查、构建和相关交互检查。

若项目使用 Ant Design，将 Token 接到既有 ConfigProvider/theme 与组件级 token；若使用 Tailwind/shadcn，接到现有 CSS 变量和组件 variants。框架与版本必须从目标仓库读取，不能仅凭 Figma 名称判断。

`theme.css` 默认使用 `[data-ui="figma-pms"]` 作用域。弹窗若通过 portal 挂载到作用域外，需将作用域放在应用根元素（例如 `<html>`），或让 portal 容器继承相同 Token；不要只给某个页面卡片加属性。

## 10. 验收清单

- [ ] 颜色、字号、间距由主题变量管理，相同组件没有多套随意数值。
- [ ] 1440px 下顶栏 50px、页面左右 32px；主卡片 16px 圆角、12px 内间距。
- [ ] 数据行最终高度 40px；按钮 32px；标签 24px，文字不截断。
- [ ] 表单、列表和弹窗字段、中文名称、枚举、权限及业务行为与改造前一致。
- [ ] 筛选、分页、排序、切换视图、展开收起、多链接和长内容可用。
- [ ] Hover、Focus、Loading、Empty、Error、Disabled/Readonly 有明确表现。
- [ ] 宽表不会把全页面撑出视口；弹窗内容与操作区在低高度窗口可访问。
- [ ] 浏览器无新增运行时错误，已完成目标仓库要求的质量检查。
- [ ] 逐项记录建议值的采用情况与尚未核实的 Figma 差异。

## 11. 待核实项

目前仍需补查：顶栏渐变参数；正文次级/占位/链接色；标题字号；输入框实测尺寸；表头高度与背景色；各按钮交互态；`Radius/XXS` 数值；图标库及原始资源；抽屉尺寸；卡片、日历、路标、甘特图内部规格；其他业务系统的差异。

这些项目不妨碍先进行已实测的公共样式改造，但不能宣称规范已覆盖全部画板或已达到逐像素还原。本地项目目录和现有技术栈尚未提供，本次没有修改项目源码。
