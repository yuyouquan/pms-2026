本轮检查项目配置、项目视图、路标项目、四类资源空间、共享人力投入、责任人权限、Mock 场景及统一 UI。发现的问题均已修复，相关回归、类型检查、生产构建和浏览器交互通过。独立代码复审未发现遗留 P1/P2。

## 修复结果

| 问题 | 修复后的行为 |
| --- | --- |
| 统一创建的整机责任人写入旧别名，基础信息编辑不能完整回显 | 新记录使用 canonical `machineSpm`；旧 `spm`、团队角色和根字段兼容读取，明确清空的人员不被旧值恢复 |
| 技术负责人在独立表单和保存链路中仍按单人处理 | 技术负责人支持多人，编辑、补充资料、保存及重载保留人员数组；根字段仅保留显示文本，角色同步使用实际人员 |
| 技术一级计划及子计划确认路径可能只识别第一名负责人 | 主容器及确认回调共享负责人解析；canonical 字段优先，缺失时回退全部角色成员，明确空数组不回退 |
| 非正式技术项目的分类显示为空且不可编辑 | 预算项目使用已知项目类型；正式项目继续显示来源分类 |
| 旧年度预算无法匹配、来源重复或绑定被占用时缺少诊断 | 精确旧导入 ID 补充待核对提示；不猜测绑定，不重写版本、月度投入或原始快照；已确认的绑定、解绑及源删除不会反复提示 |
| 已取消资源项目仍有可点击的新增版本入口 | 四类新增按钮与现有状态规则一致；已取消项目显示“已取消 · 不可新增版本”，历史仍可查看 |
| 新版本创建人和操作历史写入“当前用户”或固定姓名 | 四类新版本以及已有复制、编辑、部门投入日志记录实际登录人；原创建人、旧日志和未知历史迁移占位值不变 |
| Ant Design 6 弹窗容器叠加边距，整机详情漏统一样式 | 共享 `.pms-modal` 主体承担 24px 内边距，容器不再额外叠加；整机版本详情使用同一规范 |

## Mock 场景

保留原功能样例，本轮补充技术预算双责任人、tOS 最新年度预算部分里程碑待填写、整机已取消预算及其历史版本。

| 场景 | 数据与验证重点 |
| --- | --- |
| 四类正式项目、绑定年度预算、未绑定跨年预算 | 三种预算类型边界、来源只读、跨项目汇总去重、历史与最新版本差异 |
| 整机来源资料缺失且已绑定 | 品牌、产品线、市场名显示来源空值，只读；不阻塞年度预算创建 |
| 整机未绑定且资料为空 | 无版本空状态；新增时三项资料必填 |
| 技术预算两名负责人 | 表单多选回显、普通资料保存、人员替换、清空、角色与计划权限、重载 |
| tOS 最新版本维护结束待填写 | V0.2 缺少维护结束；V0.1 保留完整日期；新增版本可补充且不改写历史 |
| 整机已取消预算 | 保留 V0.1 年度预算及模型明细，禁止新增版本 |
| 路标项目日期未齐 | 保留项目记录和路标投影，资源空状态，无新增版本入口 |
| 旧数据异常 | 未知正式编码、重复来源、绑定占用、年度/非年度拆分、手工月度值、来源删除和重载 |

新样例只用于全新本地数据，不提高数据集版本，不向已有 registry 强行补样例或恢复已删除项目。真实浏览器分别使用保留旧数据的 3042 和本轮新数据的 3043；浏览器中的测试操作不写入源码 Mock。
