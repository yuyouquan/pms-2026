# 资源费用单位、布局和月度单向联动验收

## 本轮行为

- 资源投入区移除费用总额提示条；投入时间范围位于部门人力 / 非人力 tab 行右端，随当前版本里程碑范围更新。
- 非人力投入以元展示、编辑、导入和导出，保留两位小数；列名为「预估投入合计」。原始存储即为元，无需迁移金额。
- 整机基础信息六个控件和两个排布日期控件统一为 154px；分隔线与标题至输入框底部同高。
- 部门合计、阶段投入或百分比改变后，重算该部门的月度人力，替换该部门过时的手工月度分配；其他部门、其他版本保留原分配。
- 月度手工编辑不反写部门投入或比例。日期、批次和非人力修改不清除手工月度分配。
- 能力建设项目按照项目周期百分比计算月度分配，未满 100% 时仍保留部门目标值和正式版本校验。
- 旧持久化行建立上游投入基线；锁定旧行仅补基线元数据，保持金额快照，解锁后的首次投入修改也会重算。兼容旧部门序号 ID 和项目前缀迁移。

## 自动验证

首轮通过非人力单位、行内编辑、资源合计、正式版本校验、版本生命周期及跨标签同步回归；`npx tsc --noEmit --pretty false` 和 `npm run build` 通过。

专项脚本 `npm run verify:resource-monthly-reallocation` 先复现原始手工分配阻止重算的问题，修复后覆盖四类项目上游合计/比例变化、微小比例变化、下游不反写、部门隔离、刷新、复制、锁定和旧数据解锁。独立审查发现旧锁定行漏建基线，补修复及三种旧 ID 回归后通过复审。最终再次通过专项回归和生产构建。

## 浏览器验收

- 本地生产构建，示例整机-独立跨年预算的独立复制版本：非人力标签为元、输入和汇总均两位小数、无费用合计提示条；修改概念启动后投入范围从 2026年11月更新到 2026年10月。八个输入控件均 154×32px，分隔线与整体填写区均高 53px；正常窄视口与 1740px 宽视口均检查。
- 示例tOS-独立跨年预算，独立复制版本「V单向联动验收0920」：先手动修改产品部 2026-11 为 50，部门目标仍为 30.3、规划比例仍为 10.89%。再把部门目标改为 60，11 月自动改为 6.3，全周期分配为 60.0/60.0。
- 把规划比例改为 20%，11 月自动更新为 11.6，分配显示 65.5/60.0（+5.5）；软件部手工填写的 40 未变。费用视图相应显示 58.00（费率 5），且只读。
- 比例合计 109.11% 时设置正式版本被阻止。回填比例、通过上游合计触发重新平衡后，产品部为 60.0/60.0，软件部为 45.0/45.0。浏览器错误日志为空。

原始正式版本保持不变，验收在新建副本中进行。生产发布的分支、部署和在线读回证据记录在任务交付文件中。
