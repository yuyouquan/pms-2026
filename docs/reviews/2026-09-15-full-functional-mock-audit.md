# 功能与 Mock 联动审计

范围：当前已实现的项目管理、工作台、项目空间、计划、资源、配置中心、tOS 路标、项目组合、权限与转维。以当前需求为准；非人力投入单位为元，整机采用七个里程碑区间。

## 已定位的问题

1. **人力模型配置包含非数据成员。** `hrConfig.data` 误包含 `refreshMachineModelFixtures` 函数，导致 `structuredClone` 失败，并使内存快照与 JSON 持久化结果不一致。移除该成员，增加配置序列化回归。
2. **项目数据与历史分批通知。** 创建、修改、删除项目时，订阅者先得到项目变化，随后才得到历史；创建成员表也单独更新。改为在一次项目 store 更新中提交项目、当前选中对象、创建成员表和登记历史，避免同一个 store 内出现不一致快照。权限及路标 store 仍按原有流程同步，不宣称跨 store 事务。
3. **甘特视图未完整采用列表字段。** 浏览器确认整机一级计划列表为九列，甘特仍显示旧的五列；技术项目也使用旧常量。按列表字段、顺序、显示值统一，并验证空日期、工期、序号和实际时间。具体最终验收记录见下方。
4. **计划分享仍使用旧版交互表格。** 只读分享显示“点击填写”等旧编辑提示和旧列，空工期也显示多余单位。分享页改为基于已发布快照展示当前列表字段，所有单元格只读，草稿不进入分享；保留普通类型的现有列名和序号/名称必显规则。

## 旧校验与实际缺陷分开处理

首轮运行 104 项既有非浏览器脚本（含主题验证器自测）：81 项通过，23 项失败。失败逐项核对当前源码和已确认需求，包括：

- 七区间已取代旧六阶段；正式整机结束节点为 STR5+6个月，旧字段不能继续用于测试金额守恒。
- 新增 tOS 规划阶段后模板为六阶段；技术子项目采用当前单级里程碑和统一计划列。
- 项目配置已取代旧创建入口，正式项目必须使用有效 IPM 来源及创建人/责任人字段。
- 顶部配置导航、独立标题、项目空间锚点已移除；全屏动画和组件拆分后的源码定位同步更新。
- 项目视图支持全部/当前导出，只展示正式项目；不再使用旧的禁止导出断言。
- 独立路标 Mock 使用 DEMOR001；删除后保存的空项目集不应在重载时恢复种子。保留显式构造冲突的正向测试。
- 持久化测试使用带当前数据集标识的 `window.localStorage`，避免只声明全局 localStorage 却未执行实际持久化。

调整断言保留了金额守恒、历史不变、跨页联动、权限拒绝和输入非法时不写入等约束。
